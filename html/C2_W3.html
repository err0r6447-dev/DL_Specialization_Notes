1. Why This Week Matters

Weeks 1 and 2 gave you the tools to make a model generalize and to make it train fast. This week gives you the tools to make it actually work in practice:

  • How to tune hyperparameters efficiently — so you don't waste weeks searching blindly.
  • Batch Normalization — a technique that stabilizes training and speeds up learning dramatically.
  • Softmax regression — how to extend neural networks from binary classification to multi-class classification.
  • Deep learning frameworks — the software tools that make all of this practical.
💡 Insight Deep learning is fundamentally empirical. There is rarely a single "correct" hyperparameter. What matters is having a systematic process for finding good hyperparameters efficiently, and having techniques like batch norm and softmax in your toolkit that work reliably across many problems.

2. Which Hyperparameters Matter Most

Not all hyperparameters are equally important. Andrew Ng's guidance ranks them roughly by how much impact they typically have on final performance.

🟡 Important — practical priorities
  1. Learning rate \(\alpha\) — tune this first, and most carefully. Small changes can mean the difference between a model that trains and one that diverges.
  2. Momentum \(\beta\) (typically 0.9), # hidden units, mini-batch size — tune next.
  3. # layers, learning rate decay — tune if you have time.
  4. Adam \(\beta_1, \beta_2, \varepsilon\) — leave at defaults (0.9, 0.999, \(10^{-8}\)) unless you have a specific reason.
  5. Regularization \(\lambda\) — tune as needed.

3. Random Search vs Grid Search

3.1 The problem with grid search

An intuitive approach is grid search: define a grid of values for each hyperparameter and try every combination. But in deep learning this is wasteful.

🟢 Intuition — why random beats grid Suppose you have two hyperparameters, and only one of them actually matters for the problem. Grid search with a 5×5 grid tries only 5 distinct values of the important hyperparameter. Random search with 25 samples tries (on average) 25 distinct values — five times as many. When you don't know which hyperparameters are the important ones, random search is simply a more efficient use of your time.
🟡 Important — practical recommendation Use random search, not grid search. Sample hyperparameters randomly from ranges you choose. If you later identify a promising region, narrow your search (see Coarse to Fine below).

4. Coarse to Fine

After a first round of random search, you may notice that certain regions of the hyperparameter space do better than others. Instead of continuing to sample uniformly over the whole space, zoom in on the promising region and sample more densely there.

⚙️ Implementation — the coarse-to-fine process
  1. Define a broad range for each hyperparameter.
  2. Sample randomly (e.g. 20–50 configurations) and evaluate each on the dev set.
  3. Look at which region performed best. Shrink the ranges accordingly.
  4. Sample again more densely within the narrower range.
  5. Repeat until you're satisfied with the dev performance or your compute budget is exhausted.
💡 Insight — one experiment at a time You don't need to grid the space. Even one random configuration at a time, adjusted based on the previous results, works well. This is called "babysitting a model" and is appropriate when compute is limited.

5. Using the Right Scale

Not all hyperparameters should be sampled uniformly on a linear scale. Some — like the learning rate — are best sampled on a logarithmic scale.

5.1 The problem with linear sampling for the learning rate

Suppose the reasonable range for \(\alpha\) is \(0.0001\) to \(1\). If you sample uniformly on a linear scale, 90% of your samples fall between \(0.1\) and \(1\), and only 10% fall between \(0.0001\) and \(0.1\) — even though the range that matters most for fine tuning is the lower end.

5.2 Sampling on a log scale

Instead of sampling \(\alpha\) directly, sample its exponent \(r\) uniformly and then compute \(\alpha = 10^r\).

\[ r \sim \text{Uniform}(a, b), \qquad \alpha = 10^{r} \]

For example, to search \(\alpha\) in the range \([10^{-4}, 10^{0}]\):

r = -4 * np.random.rand()   # r is uniform in [-4, 0]
alpha = 10 ** r             # alpha is log-uniform in [10^-4, 1]
🟣 Example — sampling α for a neural network

Suppose you believe the reasonable range for \(\alpha\) is \(10^{-4}\) to \(10^{-1}\). You set \(a = -4\) and \(b = -1\). Then:

  • Sample \(r_1 = -3.2\) → \(\alpha_1 = 10^{-3.2} \approx 6.3 \times 10^{-4}\)
  • Sample \(r_2 = -1.4\) → \(\alpha_2 = 10^{-1.4} \approx 0.04\)
  • Sample \(r_3 = -2.7\) → \(\alpha_3 = 10^{-2.7} \approx 0.002\)

Each decade \(10^{-4}\) to \(10^{-3}\), \(10^{-3}\) to \(10^{-2}\), and \(10^{-2}\) to \(10^{-1}\) is equally likely. This gives fine-grained exploration at the lower end where small differences matter.

🟡 Important — which hyperparameters to sample on a log scale?
  • Learning rate \(\alpha\) — definitely log scale.
  • Regularization \(\lambda\) — log scale.
  • \(\beta\) for exponentially weighted averages (including momentum and Adam's \(\beta_1, \beta_2\)\) — special treatment, see the next section.
  • # hidden units — linear scale (or small steps).
  • # layers — integer linear scale.
  • Mini-batch size — powers of 2, so sample from that discrete set.

6. Scale for β in Exponentially Weighted Averages

6.1 The problem with uniform sampling for β

Suppose you want to tune \(\beta\) for momentum or for the exponential weighted average. The typical range is \(0.9\) to \(0.999\). If you sample uniformly, the range \(0.9\) to \(0.99\) gets \(90\%\) of the samples, while the range \(0.99\) to \(0.999\) gets only \(10\%\).

But look at the effective window \(\frac{1}{1-\beta}\):

\(\beta\)Effective window \(1/(1-\beta)\)
0.910
0.99100
0.9991000

The values \(0.9\), \(0.99\), and \(0.999\) are equally spaced in terms of their effect on the averaging window, but linearly uniform sampling treats \(0.9\) to \(0.99\) as a much larger region than \(0.99\) to \(0.999\).

6.2 The fix — sample \(1-\beta\) on a log scale

\[ 1 - \beta \sim 10^{r}, \qquad r \sim \text{Uniform}(a, b) \]

For example, to search \(1-\beta\) in the range \([10^{-3}, 10^{-1}]\) (so \(\beta \in [0.9, 0.999]\)):

r = -3 * np.random.rand() - 1     # r is uniform in [-4, -1]
one_minus_beta = 10 ** r
beta = 1 - one_minus_beta
🟣 Example
  • \(r = -3\) → \(1-\beta = 10^{-3}\) → \(\beta = 0.999\) → window ≈ 1000
  • \(r = -2\) → \(1-\beta = 10^{-2}\) → \(\beta = 0.99\) → window ≈ 100
  • \(r = -1\) → \(1-\beta = 10^{-1}\) → \(\beta = 0.9\) → window ≈ 10

Each decade of the window size gets equal sampling probability.

Depending on your computational resources, there are two main strategies for tuning hyperparameters.

🟡 Important — re-evaluate your intuitions periodically Andrew Ng's advice: hyperparameters that were best a few years ago may not be best now. 8. Batch Normalization — The Idea

8.1 The motivation

In Week 1, you saw that normalizing the input features to have zero mean and unit variance speeds up gradient descent dramatically. But in a deep network, the inputs to intermediate layers are the activations of previous layers — and those change as training progresses. Can we apply the same normalization trick to intermediate layers too?

🔵 Definition — Batch Normalization (Batch Norm) Batch Normalization is a technique that normalizes the pre-activations (or activations) of each layer to have approximately zero mean and unit variance, computed over each mini-batch. It stabilizes training, allows larger learning rates, and speeds up convergence.

9. Implementing Batch Norm

9.1 The core algorithm

Given intermediate values \(z^{(1)}, z^{(2)}, \dots, z^{(m)}\) for a mini-batch of size \(m\) (typically the pre-activations of some layer):

  1. Compute the mean: \[ \mu = \frac{1}{m} \sum_{i=1}^{m} z^{(i)} \]
  2. Compute the variance: \[ \sigma^2 = \frac{1}{m} \sum_{i=1}^{m} (z^{(i)} - \mu)^2 \]
  3. Normalize: \[ z_{\text{norm}}^{(i)} = \frac{z^{(i)} - \mu}{\sqrt{\sigma^2 + \varepsilon}} \] Here \(\varepsilon\) is a tiny number (e.g. \(10^{-8}\)) that prevents division by zero.
  4. Scale and shift with learnable parameters: \[ \tilde{z}^{(i)} = \gamma \, z_{\text{norm}}^{(i)} + \beta \] Here \(\gamma\) and \(\beta\) are learnable parameters of the layer, not fixed constants.
  5. Use \(\tilde{z}^{(i)}\) in place of \(z^{(i)}\) in the rest of the network (e.g. pass \(\tilde{z}^{(i)}\) through the activation function).
🟡 Important — \(\beta\) is a learnable parameter, not the momentum β In Batch Norm, \(\beta\) is a learnable shift parameter (like a bias). This is completely different from the momentum hyperparameter \(\beta\) you saw earlier. The course uses the same Greek letter for both; keep track of context.
🟢 Intuition — why γ and β? If we always forced activations to have exactly zero mean and unit variance, we would restrict the network's representational power. By allowing a learnable scale \(\gamma\) and shift \(\beta\), the network can recover any mean and variance it wants. The normalization simply gives it a well-conditioned starting point before it adjusts.
🟣 Example — a simple numerical case

Suppose a mini-batch has three pre-activations: \(z = (1, 3, 5)\). Then:

  • \(\mu = (1+3+5)/3 = 3\)
  • \(\sigma^2 = ((1-3)^2 + (3-3)^2 + (5-3)^2)/3 = (4 + 0 + 4)/3 \approx 2.67\)
  • \(z_{\text{norm}} = ((1-3)/\sqrt{2.67}, (3-3)/\sqrt{2.67}, (5-3)/\sqrt{2.67}) \approx (-1.22, 0, 1.22)\)

Now the batch has zero mean and unit variance. If \(\gamma = 2\) and \(\beta = 1\), then \(\tilde{z} \approx (-1.44, 1, 3.44)\). The network learns \(\gamma\) and \(\beta\) during backpropagation.

10. Fitting Batch Norm into a Neural Network

10.1 Where does it go?

In a standard deep network, each layer computes:

\[ z^{[l]} = W^{[l]} a^{[l-1]} + b^{[l]}, \quad a^{[l]} = g^{[l]}(z^{[l]}) \]

With Batch Norm, we insert a normalization step between \(z^{[l]}\) and \(g^{[l]}\):

\[ z^{[l]} = W^{[l]} a^{[l-1]} + b^{[l]} \] \[ \tilde{z}^{[l]} = \text{BN}_{\gamma^{[l]}, \beta^{[l]}}(z^{[l]}) \] \[ a^{[l]} = g^{[l]}(\tilde{z}^{[l]}) \]
🔴 Warning — the bias \(b^{[l]}\) becomes redundant Because Batch Norm subtracts the mini-batch mean \(\mu\) from \(z^{[l]}\), any constant offset added via \(b^{[l]}\) is immediately removed. So \(b^{[l]}\) has no effect on the output. Common practice is to drop \(b^{[l]}\) entirely when using Batch Norm, or set it to zero. The learnable \(\beta^{[l]}\) of Batch Norm takes over the role of the bias.

10.2 The full forward pass with Batch Norm

# For layer l:
Z = W @ A_prev + b        # (b is usually omitted when using BN)
Z_tilde = BatchNorm(Z, gamma, beta)
A = g(Z_tilde)

10.3 Parameters of the layer

Each layer now has four sets of parameters:

  • \(W^{[l]}\) — weights (learned via backprop)
  • \(b^{[l]}\) — bias (usually dropped when using BN)
  • \(\gamma^{[l]}\) — learnable scale for Batch Norm
  • \(\beta^{[l]}\) — learnable shift for Batch Norm

The update rules (using gradient descent) become:

\[ W^{[l]} := W^{[l]} - \alpha \, dW^{[l]}, \quad \gamma^{[l]} := \gamma^{[l]} - \alpha \, d\gamma^{[l]}, \quad \beta^{[l]} := \beta^{[l]} - \alpha \, d\beta^{[l]} \]

11. Working with Mini-batches

Batch Norm's statistics are computed per mini-batch. This is what gives the technique its name — it normalizes over a "batch" of examples at a time.

🟡 Important — test-time behavior At test time, we don't have a mini-batch to compute statistics from — we process one example at a time. Instead, we use exponentially weighted running averages of \(\mu\) and \(\sigma^2\) that were accumulated during training. This is why Batch Norm is said to have a training mode and a test mode.

12. Why Does Batch Norm Work?

12.1 The "changing inputs" problem

Consider a deep network. Layer 3 receives the activations from Layer 2 as input. As training progresses, the weights of Layer 2 change, so the distribution of inputs to Layer 3 shifts. Layer 3 constantly has to re-adapt to a moving target.

🟢 Intuition — a shifting target Imagine trying to learn to catch a ball, but the ball's weight and speed change every time you practice. Your learning would be very slow — you'd have to re-learn each time the parameters changed. Batch Norm stabilizes the input distribution to each layer, so each layer sees a more consistent input distribution and can learn faster.

12.2 Two benefits

  • Stabilizes learning: Each layer's inputs remain roughly normalized, so gradient descent has a well-conditioned surface to work with.
  • Allows larger learning rates: With normalized inputs, the optimizer can take larger steps without diverging. This directly speeds up training.
💡 Insight — Batch Norm's main practical effect The main effect of Batch Norm is that it makes the network much less sensitive to the exact initialization and allows a much larger learning rate. In practice, this often makes the difference between a model that trains and one that doesn't.

13. Covariate Shift

🔵 Definition — Covariate shift Covariate shift is the phenomenon where the distribution of the inputs \(X\) changes, even though the underlying function \(X \to Y\) stays the same. A model trained on one input distribution may perform poorly on a shifted distribution, even though the task is unchanged.

13.1 How Batch Norm relates to covariate shift

Within a deep network, each layer's inputs are the previous layer's activations. As training progresses, those activations change — a form of internal covariate shift. Batch Norm directly combats this by re-normalizing the inputs at every layer, keeping them in a stable range.

🟡 Important — an honest note The precise reasons Batch Norm works are still actively discussed in the research literature. The covariate-shift explanation is intuitive and commonly cited, but researchers have pointed out that the story is not the whole picture. What is unambiguous is that Batch Norm makes deep networks much easier to train — this is confirmed in practice across many architectures.

14. Batch Norm as Regularization

14.1 The regularization effect

Each mini-batch's mean and variance are slightly different, so the normalized activations \(\tilde{z}\) are slightly noisy. This noise is similar in spirit to dropout — it makes the network less able to rely on any specific activation value, which has a mild regularizing effect.

🔴 Warning — Batch Norm is not a replacement for regularization Batch Norm's regularization effect is mild. It is not a substitute for L2 or dropout. If you are overfitting, use a proper regularization method. Batch Norm just happens to add a small amount of noise on top.
💡 Insight — interaction with mini-batch size The smaller the mini-batch, the more noise there is (because the mean and variance are computed from fewer examples), so the stronger the regularization effect. Conversely, larger mini-batches give more stable statistics but weaker regularization. This is one of the many subtle interactions that make deep learning an empirical discipline.

15. Multi-class Classification — Softmax Regression

15.1 From binary to multi-class

So far we have focused on binary classification (is this a cat, yes or no?). But many real problems have more than two classes — for example, recognizing cats, dogs, and baby chicks. This is called multi-class classification.

15.2 The softmax layer

🔵 Definition — Softmax The softmax function takes a vector of real numbers \(z^{[L]} \in \mathbb{R}^C\) and produces a probability distribution over \(C\) classes: \[ a^{[L]}_i = \frac{e^{z^{[L]}_i}}{\sum_{j=1}^{C} e^{z^{[L]}_j}} \] Each output is between 0 and 1, and all outputs sum to 1.

15.3 Why softmax?

🟢 Intuition — from scores to probabilities The final layer produces raw scores \(z^{[L]}_1, \dots, z^{[L]}_C\). We want these to represent probabilities, which requires two things: (1) they are all non-negative, and (2) they sum to 1. The exponential function \(e^{z}\) makes everything positive, and dividing by the sum enforces the sum-to-1 property. Higher scores → exponentially higher probabilities.
🟡 Important — hard max vs soft max A "hard max" would set the largest score to 1 and the rest to 0. Softmax instead gives a soft probability distribution — the largest class gets the highest probability, but others still get non-zero probability. This is useful because it provides a gradable signal during training.

16. Softmax Loss and Examples

16.1 The loss function

For multi-class classification with softmax output, the loss is the categorical cross-entropy:

\[ \mathcal{L}(y, \hat{y}) = -\sum_{i=1}^{C} y_i \log(\hat{y}_i) \]

Where:

  • \(y\) — the true label, a one-hot vector (e.g. \([1, 0, 0]\) if the true class is 1).
  • \(\hat{y}\) — the predicted probabilities from softmax.
  • \(C\) — the number of classes.

Because \(y\) is one-hot, only one term is nonzero. If the true class is \(i\), then:

\[ \mathcal{L}(y, \hat{y}) = -\log(\hat{y}_i) \]
🟣 Example — 3-class problem

Suppose the true label is class 1 (so \(y = [1, 0, 0]\)) and the network predicts \(\hat{y} = [0.7, 0.2, 0.1]\). Then:

\[ \mathcal{L} = -(1 \cdot \log 0.7 + 0 \cdot \log 0.2 + 0 \cdot \log 0.1) = -\log 0.7 \approx 0.357 \]

If the network predicted \(\hat{y} = [0.9, 0.05, 0.05]\):

\[ \mathcal{L} = -\log 0.9 \approx 0.105 \]

The second prediction is better (closer to the true class), so the loss is smaller. This is exactly what we want.

16.2 Softmax with more classes — decision boundaries

16.3 Softmax in a neural network — putting it together

The forward pass of a multi-class network with softmax output looks like:

# Layers 1 to L-1: usual activation
for l in range(1, L):
    Z = W[l] @ A_prev + b[l]
    A = g[l](Z)

# Final layer L: softmax
Z_L = W[L] @ A_prev + b[L]
A_L = softmax(Z_L)   # probability distribution over C classes

17. Deep Learning Frameworks

17.1 Why use a framework?

Implementing backpropagation by hand is a great learning exercise, but for real projects, frameworks save enormous time and reduce bugs. They handle:

  • Automatic differentiation (computing gradients for you).
  • GPU acceleration.
  • Optimized linear algebra primitives.
  • Standard architectures, layers, and optimizers.

18. TensorFlow and the Motivating Problem

18.1 The motivating problem

Consider a very simple optimization problem. Suppose we want to minimize:

\[ J(w) = w^2 - 10w + 25 = (w - 5)^2 \]

The minimum is at \(w = 5\) with \(J(5) = 0\). In TensorFlow, you would write:

import tensorflow as tf

w = tf.Variable(0.0)             # initial guess
optimizer = tf.keras.optimizers.SGD(learning_rate=0.1)

for step in range(100):
    with tf.GradientTape() as tape:
        J = (w - 5) ** 2
    grad = tape.gradient(J, w)
    optimizer.apply_gradients([(grad, w)])

print(w.numpy())   # should be close to 5
⚙️ Implementation — how TensorFlow works
  1. Define variables — the parameters you want to optimize.
  2. Define the cost function using those variables.
  3. Use GradientTape to record operations and compute gradients automatically.
  4. Use an optimizer to update the variables in the direction that reduces the cost.

No manual backpropagation needed — the framework handles it.

💡 Insight — the value of frameworks The example is trivially simple, but the same pattern scales to networks with millions of parameters: define the cost, let the framework compute gradients, apply an optimizer. This is why frameworks like TensorFlow and PyTorch have made deep learning so much more accessible.

20. Review Questions

Q1. Which hyperparameter should you tune first, and why?

The learning rate \(\alpha\). It has the single largest impact on whether training converges at all and how fast. Small changes in \(\alpha\) can mean the difference between a model that trains smoothly and one that diverges. Tune it first and most carefully; other hyperparameters matter less in comparison.

Q2. Why is random search preferred over grid search?

Because we usually don't know which hyperparameters are important ahead of time. With grid search, if only 2 hyperparameters matter out of 5, you waste most of your experiments on combinations that don't matter. With random search, you explore more distinct values per axis for the same number of experiments. If you later find a promising region, use coarse-to-fine to narrow the search.

Q3. When sampling the learning rate \(\alpha\), why should you sample on a log scale rather than a linear scale?

Because the learning rate spans orders of magnitude (e.g. \(10^{-4}\) to \(10^{0}\)). Linear sampling would spend 90% of the samples in the top decade (\(0.1\) to \(1\)) and only 10% in the lower decades. Log sampling spreads samples evenly across decades, so you explore small values (where differences often matter most) more thoroughly.

Q4. What is the right scale for sampling \(\beta\) in exponentially weighted averages? Give the formula.

Sample \(1-\beta\) on a log scale. Formula: \(1-\beta = 10^{r}\) where \(r \sim \text{Uniform}(a, b)\). For example, for \(\beta \in [0.9, 0.999]\), use \(1-\beta \in [10^{-3}, 10^{-1}]\), so \(r \sim \text{Uniform}(-3, -1)\). This spreads samples evenly across the effective window sizes \(10, 100, 1000\).

Q5. What is "coarse to fine" and when should you use it?

Coarse-to-fine means starting with a broad random search over the hyperparameter space, identifying the region where performance is best, then zooming in and sampling more densely in that region. Use it after an initial round of random search has given you a rough sense of which region works well. It is especially helpful when you have many hyperparameters to tune and limited compute.

Q6. Explain the "Pandas vs Caviar" analogy for hyperparameter tuning.

Panda: When compute is limited, you can only run one or two models at a time. You "babysit" the model — watch its learning curve and adjust hyperparameters as you go. Caviar: When compute is abundant, you train many models in parallel with different hyperparameters and pick the best one. Most people today use a mix of the two approaches.

Q7. What is Batch Normalization and what problem does it solve?

Batch Normalization is a technique that normalizes the pre-activations of each layer within each mini-batch to have approximately zero mean and unit variance, then applies a learnable scale \(\gamma\) and shift \(\beta\). It solves the problem of internal covariate shift — as previous layers change during training, the inputs to later layers shift, forcing them to constantly re-adapt. Batch Norm stabilizes these inputs, allowing faster training and larger learning rates.

Q8. Write the four steps of Batch Norm computation for a mini-batch.
  1. Compute the mean: \(\mu = \frac{1}{m}\sum_i z^{(i)}\)
  2. Compute the variance: \(\sigma^2 = \frac{1}{m}\sum_i (z^{(i)} - \mu)^2\)
  3. Normalize: \(z_{\text{norm}}^{(i)} = \frac{z^{(i)} - \mu}{\sqrt{\sigma^2 + \varepsilon}}\)
  4. Scale and shift: \(\tilde{z}^{(i)} = \gamma \, z_{\text{norm}}^{(i)} + \beta\)
Q9. In Batch Norm, why are \(\gamma\) and \(\beta\) learned parameters rather than fixed constants?

If we forced activations to always have exactly zero mean and unit variance, we would restrict the network's representational power — the network could not choose to have, say, a nonzero mean at some layer if that were useful. By making \(\gamma\) and \(\beta\) learnable, the network can recover any mean and variance it wants. The normalization just provides a well-conditioned starting point that the network can then adjust during training.

Q10. Why is the bias \(b^{[l]}\) usually dropped when using Batch Norm?

Because Batch Norm subtracts the mini-batch mean \(\mu\) from \(z^{[l]}\). Any constant offset added by \(b^{[l]}\) would be immediately subtracted out by the normalization. So \(b^{[l]}\) has no effect on the output — the Batch Norm shift parameter \(\beta^{[l]}\) takes over the role of the bias. Standard practice is to drop \(b^{[l]}\) or set it to zero.

Q11. How does Batch Norm behave differently at training vs test time?

At training time, Batch Norm computes \(\mu\) and \(\sigma^2\) from each mini-batch. At test time, we process examples one at a time (or in very small batches) — computing statistics from a single example would be meaningless. Instead, we use exponentially weighted running averages of \(\mu\) and \(\sigma^2\) accumulated during training.

Q12. What is covariate shift, and how does it relate to Batch Norm?

Covariate shift is when the distribution of inputs \(X\) changes while the task \(X \to Y\) stays the same. Inside a deep network, the inputs to each layer (the previous layer's activations) change as training progresses — a form of internal covariate shift. Batch Norm stabilizes each layer's inputs by re-normalizing them at every step, which is one reason it speeds up training. Additional Context: researchers have pointed out that the covariate-shift story does not fully explain why Batch Norm works, but the practical benefit is unambiguous.

Q13. Does Batch Norm act as a regularizer? Why or why not?

Yes, it has a mild regularizing effect. Because each mini-batch computes its own mean and variance, the normalized activations are slightly noisy — similar in spirit to dropout. This noise makes the network less able to rely on specific activation values, which reduces overfitting slightly. However, this effect is small and should not be relied upon as a substitute for proper regularization (L2, dropout).

Q14. What is softmax and why is it used in the output layer of multi-class classifiers?

Softmax is a function that takes \(C\) real-valued scores and converts them into a probability distribution over \(C\) classes: \(a_i = e^{z_i} / \sum_j e^{z_j}\). It is used in the output layer because we want the network to output probabilities — all non-negative and summing to 1. The class with the highest probability is the predicted class.

Q15. What loss function is used with softmax and why?

The categorical cross-entropy loss: \(\mathcal{L} = -\sum_i y_i \log \hat{y}_i\), where \(y\) is the one-hot true label and \(\hat{y}\) is the softmax output. Because \(y\) is one-hot, the loss simplifies to \(-\log \hat{y}_i\) where \(i\) is the true class. It penalizes the model heavily when the predicted probability for the true class is low, which is exactly the behavior we want.

Q16. What is the difference between softmax and logistic regression?

Logistic regression is used for binary classification — a single output between 0 and 1 (a sigmoid). Softmax is a generalization to multi-class classification — \(C\) outputs that sum to 1. Logistic regression is a special case of softmax with \(C = 2\).

Q17. Name three criteria for choosing a deep learning framework.
  1. Ease of programming — both for development and for deployment.
  2. Running speed — critical for large models and datasets.
  3. Truly open — open source with good governance, so the project is not controlled by a single company in a way that could restrict use.
Q18. What does a deep learning framework like TensorFlow do for you?

It automates much of the work of training neural networks:

  • Automatic differentiation — computes gradients for you, so you don't have to implement backpropagation by hand.
  • GPU acceleration — runs matrix operations on GPUs, giving orders of magnitude speedups.
  • Optimized primitives — efficient implementations of matrix multiplication, convolutions, etc.
  • Standard layers and optimizers — you can compose models from pre-built components instead of writing everything from scratch.

Q19. Suppose you want to tune \(\alpha, \beta, \text{mini-batch size}, \text{and } \lambda\). Which would you sample on a log scale, which linearly, and which from a discrete set?

  • \(\alpha\) — log scale (e.g. \(10^{-4}\) to \(10^{-1}\)).
  • \(\lambda\) — log scale (e.g. \(10^{-5}\) to \(10^{-1}\)).
  • \(\beta\) — log scale on \(1-\beta\) (e.g. \(1-\beta \in [10^{-3}, 10^{-1}]\)).
  • Mini-batch size — discrete set of powers of 2 (64, 128, 256, 512).

Q20. What does Andrew Ng say about the stability of hyperparameter intuitions over time?

He advises re-evaluating hyperparameters occasionally. What was optimal a few years ago may not be optimal now — datasets, architectures, and hardware change. "Intuitions do get stale." Even for a problem you think you understand well, it is worth re-checking your hyperparameter choices periodically.

Q1. You have 5 hyperparameters to tune and a limited compute budget for 30 experiments. Would you use grid search or random search? Justify your answer with a concrete example.

Answer. Use random search.

Concrete example: suppose only 2 of the 5 hyperparameters actually matter (you don't know which). With grid search on 5 hyperparameters and 30 experiments, you can afford at most 2–3 values per axis, so you only try 2–3 distinct values of each important hyperparameter. With random search and 30 experiments, you try 30 distinct values of each hyperparameter. If even one of the important hyperparameters has a "sweet spot" that grid search misses, you lose. Random search is far more likely to hit a good region.

After identifying a promising region via random search, use coarse-to-fine to zoom in.

Q2. Suppose you want to tune the learning rate in the range \(10^{-4}\) to \(10^{-1}\). Write pseudocode to sample it correctly. Explain why linear sampling would be a bad idea.

Answer. Correct sampling:

r = -4 + 3 * np.random.rand()   # r uniform in [-4, -1]
alpha = 10 ** r                  # log-uniform in [10^-4, 10^-1]

Why linear sampling is bad: if you instead did alpha = 0.0001 + 0.0999 * np.random.rand(), then 90% of samples would fall in the range \([10^{-2}, 10^{-1}]\) (since that interval is 0.09 out of the 0.0999 total range) and only 10% would fall below \(10^{-2}\). But the region \(10^{-4}\) to \(10^{-2}\) contains two whole decades of potentially useful learning rates. You would under-sample that region and likely miss the best value. Log sampling spreads samples evenly across decades.

Q3. You are training a deep network and observe that the training loss decreases for a while, then plateaus at a value higher than you would like. Adding Batch Norm suddenly makes the loss continue decreasing. Explain why Batch Norm might help here, in terms of the internal covariate shift idea.

Answer. Without Batch Norm, as training progresses, the weights of earlier layers change. This shifts the distribution of inputs to later layers — a form of internal covariate shift. Later layers have to constantly re-adapt to a moving target, which slows learning and can lead to a plateau.

Batch Norm re-normalizes the pre-activations at each layer using the current mini-batch's mean and variance. Each layer therefore sees inputs with a stable mean and variance, regardless of how the previous layers change. This gives every layer a well-conditioned input distribution to learn from, allowing gradient descent to continue making progress — hence the loss resumes decreasing.

Additional note: the covariate shift story is intuitive and commonly used, but researchers have pointed out that it does not fully explain Batch Norm's success. The practical effect — more stable, faster training — is well established.

Q4. What happens if you keep the bias \(b^{[l]}\) in a layer that uses Batch Norm? Is it harmful?

Answer. It is not exactly "harmful" in the sense of causing the network to fail, but it is redundant — the bias has no effect on the output because Batch Norm subtracts the mini-batch mean from \(z^{[l]}\), which removes any constant offset. The parameter \(b^{[l]}\) would receive a gradient that effectively cancels itself out, and it would simply stay near its initial value (or be driven in a direction that has no effect on the output).

Convention is to drop \(b^{[l]}\) entirely when using Batch Norm. The learnable shift parameter \(\beta^{[l]}\) of Batch Norm takes over the role of the bias.

Keeping it is not harmful per se, but it wastes memory, adds useless parameters, and can cause confusion when debugging. Drop it.

Q5. You use Batch Norm with a mini-batch size of 32. Then you switch to a mini-batch size of 512. Does Batch Norm's behavior change? Explain.

Answer. Yes, in two important ways:

  • Noise / regularization effect: With mini-batch size 32, the mean and variance are computed from only 32 samples, so they are noisy. This introduces more noise into the normalized activations, giving a stronger (but still mild) regularization effect. With size 512, the statistics are much more stable, so the regularization effect is weaker.
  • Accuracy of statistics: Small batches give noisier \(\mu\) and \(\sigma^2\), which can occasionally hurt performance if the noise is very high. Very small batches (like 8 or 16) can sometimes cause instability. Larger batches give more stable statistics but less regularization.

In practice, Batch Norm works with a wide range of mini-batch sizes, but the sweet spot is often 64–512. Very small batches may need extra care.

Q6. Suppose you have a network whose last layer uses softmax over 10 classes. You observe that the loss is stuck at \(\log(10) \approx 2.3\) even after many iterations. What is likely going wrong?

Answer. \(\log(10)\) is exactly the loss you would get if the network were predicting a uniform distribution over the 10 classes — i.e., each class getting probability 0.1. This is the loss you get from random guessing. So the network is not learning at all.

Possible causes:

  • Learning rate too small — the network is barely moving.
  • Learning rate too large — the optimizer is diverging, and the weights have gone to values that produce saturated softmax outputs (uniform predictions).
  • Bug in the loss function or gradient computation — for example, using the wrong loss with softmax, or forgetting to apply softmax at all.
  • Data issue — for example, labels not properly one-hot encoded, or a mismatch between the number of outputs and number of classes.
  • Bad initialization — all weights initialized to zero (symmetry problem).

Diagnostic steps: check that the loss decreases on a small subset of the data (if it doesn't, there is a bug); check gradients against numerical approximations; try different learning rates.

Q7. Explain the following claim: "Batch Norm's regularization effect is a side effect, not its main purpose." Do you agree?

Answer. Yes, I agree. Batch Norm's main purpose is to stabilize and speed up training by normalizing intermediate activations. This allows larger learning rates and makes the network less sensitive to initialization — these are the primary benefits, demonstrated consistently in practice.

The regularization effect comes from the fact that each mini-batch uses its own \(\mu\) and \(\sigma^2\), which introduces some noise into the normalized activations. This noise is similar in spirit to dropout, and it does slightly reduce overfitting. But:

  • The effect is mild compared to dedicated regularization methods.
  • It depends on mini-batch size — larger batches give weaker regularization.
  • It is a byproduct of how Batch Norm works, not a design goal.

So the claim is accurate: Batch Norm's regularization effect is a side effect. If you are overfitting, use L2 or dropout — don't rely on Batch Norm alone.

Q8. You are building a multi-class classifier with 4 classes. What should the output layer look like? What activation function should you use? What loss?

Answer.

  • Output layer size: 4 neurons (one per class).
  • Activation: softmax. This converts the 4 pre-activations into a probability distribution over the 4 classes.
  • Loss: categorical cross-entropy: \(\mathcal{L} = -\sum_{i=1}^{4} y_i \log \hat{y}_i\). With one-hot labels, this reduces to \(-\log \hat{y}_i\) where \(i\) is the true class.

During inference, the predicted class is \(\arg\max_i \hat{y}_i\).

Important: do not use sigmoid on each output — that would treat the classes as independent binary problems, which is appropriate for multi-label classification (where an example can belong to multiple classes), but not for multi-class classification (mutually exclusive). For multi-class, use softmax.

Q9. Compare and contrast: (a) normalizing inputs, (b) Batch Norm, and (c) softmax. What problem does each solve, and how are they related?

Answer.

(a) Normalizing inputs: Done once, before training. Computes \(\mu\) and \(\sigma^2\) on the training set, then applies the transformation \(x \to (x-\mu)/\sigma\) to all inputs. Solves the problem of poorly-scaled features, which makes the cost surface elongated and gradient descent slow. Applied to the raw input \(X\), not to intermediate activations.

(b) Batch Norm: Applied at every layer during training, per mini-batch. Computes \(\mu\) and \(\sigma^2\) from the mini-batch's pre-activations, normalizes, then scales and shifts with learnable \(\gamma, \beta\). Solves internal covariate shift — the shifting distribution of inputs to each layer as earlier layers change. Allows larger learning rates and speeds up training. Also has a mild regularization side effect.

(c) Softmax: Applied at the output layer for multi-class problems. Takes \(C\) real-valued scores and produces a probability distribution over \(C\) classes via \(a_i = e^{z_i} / \sum_j e^{z_j}\). Solves the problem of needing a proper probability output for more than 2 classes. Logistic regression is the 2-class special case.

Relationships: (a) and (b) are conceptually similar — both normalize a set of values to zero mean and unit variance. The key differences are where (inputs vs intermediate layers) and when (once vs every mini-batch). (c) is unrelated to (a) and (b); it is about output representation, not normalization.

Q10. In the TensorFlow motivating example, why do we need GradientTape? Couldn't we just compute the derivative analytically?

Answer. In the trivial example \(J(w) = (w-5)^2\), yes — the derivative \(dJ/dw = 2(w-5)\) is easy to compute by hand. But for a real neural network with millions of parameters and many layers, deriving and coding the gradient by hand is extremely error-prone.

GradientTape uses automatic differentiation: it records every operation that involves the watched variables during the forward pass, building a computational graph. Then tape.gradient() traverses this graph backward, applying the chain rule automatically to compute gradients with respect to any variable.

This is the core value of frameworks like TensorFlow and PyTorch: you write only the forward pass, and the framework handles the entire backward pass. This eliminates a huge class of bugs and makes it possible to iterate on architectures quickly.

There is still a place for understanding backprop by hand — it helps you debug when things go wrong, and it is essential for understanding the algorithms. But for actual implementation, automatic differentiation is the standard tool.
