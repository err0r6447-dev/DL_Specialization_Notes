1. Why Optimization Matters

Up to now you have learned how to build a neural network and how to make it generalize well (regularization, normalization, and so on). But there is a third ingredient that determines whether your model actually trains in a reasonable amount of time: how you optimize the cost function.

🔵 Definition — Optimization Algorithm An optimization algorithm is a procedure for adjusting the parameters of a model (weights and biases) in order to minimize the cost function \(J\). Standard gradient descent is the simplest example; this week we study faster, more robust alternatives.
🟢 Intuition — why "faster" matters Training a deep network can take hours, days, or weeks. If a better optimizer halves that time, you can run twice as many experiments. Optimization algorithms do not change what the model can represent — they change how quickly and reliably you can find good parameters.

This week builds up a toolkit of optimization algorithms:

  • Mini-batch gradient descent — process the training set in chunks rather than all at once.
  • Exponentially weighted averages — a smoothing technique used by many advanced optimizers.
  • Momentum — accumulate direction to accelerate through flat regions.
  • RMSprop — adapt the learning rate per parameter based on recent gradient magnitudes.
  • Adam — combine momentum and RMSprop; the current default choice for most deep learning problems.
  • Learning rate decay — gradually shrink the learning rate over time.

2. Mini-batch Gradient Descent

2.1 The problem with batch gradient descent

In batch gradient descent, you compute the gradient of the cost over the entire training set before taking a single step. If you have \(m = 5{,}000{,}000\) training examples, one update requires processing all five million examples. That is very slow — especially when you could be making progress with much less work.

2.2 The mini-batch idea

🔵 Definition — Mini-batch gradient descent In mini-batch gradient descent, you split the training set into small chunks called mini-batches. You compute the gradient on one mini-batch, take a step, then move to the next mini-batch. One full pass through the entire training set is called an epoch.
🟣 Example — big data split

Suppose \(m = 5{,}000{,}000\) examples. You choose a mini-batch size of \(1{,}000\). Then you have \(5{,}000\) mini-batches. Define:

  • \(X^{\{t\}}\) — the inputs of mini-batch \(t\).
  • \(Y^{\{t\}}\) — the labels of mini-batch \(t\).

For \(t = 1, \dots, 5{,}000\): forward propagate on \(X^{\{t\}}\), compute the cost on the mini-batch, backpropagate, and update the parameters. One pass over all \(5{,}000\) mini-batches is one epoch.

2.3 The training loop

For each epoch, for each mini-batch \(t\):

  1. Forward propagation on the mini-batch: \[ Z^{[l]} = W^{[l]} A^{[l-1]} + b^{[l]}, \quad A^{[l]} = g^{[l]}(Z^{[l]}) \]
  2. Compute cost on the mini-batch (with \(m_{\text{mb}}\) examples): \[ J^{\{t\}} = \frac{1}{m_{\text{mb}}} \sum_{i=1}^{m_{\text{mb}}} \mathcal{L}(y^{(i)}, \hat{y}^{(i)}) \;+\; \frac{\lambda}{2 m_{\text{mb}}} \sum_l \|W^{[l]}\|_F^2 \]
  3. Backward propagation on the mini-batch to get \(dW^{[l]}, db^{[l]}\).
  4. Update parameters: \[ W^{[l]} := W^{[l]} - \alpha \, dW^{[l]}, \qquad b^{[l]} := b^{[l]} - \alpha \, db^{[l]} \]

Important notation: \(X^{\{t\}}, Y^{\{t\}}\) use curly braces to denote the \(t\)-th mini-batch, distinguishing from \(X^{(i)}\) (the \(i\)-th example) and \(X^{[l]}\) (the \(l\)-th layer).

2.4 The cost curve

🟢 Intuition — why the oscillation? Each mini-batch is a small, possibly biased sample of the full training set. Its gradient points in a slightly different direction from the "true" gradient. So individual updates are noisy. But on average, the direction is correct, and the cost trends downward.
🟡 Important — why mini-batch is faster in practice With vectorization, processing 1,000 examples is roughly as fast as processing 1 example. So mini-batch gradient descent gets ~1,000× more updates per unit of computation than batch gradient descent. Even with slightly noisier steps, this is a huge wall-clock speedup.
🔴 Warning — noise in the cost curve If you plot the cost on each mini-batch, it will go up and down. This is not a bug. A common debugging tip: compute the cost on a fixed small set of examples to see a smooth curve, or average over several mini-batches.

3. Choosing Your Mini-batch Size

3.1 The two extremes

Mini-batch sizeNameBehavior
\(= m\) (all examples) Batch gradient descent Smooth cost curve, but very slow — one update per full pass, no vectorization gains beyond a single large matrix operation, and memory pressure.
\(= 1\) (one example) Stochastic gradient descent (SGD) Very noisy, one update per example. Loses all vectorization benefits (processing one example at a time is inefficient).
In between Mini-batch gradient descent Best of both worlds — fast vectorized updates with reasonable noise.

3.2 Practical guidelines

⚙️ Implementation — choosing mini-batch size
  • If your training set is small (say \(m \leq 2{,}000\)), just use batch gradient descent. Mini-batching gives no benefit for such small datasets.
  • If your training set is large, use mini-batches. Typical sizes are powers of 2: \(64, 128, 256, 512, 1024\).
  • The reason for powers of 2 is purely practical: computer memory and GPU/CPU memory are organized in powers of 2, so these sizes tend to be slightly more efficient.
  • Make sure a mini-batch fits in CPU/GPU memory. Too large and you will run out of memory; too small and you lose vectorization.
🔴 Warning — the "default" mini-batch size A common starting point is 64 or 128 for small networks, and larger (256, 512) for bigger ones. But there is no universal best value — treat it as a hyperparameter to tune. You will often find that a range of sizes works fine.

4. Exponentially Weighted Averages

Before we look at the advanced optimizers (Momentum, RMSprop, Adam), we need one key building block: the exponentially weighted average (EWA). This is a simple technique for smoothing a noisy sequence of numbers.

4.1 The temperature example

Imagine you are recording the daily temperature in London. Each day's reading \(\theta_t\) is somewhat noisy — the weather fluctuates. You want a smoothed version \(v_t\) that shows the underlying trend without the day-to-day jitter.

4.2 The formula

🔵 Definition — Exponentially Weighted Average The exponentially weighted average of a sequence \(\theta_1, \theta_2, \theta_3, \dots\) is defined recursively by: \[ v_t = \beta \, v_{t-1} + (1 - \beta) \, \theta_t \] where \(0 \leq \beta < 1\) is a hyperparameter controlling the amount of smoothing, and \(v_0 = 0\).

Symbols:

  • \(\theta_t\) — the raw value at time \(t\) (e.g. today's temperature).
  • \(v_t\) — the smoothed (averaged) value at time \(t\).
  • \(\beta\) — a hyperparameter between 0 and 1. Larger \(\beta\) = smoother average.
  • \((1 - \beta)\) — the weight given to the current observation.
🟣 Example — a few steps

Take \(\beta = 0.9\) and \(v_0 = 0\). Suppose the temperatures are \(40, 49, 45, \dots\)

\[ \begin{aligned} v_1 &= 0.9 \cdot 0 + 0.1 \cdot 40 = 4 \\ v_2 &= 0.9 \cdot 4 + 0.1 \cdot 49 = 3.6 + 4.9 = 8.5 \\ v_3 &= 0.9 \cdot 8.5 + 0.1 \cdot 45 = 7.65 + 4.5 = 12.15 \end{aligned} \]

You can see the average is slowly climbing toward the actual temperatures.

4.3 What "exponential" means

If you unroll the recursion, \(v_t\) is a weighted sum of all past \(\theta\) values:

\[ v_t = (1-\beta) \left[ \theta_t + \beta \theta_{t-1} + \beta^2 \theta_{t-2} + \beta^3 \theta_{t-3} + \cdots \right] \]

The weight given to \(\theta_{t-k}\) is \((1-\beta)\beta^k\), which decays exponentially as \(k\) grows. That is why it is called an exponentially weighted average: recent values count more, old values fade away.

4.4 How much history does the average use?

🟡 Important — rule of thumb The effective window of the average is roughly \(\frac{1}{1-\beta}\) time steps.
  • \(\beta = 0.9\) → effective window of ~10 observations.
  • \(\beta = 0.98\) → effective window of ~50 observations.
  • \(\beta = 0.5\) → effective window of ~2 observations (a very reactive average).

This follows from \((1 - \varepsilon)^{1/\varepsilon} \approx 1/e \approx 0.35\), where \(\varepsilon = 1 - \beta\). After \(1/(1-\beta)\) steps, the weight has dropped to about 1/3 of the initial weight.

5. Implementing Exponentially Weighted Averages

Implementation is extremely cheap. You keep just one running number \(v\) and update it each step:

v = 0
for theta_t in theta_sequence:
    v = beta * v + (1 - beta) * theta_t
    # Optionally: store or use v
💡 Insight — memory efficiency The exponentially weighted average requires O(1) memory — you only need to remember \(v\), not the entire history. This is why it is so appealing in optimizers: you get a smoothed estimate of a quantity without storing a big window of past values.

6. Bias Correction

6.1 The problem

When you initialize \(v_0 = 0\), the first few values of \(v_t\) are biased toward zero. Example: with \(\beta = 0.98\), the first few values look like:

\[ \begin{aligned} v_1 &= 0.98 \cdot 0 + 0.02 \theta_1 = 0.02 \theta_1 \\ v_2 &= 0.98 \cdot 0.02 \theta_1 + 0.02 \theta_2 \approx 0.02 \theta_2 \\ \end{aligned} \]

For a while, \(v_t\) is only about \(2\%\) of \(\theta_t\), instead of being close to it. This produces a "starting low" bias in the average — visible in Figure 5 as a curve that begins well below the data.

6.2 The fix

🔵 Definition — Bias Correction Instead of using \(v_t\) directly, use: \[ v_t^{\text{corrected}} = \frac{v_t}{1 - \beta^t} \] where \(t\) is the current time step (starting at \(t=1\)). As \(t\) grows, \(\beta^t\) becomes very small, so the correction factor approaches 1 and has almost no effect.
🟣 Example

With \(\beta = 0.98\):

  • At \(t=1\): \(1 - \beta^1 = 0.02\), so we divide \(v_1\) by 0.02 — this "undoes" the initial shrink.
  • At \(t=2\): \(1 - \beta^2 = 1 - 0.9604 = 0.0396\).
  • At \(t=50\): \(1 - \beta^{50} \approx 0.636\).
  • At \(t=200\): \(1 - \beta^{200} \approx 1\), so the correction is negligible.

So the correction only matters in the early steps.

🟡 Important — is bias correction always needed? In practice, many implementations skip bias correction and still work fine — especially when there are many iterations, since the correction becomes negligible. But it is standard in Adam and is worth knowing.

7. Gradient Descent with Momentum

7.1 The problem it solves

Standard gradient descent can oscillate when the cost surface is elongated — for example, when one parameter needs a large change and another needs a small one. The updates zig-zag, and progress in the "right" direction is slow.

7.2 The idea

🟢 Intuition — a ball rolling downhill Imagine a ball rolling down a hill. On flat ground it still moves — because of the momentum it built up. In the same way, if we accumulate past gradients, the optimizer keeps moving in a consistent direction even if the current gradient is small or points sideways.

7.3 The algorithm

On each iteration \(t\) (using the current mini-batch):

  1. Compute \(dW, db\) on the current mini-batch.
  2. Update the velocity for each parameter: \[ v_{dW} = \beta \, v_{dW} + (1-\beta)\, dW \] \[ v_{db} = \beta \, v_{db} + (1-\beta)\, db \]
  3. Update the parameters using the velocity instead of the raw gradient: \[ W := W - \alpha \, v_{dW}, \qquad b := b - \alpha \, v_{db} \]
🟡 Important — two variants of the update There are two conventions in the literature:
  • Andrew Ng's slides: \(v_{dW} = \beta v_{dW} + (1-\beta) dW\), then \(W := W - \alpha v_{dW}\).
  • Some other texts: \(v_{dW} = \beta v_{dW} + dW\), then \(W := W - \alpha v_{dW}\).

Both work; the first is the "exponentially weighted average of gradients" view, the second uses a slightly different scaling. Pick one and stick with it. Below we use the first, which matches the course slides.

🟣 Example — a simple case

Suppose \(\beta = 0.9\), and over three iterations the gradient \(dW\) is \(1, 1, 1\). Then:

  • \(v_{dW}^{(1)} = 0.9 \cdot 0 + 0.1 \cdot 1 = 0.1\)
  • \(v_{dW}^{(2)} = 0.9 \cdot 0.1 + 0.1 \cdot 1 = 0.19\)
  • \(v_{dW}^{(3)} = 0.9 \cdot 0.19 + 0.1 \cdot 1 = 0.271\)

The velocity builds up over iterations, so the effective step size gets larger — which is exactly what we want when gradients consistently point the same way.

7.4 Hyperparameters

⚙️ Implementation — momentum hyperparameters
  • \(\alpha\) — learning rate. Tune as usual.
  • \(\beta\) — momentum coefficient, typically \(0.9\). It is the same \(\beta\) as in the exponentially weighted average, applied to gradients rather than to temperatures.
  • \(v_{dW}, v_{db}\) — initialized to zero.
🔴 Warning — no bias correction needed in practice Unlike in the EWA temperature example, we usually do not apply bias correction in momentum. With a reasonable \(\beta\) (e.g. 0.9) and many iterations, the initial bias washes out quickly and has negligible effect on the final result.

8. RMSprop

8.1 The idea

🔵 Definition — RMSprop RMSprop (Root Mean Square propagation) is an optimization algorithm that adapts the learning rate for each parameter individually, based on the recent magnitude of the gradients. Parameters with consistently large gradients get a smaller effective learning rate; parameters with small gradients get a larger one.
🟢 Intuition — normalizing by the gradient magnitude Suppose \(W_1\) has a large gradient and \(W_2\) has a small one. Standard gradient descent moves \(W_1\) too fast and \(W_2\) too slow. RMSprop divides each update by a running average of the recent squared gradients. Large gradients → large denominator → smaller step. This equalizes progress across parameters.

8.2 The algorithm

On each iteration \(t\):

  1. Compute \(dW, db\).
  2. Update the squared-gradient accumulators: \[ S_{dW} = \beta_2 \, S_{dW} + (1-\beta_2)\, (dW)^2 \] \[ S_{db} = \beta_2 \, S_{db} + (1-\beta_2)\, (db)^2 \] Note: \((dW)^2\) is element-wise squaring.
  3. Update the parameters: \[ W := W - \alpha \, \frac{dW}{\sqrt{S_{dW}} + \varepsilon}, \qquad b := b - \alpha \, \frac{db}{\sqrt{S_{db}} + \varepsilon} \] where \(\varepsilon\) is a very small number (e.g. \(10^{-8}\)) to avoid division by zero.

8.3 Why it works

Consider a parameter whose gradient has been oscillating. The accumulator \(S\) grows. Dividing by \(\sqrt{S}\) shrinks the effective step size — dampening oscillations. A parameter whose gradient has been consistently small has a small \(S\), so its step size stays relatively large — letting it catch up.

🟡 Important — hyperparameters
  • \(\alpha\) — learning rate. Needs tuning.
  • \(\beta_2\) — decay rate for the squared gradients. Typical value: 0.999.
  • \(\varepsilon\) — small constant, e.g. \(10^{-8}\), to prevent division by zero.
🔴 Warning — \(\varepsilon\) position \(\varepsilon\) must be added outside the square root, in the denominator: \(\sqrt{S} + \varepsilon\). Putting it inside as \(\sqrt{S + \varepsilon}\) changes the behavior subtly and is not standard.

9. Adam Optimization Algorithm

9.1 The idea

🔵 Definition — Adam Adam (Adaptive Moment Estimation) combines Momentum and RMSprop. It keeps both a running average of the gradients (first moment, like momentum) and a running average of the squared gradients (second moment, like RMSprop). It also applies bias correction to both. Adam is currently the most widely used optimizer in deep learning.
🟢 Intuition Adam is like momentum (which smooths the direction of updates) plus RMSprop (which scales each update by the recent gradient magnitude) plus bias correction (which fixes the early underestimation). The result is a robust, fast, low-tuning optimizer.

9.2 The algorithm

Initialize the accumulators to zero: \(v_{dW} = 0, v_{db} = 0, S_{dW} = 0, S_{db} = 0\). Also initialize the step counter \(t = 0\).

On each iteration:

  1. Increment \(t := t + 1\).
  2. Compute \(dW, db\) on the current mini-batch.
  3. Momentum terms (first moment): \[ v_{dW} = \beta_1 \, v_{dW} + (1-\beta_1)\, dW \] \[ v_{db} = \beta_1 \, v_{db} + (1-\beta_1)\, db \]
  4. RMSprop terms (second moment): \[ S_{dW} = \beta_2 \, S_{dW} + (1-\beta_2)\, (dW)^2 \] \[ S_{db} = \beta_2 \, S_{db} + (1-\beta_2)\, (db)^2 \]
  5. Bias corrections: \[ v_{dW}^{\text{corrected}} = \frac{v_{dW}}{1 - \beta_1^{\,t}}, \qquad v_{db}^{\text{corrected}} = \frac{v_{db}}{1 - \beta_1^{\,t}} \] \[ S_{dW}^{\text{corrected}} = \frac{S_{dW}}{1 - \beta_2^{\,t}}, \qquad S_{db}^{\text{corrected}} = \frac{S_{db}}{1 - \beta_2^{\,t}} \]
  6. Parameter update: \[ W := W - \alpha \, \frac{v_{dW}^{\text{corrected}}}{\sqrt{S_{dW}^{\text{corrected}}} + \varepsilon} \] \[ b := b - \alpha \, \frac{v_{db}^{\text{corrected}}}{\sqrt{S_{db}^{\text{corrected}}} + \varepsilon} \]

9.3 Hyperparameters

⚙️ Implementation — Adam default hyperparameters
HyperparameterMeaningTypical value
\(\alpha\)Learning rateNeeds tuning. Often \(10^{-3}\), \(10^{-4}\), etc.
\(\beta_1\)Decay rate for first moment (momentum)0.9
\(\beta_2\)Decay rate for second moment (RMSprop)0.999
\(\varepsilon\)Small constant to avoid division by zero\(10^{-8}\)

Of these, usually only \(\alpha\) needs tuning. The others are remarkably robust across problems.

💡 Insight — why Adam is so popular Adam works well "out of the box" for most problems. It combines the benefits of both momentum and RMSprop, requires little hyperparameter tuning, is memory-efficient, and handles sparse gradients (e.g. in NLP) especially well. Adam's name comes from adaptive moment estimation — it adapts using both the first and second moments of the gradients.

10. Learning Rate Decay

10.1 The problem

With a fixed learning rate \(\alpha\), the optimizer oscillates around the minimum rather than settling into it. If you shrink \(\alpha\) over time, the oscillations damp out and you settle closer to the optimum.

10.2 Common decay schedules

🔵 Definition — Learning rate decay A learning rate decay schedule is a rule for reducing the learning rate \(\alpha\) as training proceeds, usually as a function of the epoch number.

Some common forms (with \(\alpha_0\) the initial learning rate):

NameFormulaNotes
Exponential decay \(\alpha = 0.95^{\text{epoch-num}} \cdot \alpha_0\) The learning rate shrinks by a constant factor each epoch.
Inverse-time decay \(\alpha = \frac{k}{\sqrt{\text{epoch-num}}} \cdot \alpha_0\) Also written \(\frac{k}{\sqrt{t}} \cdot \alpha_0\) where \(t\) is the iteration.
Step decay Reduce \(\alpha\) by a factor (e.g. 0.5) every few epochs Simple, and used widely in practice.
Manual decay Watch the training and halve \(\alpha\) by hand when progress stalls Effective if you have the time.
🟡 Important — hyperparameters of decay Each schedule introduces its own hyperparameters (e.g. \(k\) in inverse-time decay, or the step size in step decay). In practice, a moderate amount of decay and thoughtful tuning of these schedules can help, but the gain from decay alone is usually smaller than the gain from a good optimizer like Adam.

11. The Problem of Local Optima

11.1 Local optima — a common worry

In low-dimensional problems, the cost surface can have many local minima — points where the cost is low locally but not globally. A naive optimizer might get stuck in one.

11.2 The modern view

💡 Insight — Andrew Ng's key point In very high-dimensional deep learning problems:
  • Bad local minima are actually unlikely. With so many dimensions, you would have to be unlucky in every direction to be trapped in a genuinely bad local minimum.
  • Most "flat" regions are saddle points — the gradient is (nearly) zero, but you can still escape by moving in some direction.
  • The real problem is plateaus — long flat regions where the gradient is tiny. Learning slows down because the gradient signal is weak.

11.3 Why momentum and Adam help here

On a plateau, the raw gradient is tiny, so vanilla gradient descent makes tiny steps. But momentum accumulates past gradients, allowing the optimizer to keep moving. Adam's adaptive scaling and momentum also help the optimizer continue progressing through flat regions. This is one reason why modern optimizers train deep networks much faster than plain gradient descent.

🔴 Warning — do not over-worry about local optima Beginners often worry about local optima in deep learning. In practice this is rarely the main concern. Focus on plateaus, saddle points, and good optimization algorithms instead.

12. Weekly Summary

What we covered

  • Mini-batch gradient descent — split the training set into small chunks; many updates per epoch; noisy but fast.
  • Choosing a mini-batch size — powers of 2 (64–512) are typical; make sure it fits in memory.
  • Exponentially weighted averages — a smoothing technique that keeps a running average of a sequence. Effective window ~ \(1/(1-\beta)\).
  • Bias correction — divide by \(1-\beta^t\) to correct the initial underestimation of EWA.
  • Momentum — accumulate past gradients to speed up consistent directions and damp oscillations.
  • RMSprop — divide each update by the recent RMS of gradients, adapting the effective step size per parameter.
  • Adam — combine momentum (first moment) with RMSprop (second moment) and bias correction. Default choice for most deep learning.
  • Learning rate decay — gradually reduce \(\alpha\) to settle closer to the minimum.
  • Local optima — rarely a problem in high dimensions; saddle points and plateaus are more important.

Must-Know Concepts

  • Mini-batch size = \(m\) → batch gradient descent. Mini-batch size = 1 → SGD.
  • Effective window of EWA is roughly \(1/(1-\beta)\).
  • Bias-corrected EWA: \(v_t^{\text{corrected}} = v_t / (1 - \beta^t)\).
  • Momentum update: \(v_{dW} = \beta v_{dW} + (1-\beta)dW\), then \(W \mathrel{-}= \alpha v_{dW}\).
  • RMSprop: \(S_{dW} = \beta_2 S_{dW} + (1-\beta_2)(dW)^2\), then \(W \mathrel{-}= \alpha dW/(\sqrt{S_{dW}} + \varepsilon)\).
  • Adam combines momentum + RMSprop + bias correction.
  • Adam default hyperparameters: \(\beta_1 = 0.9\), \(\beta_2 = 0.999\), \(\varepsilon = 10^{-8}\).

13. Review Questions

Q1. Why is mini-batch gradient descent often faster than batch gradient descent, even though each step is noisier?

Because it makes many more parameter updates per unit of wall-clock time. With vectorization, processing 1,000 examples costs roughly the same as processing one, so mini-batch gradient descent gets vastly more updates. Even if each update is noisier, the aggregate progress is much faster. The noise also has a slight regularizing effect.

Q2. What mini-batch size would you pick for a training set with 1,000,000 examples?

Typically a power of 2 such as 64, 128, 256, 512, or 1024. The choice depends on the model and hardware. Make sure each mini-batch fits in CPU/GPU memory. There is no universal best value — treat it as a hyperparameter.

Q3. Explain in one sentence what an exponentially weighted average does.

It computes a weighted average of past values in which each value is weighted by \((1-\beta)\beta^k\) where \(k\) is the number of steps back — recent values count more, and the weights decay exponentially into the past.

Q4. With \(\beta = 0.98\), what is the approximate effective window of the EWA?

Roughly \(1/(1-\beta) = 1/0.02 = 50\) observations.

Q5. Why is bias correction needed when computing an EWA?

Because we initialize \(v_0 = 0\). For the first few steps, \(v_t\) is systematically smaller than \(\theta_t\). Dividing by \(1 - \beta^t\) corrects for this. As \(t\) grows, \(\beta^t \to 0\) and the correction has negligible effect.

Q6. Write down the momentum update equations. \[ v_{dW} = \beta v_{dW} + (1-\beta)dW \] \[ v_{db} = \beta v_{db} + (1-\beta)db \] \[ W := W - \alpha v_{dW}, \qquad b := b - \alpha v_{db} \]

\(\beta\) is typically 0.9. The velocity \(v_{dW}\) accumulates past gradients, so consistent directions get amplified and oscillations damp out.

Q7. How does momentum help when training through a flat plateau?

On a plateau, the raw gradient is very small. But momentum accumulates past gradients into a velocity term, so the optimizer keeps moving in the same direction even when the current gradient signal is weak. This lets the optimizer traverse flat regions much more quickly than vanilla gradient descent.

Q8. What is the role of \(\varepsilon\) in RMSprop and Adam?

\(\varepsilon\) is a small constant (e.g. \(10^{-8}\)) added to the denominator to prevent division by zero or by a very small number. It also ensures numerical stability when the accumulator \(S\) happens to be extremely small.

Q9. What is the difference between Momentum and RMSprop?

Momentum accumulates gradients into a velocity term. The update is \(\alpha v_{dW}\), which is a smoothed version of the gradient scaled by a fixed \(\alpha\). RMSprop accumulates squared gradients and divides each update by the square root of this accumulator: the effective learning rate is \(\alpha/\sqrt{S}\). Momentum smooths direction; RMSprop scales the step size per parameter.

Q10. What does Adam combine?

Adam combines:

  • Momentum — via the first moment estimate \(v\) (running average of gradients).
  • RMSprop — via the second moment estimate \(S\) (running average of squared gradients).
  • Bias correction — applied to both \(v\) and \(S\).

Q11. What are Adam's typical default hyperparameters?

\(\beta_1 = 0.9\) (first moment decay), \(\beta_2 = 0.999\) (second moment decay), \(\varepsilon = 10^{-8}\). The learning rate \(\alpha\) needs to be tuned, but the other three work well across many problems.

Q12. Why is Adam often a good default choice for deep learning?

Because it works well "out of the box" across a wide range of problems, combines momentum and adaptive per-parameter scaling, requires little hyperparameter tuning, is memory-efficient, and handles sparse gradients well (e.g. in NLP). The main practical downside is that it uses more memory than momentum alone.

Q13. What is learning rate decay and why is it useful?

Learning rate decay means gradually reducing \(\alpha\) as training proceeds. It is useful because the optimizer oscillates around the minimum with a constant \(\alpha\); decaying \(\alpha\) damps those oscillations and lets the optimizer settle closer to the minimum.

Q14. Give one example of a learning rate decay schedule.

Step decay: reduce \(\alpha\) by a factor of, say, 0.5 every few epochs. Other examples: exponential decay \(\alpha = 0.95^{\text{epoch-num}} \alpha_0\), inverse-time decay \(\alpha = (k/\sqrt{\text{epoch-num}}) \alpha_0\), or manual decay.

Q15. Why are bad local optima usually not a serious concern in deep learning?

Because deep learning problems have very high-dimensional parameter spaces. To be stuck in a bad local minimum, you would need to be unlucky in every direction. In high dimensions, most critical points are saddle points rather than local minima — the gradient is zero but you can still escape by moving in certain directions. The real practical challenge is plateaus (flat regions with tiny gradients).

Q16. How does a saddle point differ from a local minimum?

At a local minimum, the function curves upward in every direction — you cannot reduce the cost by moving anywhere. At a saddle point, the function curves upward in some directions and downward in others — the gradient is zero, but you can still reduce the cost by moving in one of the "downward" directions. Saddle points are far more common in high dimensions.

Q17. What does the "effective window" of an EWA mean, and how does it depend on \(\beta\)?

The effective window is the approximate number of past time steps that significantly contribute to the average. It equals roughly \(1/(1-\beta)\). For \(\beta = 0.9\), the window is about 10 steps. For \(\beta = 0.98\), it is about 50 steps. Larger \(\beta\) means a longer, smoother window.

Q18. Explain the difference between batch gradient descent, mini-batch gradient descent, and stochastic gradient descent.

  • Batch (\(m_{\text{batch}} = m\)): one update per epoch. Smooth cost curve, slow progress.
  • Mini-batch (\(1 < m_{\text{batch}} < m\)): many updates per epoch, each on a small chunk. Moderate noise, fast progress in wall-clock time.
  • Stochastic (\(m_{\text{batch}} = 1\)): one update per example. Very noisy, loses vectorization benefits.

Q19. What is the cost curve shape with mini-batch gradient descent, and why?

The cost curve oscillates up and down, but trends downward overall. It oscillates because each mini-batch is a small sample of the data and its gradient points in a slightly different direction. It trends downward because on average the direction is correct. A smooth debugging curve can be obtained by computing the cost on a fixed set of examples or averaging over mini-batches.

Q20. If your training cost is oscillating wildly, what are two possible causes?

Possible causes:

  • Mini-batch noise: normal when using small mini-batches — see the explanation above. If this is the cause, the curve still trends downward.
  • Learning rate too large: the optimizer may be jumping past the minimum. Try reducing \(\alpha\), or use a learning rate decay schedule.
Other possibilities: bug in the gradient computation, or numerical instability (NaNs).

14. Self-Test

Click each question to reveal the answer. These questions test conceptual understanding rather than memorization.

Q1. You are training a model on a dataset with \(m = 10{,}000\) examples. Your colleague suggests using a mini-batch size of 5,000. Would you agree? What size would you suggest instead, and why?

Answer. A mini-batch size of 5,000 gives only 2 updates per epoch — that is essentially batch gradient descent with extra bookkeeping overhead. It defeats the purpose of mini-batching. A better starting point would be 64, 128, or 256 (a power of 2). These give 40–150+ updates per epoch, much faster convergence in wall-clock time, and still allow vectorization on the CPU/GPU.

Rule of thumb: if the dataset is small (say \(m \leq 2{,}000\)), batch gradient descent is fine. For larger datasets, use mini-batches of 64–512, but make sure the batch fits in memory.

Q2. Explain in your own words why the mini-batch cost curve is noisy, and why this is not a problem.

Answer. Each mini-batch is a small random subset of the training set. The gradient computed from this subset is an estimate of the true gradient — it points in approximately the right direction, but with noise. As you move from one mini-batch to the next, this noise makes the cost go up and down slightly.

This is not a problem because:

  • On average, the gradient estimate is correct, so the cost trends downward over the course of many iterations.
  • The noise can actually help — it lets the optimizer escape small flat regions and saddle points that would stall a batch-gradient-descent optimizer.
  • You can smooth the curve for debugging by computing the cost on a fixed set of examples or averaging over several mini-batches.
Q3. With \(\beta = 0.9\) in an exponentially weighted average, roughly how many previous values contribute meaningfully to the average? Show your reasoning.

Answer. The effective window is roughly \(1/(1-\beta) = 1/0.1 = 10\). Reasoning: the weight given to the value \(k\) steps in the past is \((1-\beta)\beta^k\). Setting this to roughly 1/3 of the initial weight (a common threshold), we solve \(\beta^k = 1/e\), i.e. \(k = -1/\ln(\beta)\). For \(\beta = 0.9\), \(\ln(0.9) \approx -0.105\), so \(k \approx 9.5\), about 10 steps. (More generally, the rule of thumb is \(1/(1-\beta)\) steps for \(\beta\) close to 1.)

Q4. Bias correction in EWA uses \(v_t^{\text{corrected}} = v_t / (1-\beta^t)\). Why does the correction become negligible for large \(t\)? Give a numerical example.

Answer. Because \(\beta^t\) shrinks exponentially toward zero as \(t\) grows. When \(\beta^t\) is negligible compared to 1, the denominator \(1-\beta^t\) is essentially 1, so the correction is a no-op.

Example with \(\beta = 0.98\):

  • At \(t=1\): \(1 - 0.98 = 0.02\), so \(v_1\) is divided by 0.02 — a large correction (50×).
  • At \(t=10\): \(1 - 0.98^{10} \approx 1 - 0.817 = 0.183\), still a significant correction.
  • At \(t=50\): \(1 - 0.98^{50} \approx 0.636\).
  • At \(t=200\): \(1 - 0.98^{200} \approx 1\). The correction is negligible.

So bias correction matters mainly for the first tens of iterations.

Q5. Suppose you plot the cost and it decreases monotonically for 100 epochs, then starts oscillating with an amplitude that never shrinks. What is likely happening, and what would you try?

Answer. This is a classic sign that the learning rate is too large for the region of the cost surface you have reached. The optimizer is "overshooting" the minimum on every step, so it never settles. Solutions:

  • Use a learning rate decay schedule, so \(\alpha\) shrinks over time and the oscillations damp out.
  • Reduce \(\alpha\) manually — perhaps halve it and continue training.
  • Use an optimizer with adaptive step sizes (RMSprop or Adam), which can be more robust to a suboptimal \(\alpha\).
  • Check that the oscillation is not just mini-batch noise. If you use a small mini-batch size, some oscillation is expected; but a steady amplitude over many epochs suggests an issue with \(\alpha\), not just noise.
Q6. Explain the difference between momentum and RMSprop in a way a beginner could understand, then explain how Adam combines them.

Answer.

Momentum — analogy: Imagine pushing a ball down a bumpy slope. Each push is a little different, but because the ball has inertia, it keeps moving in the general downhill direction. Past gradients accumulate into a "velocity" that smooths out the direction of motion.

RMSprop — analogy: Imagine each parameter has its own automatic throttle. If a parameter's gradients have been large, its throttle is reduced — the optimizer takes smaller steps there. If the gradients have been small, the throttle is opened — larger steps. This equalizes progress across parameters.

Adam = Momentum + RMSprop + bias correction. It computes a running average of the gradients (momentum, \(v\)) and a running average of squared gradients (RMSprop, \(S\)), corrects both for the initial bias, then uses \(\alpha \cdot v^{\text{corrected}} / (\sqrt{S^{\text{corrected}}} + \varepsilon)\) as the update. The numerator provides momentum-like smoothing; the denominator provides RMSprop-like adaptive scaling.

Q7. Is it worth spending time tuning \(\beta_1\) and \(\beta_2\) in Adam, or are the defaults fine? Justify your answer.

Answer. In most cases, the defaults \(\beta_1 = 0.9\), \(\beta_2 = 0.999\), and \(\varepsilon = 10^{-8}\) are fine and rarely need tuning. Adam's design is deliberately robust to these choices, and there are many other hyperparameters more worth your time (architecture, learning rate \(\alpha\), mini-batch size, regularization).

There are a few exceptions:

  • If you are training on tasks with very sparse gradients or extremely long sequences, tuning \(\beta_2\) slightly may help.
  • Some problems benefit from using a slightly larger \(\varepsilon\) (e.g. \(10^{-6}\)) for numerical stability.
  • The learning rate \(\alpha\) is the hyperparameter you should almost always tune first.

General rule: start with defaults, tune \(\alpha\), and only consider tweaking \(\beta_1\), \(\beta_2\), \(\varepsilon\) if you have reason to believe the defaults are not appropriate.

Q8. You are training a very deep network with plain gradient descent. The cost decreases for a while, then plateaus at a value well above the minimum, even though training has not converged. You check the gradient and it is very small but not zero. What is happening, and how would momentum or Adam help?

Answer. The optimizer is likely stuck on a plateau — a flat region of the cost surface where the gradient is very small. Vanilla gradient descent makes tiny steps because the step size is proportional to the gradient, so progress effectively stops.

How momentum helps: it accumulates past gradients into a velocity term. Even if the current gradient is small, the accumulated velocity can carry the optimizer across the flat region. This effectively "coasts" through plateaus.

How Adam helps: Adam has the same momentum property (via its first moment \(v\)), and also adaptively scales updates by the second moment \(S\). On a plateau, \(S\) is small (because the recent gradients are small), so the effective learning rate \(\alpha / (\sqrt{S} + \varepsilon)\) becomes larger, which helps push the optimizer forward.

This is one of the main reasons Adam and other adaptive optimizers train deep networks much faster than plain gradient descent.

Q9. Why is the following statement misleading: "Deep learning suffers from getting stuck in bad local minima, so we need smart optimizers to escape them."

Answer. The statement reflects an older, low-dimensional intuition that does not accurately describe modern deep learning. In high-dimensional parameter spaces:

  • Bad local minima are rare. For the optimizer to be trapped in a bad local minimum, the cost surface must curve upward in every direction at that point. In a space with millions of dimensions, this is very unlikely — the vast majority of critical points are saddle points.
  • Saddle points dominate. At a saddle point, the gradient is zero, but the surface curves downward in at least one direction. Optimizers can escape these by moving in that direction. Momentum and Adam help here, but the issue is escaping saddles, not local minima.
  • Plateaus are the bigger problem. Long flat regions with tiny gradients slow learning much more than local minima do.

A more accurate statement: "Deep learning can suffer from saddle points and plateaus that slow down optimization. Momentum-based and adaptive optimizers help traverse these regions efficiently."

Q10. Suppose you have two models with identical architectures but different optimizers (Momentum vs Adam). You run both for the same number of epochs on the same data. Which is likely to converge faster, and why? Are there any caveats?

Answer. Adam is likely to converge faster for most problems, because it combines momentum with per-parameter adaptive scaling and bias correction. On many benchmarks, Adam reaches a given training loss in fewer epochs than momentum.

Caveats:

  • The advantage depends on the problem. On some problems, carefully tuned momentum can match or beat Adam. A well-tuned SGD with momentum is still competitive on computer vision tasks, where it can generalize slightly better than Adam.
  • Adam's per-parameter step sizes can sometimes lead to slightly worse generalization on certain vision benchmarks, even if training loss is lower. There is an active debate about this in the literature.
  • Adam uses more memory than plain momentum (it stores two accumulators per parameter: \(v\) and \(S\), instead of just \(v\)).
  • Both optimizers require a decent learning rate. Adam is more forgiving to a suboptimal \(\alpha\), but \(\alpha\) still matters a lot.

General practical advice: start with Adam, and switch to momentum-tuned SGD if you observe worse generalization on validation data or need to squeeze out the last percentage points.
