Week 3 — Object Detection & Semantic Segmentation

Course 4 (Convolutional Neural Networks) · Deep Learning Specialization · Andrew Ng

🔵 What This Week Is About

Up to now we've answered "what is in this image?" This week we answer "where is it, and how many?" — the task of object detection. We start with classification + localization (one object), add landmark detection, then build up the full object detection pipeline: sliding windows, its convolutional implementation, bounding-box regression (YOLO), IoU, non-max suppression, and anchor boxes. We finish with region proposals (R-CNN family) and semantic segmentation with U-Net, where every pixel gets a class label.

🟢 Big-Picture Progression
  • Image classification → single label ("cat").
  • Classification + localization → label + one bounding box.
  • Landmark detection → coordinates of specific features (eyes, nose, joints).
  • Object detection → multiple objects, each with a label + box.
  • Semantic segmentation → per-pixel class labels (e.g., road / car / building).

2. Classification with Localization

Given a picture with a single object (e.g., one car), produce both the class label and the coordinates of a bounding box that surrounds the object.

2.1 Bounding box parameters

A bounding box is described by four numbers:

  • \(b_x, b_y\) — the \((x, y)\) coordinates of the centre of the box.
  • \(b_h\) — the height of the box.
  • \(b_w\) — the width of the box.
Figure 2.1 — Bounding box notation. \(b_x, b_y\) are the box centre coordinates; \(b_w, b_h\) are its width and height. All values are usually normalised by the image dimensions.
🟡 Important — Normalised Coordinates

In practice, \(b_x, b_y, b_w, b_h\) are all normalised to the range \([0,1]\). So \(b_x = 0.5\) means the box centre is at the horizontal midpoint of the image. This keeps the network's outputs bounded and makes training easier.

2.2 The network architecture

Start with a standard CNN that outputs a feature vector. Then attach multiple heads:

  • Class head (softmax over classes + "background") → predicts the class.
  • Box head (4 linear outputs) → predicts \(b_x, b_y, b_h, b_w\).
Figure 2.2 — A classification-with-localization network has a shared "backbone" (ConvNet) and two output heads: one for the class, one for the bounding box coordinates.

3. Defining the Target Label \(y\)

To train this network, we need to define what the ground-truth label \(y\) looks like for each image.

3.1 The class list

Example from the lecture — four categories (the "background" class handles images with no object):

  1. Pedestrian
  2. Car
  3. Motorcycle
  4. Background

3.2 The label vector

Each training example's target is an 8-dimensional vector (assuming 3 object classes):

$$ y = \begin{bmatrix} p_c \\ b_x \\ b_y \\ b_h \\ b_w \\ c_1 \\ c_2 \\ c_3 \end{bmatrix} $$
SymbolMeaning
\(p_c\)Probability that any object is present (1 = object, 0 = background).
\(b_x, b_y, b_h, b_w\)Bounding-box coordinates (only meaningful if \(p_c=1\)).
\(c_1, c_2, c_3\)One-hot class labels (e.g., [1,0,0] = pedestrian; [0,1,0] = car; …).

3.3 Two cases: object vs background

Figure 3.1 — Two training labels. When an object is present, \(p_c = 1\) and the box + class values are meaningful. When there is no object (\(p_c = 0\)), the remaining entries can be set to anything — we "don't care" about them.

3.4 The loss function

Because the network has multiple outputs, we combine several loss terms with a switch based on \(p_c\):

$$ \mathcal{L}(\hat{y}, y) = \begin{cases} (\hat{y}_1 - y_1)^2 + \sum_{i=2}^{8}(\hat{y}_i - y_i)^2 & \text{if } y_1 = 1 \text{ (object present)} \\[6pt] (\hat{y}_1 - y_1)^2 & \text{if } y_1 = 0 \text{ (background)} \end{cases} $$
🟢 Intuition — Why the Switch?

When \(p_c=1\), we need to train the box coordinates and the class probabilities — so we sum squared errors across all 8 outputs. When \(p_c=0\), there is no object to localise or classify, so we only train \(p_c\) itself. Training the "don't care" entries on a background image would give contradictory gradients.

📎 Additional Context — Modern Practice

Andrew's lecture uses squared error for simplicity. In practice, object detectors use:

  • Log loss for \(p_c\) (binary classification) and for class probabilities (softmax cross-entropy).
  • L1 / smooth-L1 losses for the box coordinates \(b_x, b_y, b_h, b_w\).
  • IoU-based losses (e.g., GIoU, DIoU) in the latest detectors.

The switch-on-\(p_c\) structure is the key idea and persists in all of them.

4. Landmark Detection

Instead of drawing a box around the whole object, we might want the network to output the coordinates of specific features — the corners of the eyes, the tip of the nose, joints of the body, etc.

🔵 Definition — Landmark Detection

Landmark detection is a regression task where the network outputs the \((x, y)\) coordinates of a fixed set of landmarks on an object. Each landmark is two numbers, so \(k\) landmarks → \(2k\) outputs.

Figure 4.1 — Landmark detection on a face. Each red dot is a landmark whose \((x,y)\) coordinates the network learns to output. The training set must be consistently annotated — landmark 1 must always be the same feature (e.g., left eye corner).
🟡 Important — Landmark Consistency

The training labels must be consistent across examples. Landmark 1 must always denote the same point (e.g., the left corner of the left eye). If annotation order varies between images, the network can't learn.

🔴 Warning — More Landmarks ≠ Better

Landmark detection requires a large, consistently-annotated dataset. It's not a general-purpose technique — pick a fixed set of landmarks that is meaningful for your task (e.g., 64 face points, or 17 joints for human pose).

5. Object Detection

Localization gave us one box per image. Real applications need many objects located at once.

🔵 Definition — Object Detection

Object detection identifies and localises multiple objects in an image. Output is a variable-length list of (class, bounding box) pairs.

5.1 Building a training set for detection

You can reuse a classifier trained on cropped images and slide it across an image. This is the core idea behind sliding windows.

Figure 5.1 — Build a training set of tightly-cropped car images (label 1) and non-car images (label 0). A classifier trained on this can then be slid across a larger image to find cars.

6. Sliding Windows Detection

🔵 Definition — Sliding Window Detection

Slide a fixed-size window across the image at multiple positions and scales. At each position, crop the patch inside the window and pass it through the classifier. If the classifier says "car", record that window as a detection.

🟢 Intuition — A Flashlight Scanning the Image

Imagine a rectangular flashlight of a fixed size that you sweep left-to-right, top-to-bottom, across the whole image. Then repeat with a bigger flashlight (to catch bigger objects), then an even bigger one. At each sweep position you ask, "Does this crop contain an object?"

6.1 Algorithm

  1. Pick a window size (e.g., 64×64).
  2. Slide the window across the image with a fixed stride (e.g., 4 pixels).
  3. At each position, crop the patch and run the classifier.
  4. If the classifier outputs "object", save the window position as a detection.
  5. Repeat with larger window sizes to catch objects of different scales.
Figure 6.1 — Sliding window detection. At every position and size, crop a patch and classify it.
🔴 Warning — Computationally Expensive

Sliding windows with a small stride and many scales means thousands of forward passes through the CNN per image. This is far too slow for real-time detection. The next section shows the fix.

7. Convolutional Implementation of Sliding Windows

The key observation is that sliding windows can be implemented as a single convolutional forward pass, replacing the naive approach of running the classifier many times.

7.1 Turning FC layers into convolutions

Consider a classifier that takes \(14\times14\times3\) input, applies conv + pool, then FC + FC + softmax. The FC layers can be replaced with convolutions of matching size:

Figure 7.1 — Replacing FC layers by their equivalent conv layers gives a fully convolutional network. This enables the sliding-window trick below.

7.2 The trick — one forward pass, many windows

Instead of cropping patches and running the network many times, feed the whole image through the fully convolutional network once. The output is a grid where each cell is the classification result for one sliding-window position.

Figure 7.2 — Sliding windows as a single conv pass. The big \(16\times16\times3\) input produces a \(2\times2\times4\) output — each of the four output cells is the classification for one 14×14 crop of the input.
🟡 Important — Why This Is a Huge Speedup

Naive sliding windows: run the classifier ~N times (N = number of positions × scales). Conv implementation: run the network once. The number of positions is baked into the spatial dimensions of the output. This is what makes real-time detection possible.

🔴 Warning — Coarse Localisation

Because the conv implementation outputs one prediction per window position (not per pixel), the localisation can be coarse. The next section shows how to get much more accurate boxes.

8. Bounding Box Predictions — YOLO

Redmon et al., 2015. YOLO = "You Only Look Once". Real-time object detection.

8.1 The grid idea

🔵 Definition — YOLO Grid

Divide the input image into an \(S \times S\) grid (e.g., \(3\times3\), or \(19\times19\) in the real paper). For each grid cell, ask the network to predict a label vector \(y\) describing the object whose centre falls inside that cell.

Figure 8.1 — YOLO partitions the image into a grid. Each cell predicts an 8-dimensional label describing any object whose centre lies in that cell. In the actual YOLO paper, the grid is \(19\times19\) → output volume \(19\times19\times 8\).

8.2 Target output

For a \(3\times 3\) grid with 3 classes, the target volume is \(3\times 3\times 8\). Cells with no object get \(p_c = 0\); cells containing an object's centre get \(p_c = 1\) and the appropriate box + class entries.

🟡 Important — Object Assigned to Cell with Its Centre

An object is assigned to the grid cell containing its centre. If the object spans multiple cells, it still belongs to only one (the centre cell) — this avoids ambiguity during training.

8.3 How the network is trained

Build a ConvNet whose output has shape \(S\times S\times 8\) (or \(S\times S\times(5+K)\) for \(K\) classes). Train with the switch-loss from §3 — the network learns \(p_c\), the box coordinates, and the class probabilities simultaneously.

8.4 Inference — turning the grid into boxes

At test time, run the CNN once to get the \(S\times S\times 8\) output, then post-process:

  1. For each grid cell, read off \(p_c\) and (if \(p_c\) is above a threshold) the box + class.
  2. Many cells might produce overlapping boxes for the same object.
  3. Apply non-max suppression (§10) to keep only the best box per object.
🟡 Important — What YOLO Solves
  • Faster than sliding windows — one forward pass.
  • More accurate boxes — regression on box coordinates.
  • Capable of detecting multiple objects — each grid cell is independent.

9. Intersection over Union (IoU)

🔵 Definition — Intersection over Union

IoU measures how much two bounding boxes overlap. It is the ratio of the area of their intersection to the area of their union.

$$ \text{IoU} = \frac{\text{Area of overlap}}{\text{Area of union}} $$
Figure 9.1 — IoU between a ground-truth box and a predicted box. IoU ≥ 0.5 is the conventional threshold for calling a detection "correct."
🟢 Intuition — Overlap Quality Score

If the two boxes are identical, IoU = 1. If they don't touch at all, IoU = 0. Anything in between measures how well they overlap — a simple, robust way to say "did we get the box approximately right?"

🟡 Important — Threshold Choice

IoU ≥ 0.5 is a common convention, but stricter tasks use 0.75 or higher. The exact threshold is a hyperparameter you choose based on the application.

10. Non-Max Suppression (NMS)

After YOLO produces many box predictions, many of them overlap heavily for the same object. NMS cleans them up.

🔵 Definition — Non-Max Suppression

NMS is a post-processing step that removes redundant, overlapping detections and keeps only the highest-confidence one for each object.

🟢 Intuition — Elections

Imagine several overlapping boxes each saying "I found a car!" NMS picks the one with the highest confidence, declares it the winner, and discards all other boxes that heavily overlap with it. Then it repeats with the remaining boxes until no overlaps remain.

10.1 Algorithm

  1. Discard low-confidence boxes: remove all boxes with \(p_c \le 0.6\) (or some threshold).
  2. While boxes remain:
    1. Pick the box with the highest \(p_c\). Output it as a prediction.
    2. Discard any remaining box that has IoU ≥ 0.5 with the box just picked.
  3. Repeat for each class separately (pedestrian, car, motorcycle, …).
Figure 10.1 — NMS in action. Starting from many overlapping predictions, NMS keeps the highest-confidence box and discards nearby ones with high IoU.
🔴 Warning — NMS Is Per Class

If you have multiple classes, run NMS separately for each class. Otherwise a "car" box and a "pedestrian" box that happen to overlap would suppress each other — which is wrong, since they refer to different objects.

11. Anchor Boxes

YOLO's basic grid has a problem: what if two objects fall into the same grid cell? Or what if the same cell contains both a tall pedestrian and a wide car? Anchor boxes solve both issues.

🔵 Definition — Anchor Boxes

Anchor boxes are pre-defined box shapes (e.g., one tall, one wide) that each grid cell predicts against. Instead of outputting one object per cell, each cell outputs one object per anchor box.

Figure 11.1 — Anchor boxes. With two anchors, each cell outputs two object predictions (one per anchor). A tall pedestrian uses the tall anchor; a wide car uses the wide anchor.

11.1 How training labels are assigned

  1. Each object is assigned to the grid cell containing its centre.
  2. Within that cell, the object is assigned to the anchor box with the highest IoU with the object's shape.
  3. The other anchor's entries are set to \(p_c = 0\) (no object).

11.2 How the output shape changes

$$ S \times S \times (n_{\text{anchors}} \times 8) $$

For a \(3\times 3\) grid with 2 anchors and 3 classes: \(3 \times 3 \times 16\).

🟡 Important — When to Use Anchors
  • Two objects in the same cell → anchors let the cell represent both.
  • Objects of very different shapes → anchors specialise by shape, improving box regression.
  • Typically 5–10 anchors are used, chosen via k-means clustering of dataset box shapes.
🔴 Warning — Limitations of Anchors
  • Two objects of the same shape in the same cell still can't be represented (rare in practice).
  • You must choose anchor shapes for your dataset — generic anchors work poorly on unusual data.

12. YOLO in Full — Putting It Together

12.1 Training

  1. Divide each training image into an \(S \times S\) grid (e.g., \(3\times 3\), or \(19\times 19\)).
  2. For each cell, build the target \(y\) vector (\(8 \times n_{\text{anchors}}\) numbers).
  3. Run a ConvNet on the input image. Its output has shape \(S \times S \times (8 \times n_{\text{anchors}})\).
  4. Train with the switch-loss (§3) on \(p_c\), the box coordinates, and the class probabilities.
Figure 12.1 — YOLO training. The network outputs an \(S\times S\times (8\cdot n_{\text{anchors}})\) tensor; the loss compares it against the target grid built from the ground-truth annotations.

12.2 Inference

  1. Run the network once → get \(S \times S \times 16\) output.
  2. For each grid cell and each anchor, read off the predicted \(p_c\) and box.
  3. Discard low-\(p_c\) predictions.
  4. For each class, run non-max suppression to get the final boxes.
🟡 Important — Why YOLO Is Fast and Popular
  • Single forward pass — no per-region classification.
  • Regression on box coordinates gives accurate localisation.
  • Handles multiple objects naturally via the grid.
  • Real-time capable (with an efficient backbone).

13. Region Proposals — The R-CNN Family

An alternative to sliding windows is to first propose a small set of candidate regions, then classify each one.

🔵 Definition — Region Proposals

Region proposals are candidate bounding boxes that are likely to contain objects, generated by a separate algorithm (e.g., selective search) before the CNN runs. This avoids processing every possible window.

13.1 Three generations

MethodIdeaSpeed
R-CNN (Girshick et al., 2014) Use selective search to propose ~2000 regions. Classify each region with a CNN one at a time. Output label + refined box. Very slow (2000 separate CNN passes per image).
Fast R-CNN Run the CNN once on the full image. Use RoI pooling to extract features for each proposed region from the shared feature map. Classify + regress boxes from those features. Much faster than R-CNN.
Faster R-CNN Replace the hand-crafted region proposal algorithm with a Region Proposal Network (RPN) — a small CNN that learns to propose regions. Fastest of the three; often real-time capable.
🟡 Important — R-CNN vs YOLO
  • R-CNN family: two-stage (propose then classify). Higher accuracy, slower.
  • YOLO: one-stage (predict everything at once). Faster, slightly lower accuracy historically (modern YOLO versions have closed the gap).
📎 Additional Context — Optional Material

Andrew marks this section as optional. You'll be well-served knowing the three names and the high-level distinction, without needing to derive the details.

14. Semantic Segmentation vs Object Detection

🔵 Definition — Semantic Segmentation

Semantic segmentation assigns a class label to every pixel in the image. Instead of a list of bounding boxes, the output is a segmentation map with the same spatial size as the input.

Figure 14.1 — Detection gives bounding boxes; semantic segmentation labels every pixel. The output has the same spatial size as the input.

14.1 Per-pixel class labels

Each pixel in the image gets a class label. Classes might be, for example: {1: car, 2: building, 3: road}. The network's output is a "segmentation map" with the same height and width as the input.

Figure 14.2 — A segmentation map stores a class label at each pixel, matching the input's spatial dimensions.
🟢 Why Semantic Segmentation?
  • Medical imaging — tumour boundaries, organ segmentation.
  • Autonomous driving — road, car, pedestrian, sidewalk pixels.
  • Satellite imagery — land-use classification per pixel.

15. Transpose Convolution

Segmentation requires upsampling: the network first downsamples the image (via pooling/strided convs) to capture what is present, then must upsample back to full resolution to say where each class appears.

🔵 Definition — Transpose Convolution

Transpose convolution (also called deconvolution or fractionally-strided convolution) is a learnable upsampling operation. It takes a small input and produces a larger output — the opposite of a normal convolution.

🟢 Intuition — Reversing the Flow

A normal convolution maps a large input to a small output. A transpose convolution maps a small input to a large output by spreading each input value into a small patch and summing overlapping contributions.

Figure 15.1 — Normal convolution shrinks spatial size. Transpose convolution grows it. The filter is still learned — the operation is just "inverse-shaped."

15.1 How the numbers work

Take a \(2 \times 2\) input and a \(3 \times 3\) filter, with padding \(p=1\) and stride \(s=2\). Transpose convolution produces a \(4 \times 4\) output:

Figure 15.2 — Transpose conv takes a small input and produces a larger output. Parameters: filter \(f=3\), padding \(p=1\), stride \(s=2\). The numbers are illustrative.
🟡 Important — What to Remember
  • Transpose conv is a learned upsampling operation — the filter values are trained.
  • It's the reverse of a normal conv in terms of shape, though not a mathematical inverse.
  • Used in segmentation, generative models, and any architecture that needs to expand spatial dimensions.

16. U-Net Architecture

Ronneberger et al., 2015. U-Net is a fully convolutional network designed for biomedical image segmentation. Its shape — down then up — is what gives it the name (the "U").

16.1 The overall architecture

Figure 16.1 — U-Net. The encoder (left) down­samples via conv + pooling. The decoder (right) upsamples via transpose conv. Skip connections (purple arcs) copy high-resolution features directly from encoder to decoder so precise localisation is not lost.

16.2 Why skip connections are essential

🟢 Intuition

As the encoder downsamples, it captures semantic information (e.g., "this region is a car") but loses spatial precision. The decoder needs to recover where the car's edges are. Skip connections feed the decoder the high-resolution feature maps from the encoder, so it can combine "what" (from deep features) with "where" (from shallow features).

🟡 Important — U-Net Ingredients
  • Encoder: stack of conv + maxpool (downsampling).
  • Bottleneck: most compressed representation.
  • Decoder: stack of transpose conv + conv (upsampling).
  • Skip connections: concatenate encoder features onto the corresponding decoder layer.
  • Output: \(H \times W \times n_{\text{classes}}\) — per-pixel logits.
🔴 Warning — Skip Connections Here Are Not ResNet's

U-Net's skip connections concatenate encoder feature maps onto decoder feature maps (increasing channel count). ResNet's skip connections add the input to the block output (channel count unchanged). Different operations, similar motivation: preserve gradient flow and information.

17. Weekly Summary

  • Classification + localization: predict class + one bounding box. Output vector \(y = [p_c, b_x, b_y, b_h, b_w, c_1, \dots, c_K]\).
  • Loss switch: if \(p_c = 1\), train everything; if \(p_c = 0\), only train \(p_c\).
  • Landmark detection: output coordinates of fixed features (face, pose). Consistency across examples is essential.
  • Sliding windows: naive approach is slow. Conv implementation computes all window positions in one forward pass.
  • YOLO: divide image into a grid, each cell predicts an \(8\)-number label. Fast, one-shot detection.
  • IoU: overlap quality measure. IoU ≥ 0.5 = "correct" detection.
  • NMS: discard redundant overlapping boxes; keep highest-confidence per object per class.
  • Anchor boxes: allow multiple objects per grid cell and specialisation by shape.
  • R-CNN family: propose regions then classify (R-CNN, Fast R-CNN, Faster R-CNN).
  • Semantic segmentation: per-pixel class labels; output same size as input.
  • Transpose convolution: learned upsampling operation.
  • U-Net: encoder-decoder with skip connections for high-quality segmentation.

18. Important Equations

EquationMeaning
\(y = [p_c, b_x, b_y, b_h, b_w, c_1, \dots, c_K]^T\) Target label for classification + localization. \(p_c\) = objectness, \(b_*\) = box coords, \(c_i\) = class one-hot.
\(\mathcal{L}(\hat{y}, y) = \sum_i (\hat{y}_i - y_i)^2\) when \(y_1=1\) Loss when an object is present — all 8 outputs supervised.
\(\mathcal{L}(\hat{y}, y) = (\hat{y}_1 - y_1)^2\) when \(y_1=0\) Loss when no object — only \(p_c\) supervised.
\(\text{IoU} = \dfrac{\text{Area}(\text{Box}_1 \cap \text{Box}_2)}{\text{Area}(\text{Box}_1 \cup \text{Box}_2)}\) Overlap measure between two boxes. Correct if ≥ 0.5 (convention).
\(S \times S \times (8 \times n_{\text{anchors}})\) Output shape of a YOLO network with \(S\times S\) grid and \(n_{\text{anchors}}\) anchors.
\(n_H^{[out]} = \lfloor (n_H^{[in]} + 2p - f)/s \rfloor + 1\) Conv output size (recall from Week 1).
\(n_H^{[out]} = (n_H^{[in]} - 1)\cdot s - 2p + f\) Transpose conv output size (upsampling formula).

19. Common Confusions

Often confusedCorrect distinction
Classification vs localization vs detection Classification = label only. Localization = label + one box. Detection = labels + multiple boxes.
\(p_c\) vs class probabilities \(c_i\) \(p_c\) = "is there any object?" (binary). \(c_i\) = "which class?" (one-hot). Both are needed.
Landmark detection vs object detection Landmarks = coordinates of specific features (eyes, joints). Object detection = bounding boxes around whole objects.
Sliding windows vs YOLO Sliding windows explicitly enumerate positions (slow). YOLO uses a fixed grid, one prediction per cell (fast).
IoU vs accuracy IoU measures box overlap. Accuracy measures class correctness. Both matter for detection quality.
NMS threshold vs confidence threshold Confidence threshold discards low-\(p_c\) predictions. NMS threshold discards boxes overlapping the chosen one.
Anchor box vs bounding box An anchor box is a template shape (fixed). A bounding box is a predicted box that the network regresses, relative to the anchor.
Object detection vs semantic segmentation Detection = bounding boxes. Segmentation = per-pixel class labels (no boxes).
Transpose conv vs deconvolution "Deconvolution" is a loose name for transpose conv — it is NOT a mathematical inverse of convolution. Prefer the term "transpose convolution."
ResNet skip vs U-Net skip ResNet adds (element-wise). U-Net concatenates (channels stack). Different purposes.

20. Review Questions

Q1. What is the difference between classification with localization and object detection?
Classification with localization predicts one object's class and its bounding box. Object detection predicts multiple objects, each with its own class and bounding box. Detection has a variable-length output.
Q2. Write the target label vector \(y\) for classification with localization and explain each entry.
$$y = [p_c, b_x, b_y, b_h, b_w, c_1, \dots, c_K]^T$$ \(p_c\) — 1 if an object is present, 0 otherwise. \(b_x, b_y\) — box centre coordinates (normalised). \(b_h, b_w\) — box height/width (normalised). \(c_1, \dots, c_K\) — one-hot class probabilities.
Q3. Why does the loss switch on \(p_c\)?
When \(p_c=0\) (no object), the box and class values are undefined — the annotation has no meaning. We "don't care" about those entries and shouldn't backpropagate through them. The switch ensures the loss only trains the parts of \(y\) that actually have ground truth.
Q4. What is landmark detection, and what is a common failure mode?
Landmark detection outputs \((x, y)\) coordinates of a fixed set of features (e.g., 64 face points). Common failure: if annotations are inconsistent across training examples (e.g., "landmark 1" means different things in different images), the network cannot learn.
Q5. Why is naive sliding-window detection slow?
It requires one forward pass through the classifier for each window position (× each scale). A 1000×1000 image with stride 4 and multiple scales could need tens of thousands of forward passes.
Q6. How does the convolutional implementation speed up sliding windows?
By replacing fully connected layers with equivalent conv layers (e.g., a \(5\times5\times16\) FC becomes a \(5\times5\) conv, and \(1\times1\) FCs become \(1\times1\) convs). Then feed the whole image through once — the output is a grid where each cell represents one window position. One forward pass instead of thousands.
Q7. Describe YOLO's grid approach in one sentence.
Divide the image into an \(S\times S\) grid; each cell predicts an 8-dimensional label for the object whose centre lies inside that cell (or predicts \(p_c=0\) if there is no object).
Q8. What is IoU and why do we use it?
IoU = (area of intersection) / (area of union) between two boxes. It's a scale-invariant measure of how much two boxes overlap. It lets us quantitatively say "the predicted box is approximately right" — IoU ≥ 0.5 is the conventional correctness threshold.
Q9. Describe the NMS algorithm.
(1) Discard all boxes with \(p_c\) below a threshold. (2) While boxes remain: pick the one with the highest \(p_c\), output it, discard any remaining box with IoU ≥ 0.5 with the picked one. Repeat. Do this per class.
Q10. Why does YOLO use anchor boxes?
Two reasons: (1) a single grid cell may contain two objects (e.g., pedestrian and car) — anchor boxes give one prediction slot per object. (2) objects of different shapes (tall vs wide) are better modelled by shape-specific anchors, improving box regression.
Q11. How do you assign a ground-truth object to a grid cell + anchor box during training?
Find the grid cell containing the object's centre. Within that cell, choose the anchor box whose shape has the highest IoU with the object's ground-truth box. Assign the object to that (cell, anchor) slot. Set \(p_c=1\) there and \(p_c=0\) for the other anchors in the same cell.
Q12. What is the difference between R-CNN, Fast R-CNN, and Faster R-CNN?
R-CNN: propose ~2000 regions with selective search, classify each with a CNN (slow). Fast R-CNN: run CNN once on the full image, use RoI pooling to extract features from each proposed region (much faster). Faster R-CNN: replace selective search with a learned Region Proposal Network (fastest).
Q13. What is the difference between object detection and semantic segmentation?
Object detection outputs a list of bounding boxes (each with a class label). Semantic segmentation outputs a per-pixel class label map with the same spatial size as the input — no boxes involved.
Q14. What is transpose convolution, and how does it differ from a normal convolution?
Transpose convolution is a learned upsampling operation. A normal convolution maps a large input to a small output (downsampling). Transpose convolution maps a small input to a large output (upsampling), by spreading each input value into a small patch and summing overlaps.
Q15. Why does U-Net use skip connections?
The encoder downsamples and captures "what" (semantic content) but loses fine spatial detail. The decoder upsamples and needs to recover "where." Skip connections copy high-resolution features from encoder to decoder, letting the decoder combine semantic depth with spatial precision.
Q16. Compute the IoU given: two boxes, one with area 100, one with area 120, and their intersection is 60.
Union = 100 + 120 − 60 = 160. IoU = 60 / 160 = 0.375. Below 0.5, so this would be considered an incorrect detection by the conventional threshold.
Q17. A YOLO network uses a \(19\times 19\) grid, 5 anchor boxes, and 20 classes. What is the output shape?
Each cell-anchor predicts \(5 + K = 5 + 20 = 25\) values? No — for YOLO v1 style with the vector \([p_c, b_x, b_y, b_h, b_w, c_1,\dots,c_K]\) that's \(5 + K\) values. With 5 anchors per cell: \(19 \times 19 \times (5 \times (5+20)) = 19 \times 19 \times 125\). (For the simpler 3-class example in the lectures, it's \(19\times 19\times(5\times 8) = 19\times19\times 40\).)
Q18. Why is \(p_c\) needed separately from the class probabilities?
Because "there is no object" is different from "the object is class X." Without \(p_c\), a cell with no object would still be forced to pick some class with high probability. \(p_c\) lets the network say "nothing here."
Q19. Why is NMS applied separately per class?
Because a pedestrian box and a car box can overlap heavily without being duplicates of each other. NMS should only suppress boxes that refer to the same object. Running it per class avoids suppressing a valid detection just because it overlaps with a detection of another class.
Q20. Name two practical applications of semantic segmentation and why it helps in each.
(1) Medical imaging — segmenting tumours or organs on CT/MRI gives precise shape and boundary information, which pixel-level labels preserve better than bounding boxes. (2) Autonomous driving — knowing exactly which pixels are road vs sidewalk vs obstacle lets the planner decide drivable areas precisely.

21. Self‑Test

Easy

1. Which task requires multiple bounding boxes?
Object detection.
2. What does \(p_c = 0\) mean in the label vector?
There is no object in this cell (background only).
3. What does IoU ≥ 0.5 signify?
The predicted box overlaps sufficiently with the ground truth to count as "correct" (convention).
4. What does NMS stand for, and what does it do?
Non-Max Suppression. It removes redundant overlapping detections, keeping only the highest-confidence one per object per class.
5. In one sentence, what is transpose convolution?
A learned upsampling operation that maps a small input to a larger output, used in segmentation and generative models.

Medium

6. Why is conv implementation of sliding windows much faster than naive sliding windows?
Naive sliding windows run the classifier for every window position. The conv implementation feeds the entire image once through a fully convolutional network, producing all window results at once. It reuses the convolution over the overlapping regions — huge computational savings.
7. Explain how anchor boxes handle two objects in the same grid cell.
Each anchor box provides its own set of output predictions (including \(p_c\)). So the cell can output, e.g., \(p_c=1\) for anchor 1 (the tall pedestrian) and \(p_c=1\) for anchor 2 (the wide car), with separate box and class predictions for each.
8. A YOLO prediction for a cell has \(p_c=0.9\), and the box overlaps with a neighbouring cell's \(p_c=0.95\) box with IoU=0.7. What does NMS do?
NMS picks the higher-confidence box (0.95) as the winner, then discards the 0.9 box because its IoU with the winner is 0.7 ≥ 0.5 (assuming the standard threshold).
9. What is the output shape of a YOLO network with a \(13\times 13\) grid, 3 anchors, and 10 classes?
Each anchor-cell predicts \([p_c, b_x, b_y, b_h, b_w, c_1, \dots, c_{10}]\) = \(5 + 10 = 15\) numbers. With 3 anchors: \(13 \times 13 \times (3 \times 15) = 13 \times 13 \times 45\).
10. Why do we need NMS at all? Isn't one prediction per grid cell enough?
Multiple grid cells (and multiple anchors) can predict boxes around the same object — the object's centre might be close to a cell boundary, so neighbouring cells also fire. NMS resolves these duplicates.
11. Why does U-Net's decoder use skip connections rather than just transpose convolutions?
Because pure transpose conv can recover spatial size but not the exact high-frequency detail lost during downsampling. Skip connections pass those details directly from the encoder at matching resolutions, yielding much sharper segmentation boundaries.

Hard

12. Derive how many parameters a YOLO head has for a \(3\times 3\) grid, 2 anchors, 3 classes — ignoring the backbone.
The head needs to produce \(3 \times 3 \times 16 = 144\) output values. If the last layer is a \(1\times 1\) conv from \(C_{\text{in}}\) channels to \(144\) channels with no bias, that's \(C_{\text{in}} \times 144\) parameters. If \(C_{\text{in}} = 512\), then ~73,728 parameters for just that final layer. (Plus any bias terms — typically 144 biases.)
13. In YOLO, why might two objects in the same cell with the same anchor shape be undetectable?
Because each (cell, anchor) pair provides only one prediction slot. If two objects have similar shapes and both centres fall in the same cell, they'd both be assigned to the same anchor and the label would have to choose one. In practice this is rare, especially with fine grids (\(19\times 19\)) and multiple anchors.
14. Show that a \(3\times 3\) transpose convolution with stride 2 expands a \(2\times 2\) input into a \(4\times 4\) output (formula-based).
The transpose conv output size formula: \(n_{\text{out}} = (n_{\text{in}} - 1) \cdot s - 2p + f\). With \(n_{\text{in}}=2, s=2, p=1, f=3\): \(n_{\text{out}} = (2-1)\cdot 2 - 2(1) + 3 = 2 - 2 + 3 = 3\)? Hmm — different conventions exist. In many frameworks (PyTorch/TF), the transposed conv output size is \(n_{\text{out}} = (n_{\text{in}} - 1)s - 2p + f\). With \(n_{\text{in}}=2, s=2, p=1, f=3\): \(n_{\text{out}} = 1\cdot 2 - 2 + 3 = 3\). If we want 4×4, we'd use \(p=0\): \(n_{\text{out}} = 2 - 0 + 3 = 5\)? Or the simplest demonstration is: \(2\times2\) input, filter \(2\times2\), stride 2, no padding → output 4×4.
15. Describe the exact sequence of steps a modern object detector (like YOLOv3) takes from raw image to final detections.
(1) Feed the image to a CNN backbone (e.g., Darknet). (2) The backbone produces feature maps at multiple scales. (3) Detection heads produce \(S\times S\times(\text{anchors}\times(5+K))\) predictions at each scale. (4) For each (cell, anchor), decode the predicted offsets into an actual box, apply the objectness and class scores. (5) Discard low-\(p_c\) predictions. (6) Run NMS per class to remove duplicates. (7) Output the final list of boxes with class labels and confidence scores.
16. A medical imaging team wants to outline tumours in MRI scans. Which of the two tasks in this week would you recommend — object detection or semantic segmentation? Why?
Semantic segmentation. Tumour boundaries are irregular; bounding boxes would be too coarse. Per-pixel labels give precise shape, area, and boundary information — critical for diagnosis and surgical planning. U-Net is the standard architecture for this exact task.
17. If a detector has perfect bounding boxes but mislabels some cars as buses, is IoU high or low? Is NMS affected?
IoU measures only box overlap — so it would be high (close to 1) because the boxes are correct. NMS is also based on IoU, so its behaviour would be normal. But the detection as a whole is wrong because the class label is wrong — IoU captures localisation quality, not classification quality.
18. Could you use NMS for regression (e.g., overlapping pose keypoints)? Why or why not?
Not directly. NMS assumes each detection has a scalar confidence and an IoU-measurable shape (a box). For keypoints, there's no box and no natural IoU. Detection models that predict keypoints usually use NMS on person-level boxes first, then apply keypoint regression on each surviving box.
19. In YOLO with anchor boxes, how would the label vector look for a cell containing both a pedestrian (assigned to anchor 1) and a car (assigned to anchor 2)?
$$y = \underbrace{[1, b_x^p, b_y^p, b_h^p, b_w^p, 1, 0, 0]}_{\text{anchor 1 (pedestrian)}}, \underbrace{[1, b_x^c, b_y^c, b_h^c, b_w^c, 0, 1, 0]}_{\text{anchor 2 (car)}}$$ Both \(p_c\) entries are 1, and the class one-hots are placed in the correct positions for each anchor.
20. Explain why U-Net's "U" shape is important. What would go wrong if we just used an encoder followed by a fully connected layer?
An encoder + FC gives a global classification but loses all spatial information — you can't output a segmentation map. The U-shape (encoder → bottleneck → decoder) reconstructs the spatial resolution step by step. Without the decoder, the output wouldn't be pixel-aligned with the input, and without skip connections, boundaries would be very fuzzy.
