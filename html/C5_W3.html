1. Introduction & Big Picture

In Week 1 we learned the basic RNN. In Week 2 we learned how to represent words with embeddings. This week we put these pieces together to build the models that power modern machine translation, speech recognition, and image captioning: sequence-to-sequence (seq2seq) models.

The central idea is simple: use one RNN (the encoder) to read the input sequence, and a second RNN (the decoder) to generate the output sequence. When the input is very long, we add an attention mechanism that lets the decoder look back at specific parts of the input rather than relying on a single fixed-size vector.

🟢 Intuition — Encoder + Decoder

Imagine translating a French sentence. You read the whole French sentence first and build a mental understanding of it (encoder). Then you start writing the English translation word by word (decoder), glancing back at different parts of the French sentence as needed. The glancing back is exactly what attention does.

This week covers:

  1. Sequence-to-sequence (seq2seq) models and image captioning.
  2. How to choose the best output sequence — beam search.
  3. How to evaluate machine translation — BLEU score.
  4. The attention mechanism and how it fixes long-sequence problems.
  5. Speech recognition and the CTC loss.
  6. Trigger word detection (e.g., "Hey Siri", "Okay Google").

2. Sequence-to-Sequence Models

🔵 Definition — Sequence-to-Sequence (Seq2Seq) Model

A seq2seq model is a neural network architecture that takes a sequence as input and produces a sequence as output. It is composed of two RNNs: an encoder that reads the input sequence, and a decoder that generates the output sequence.

2.1 Machine Translation Example

Input (French): "Jane visite l'Afrique en septembre."
Output (English): "Jane is visiting Africa in September."

Figure 1. Seq2seq model for machine translation. The encoder (green) reads the French sentence and produces a final hidden state that summarizes it. The decoder (blue) takes that summary and generates the English translation word by word, feeding each output back as the next input. The purple arrow shows the handoff from encoder to decoder.

🟡 Important — Many-to-Many with Tx ≠ Ty

This is the "many-to-many with \(T_x \neq T_y\)" architecture from Week 1. The input and output sequences can have different lengths. The encoder consumes the whole input; the decoder generates the output.

💡 Insight — Origin

The seq2seq model was introduced by Sutskever, Vinyals, and Le (2014) and by Cho et al. (2014). It dramatically improved machine translation quality and is the foundation of modern translation and text summarization systems.

3. Image Captioning

A powerful application of the same seq2seq idea: given an image, produce a caption.

Figure 2. Image captioning. A CNN (typically a pretrained network like VGG or ResNet) reads the image and produces a feature vector (e.g., 4096 dimensions). This replaces the encoder RNN of the translation model. The RNN decoder then generates a caption word by word: "A cat sitting on a chair."

💡 Insight — The Encoder Need Not Be an RNN

For image captioning, the "encoder" is a CNN. This shows the flexibility of the seq2seq framework: any model that turns the input into a useful representation can serve as the encoder. What matters is the decoder generates the output sequence.

4. Machine Translation as a Conditional Language Model

To translate well, we need a model that estimates:

$$P(y^{\langle 1 \rangle}, \dots, y^{\langle T_y \rangle} \mid x^{\langle 1 \rangle}, \dots, x^{\langle T_x \rangle})$$

This is the probability of the English sentence \(y\) given the French sentence \(x\). This is called a conditional language model.

🔵 Definition — Conditional Language Model

A language model that estimates the probability of a target sequence given some input sequence. Whereas a plain language model learns \(P(y)\), a conditional language model learns \(P(y \mid x)\).

4.1 Language Model vs Conditional Language Model

AspectLanguage ModelConditional Language Model
Learns \(P(y^{\langle 1 \rangle}, \dots, y^{\langle T_y \rangle})\) \(P(y^{\langle 1 \rangle}, \dots, y^{\langle T_y \rangle} \mid x)\)
Input Nothing (or a start token) An input sequence \(x\) (e.g., French sentence)
Use case Text generation Machine translation, image captioning
Encoder Not needed Required to encode \(x\)
🟡 Important — Why "Conditional"?

The model is "conditioned" on \(x\). When we generate a translation, we want it to be fluent and faithful to the meaning of \(x\). The conditional probability \(P(y \mid x)\) captures both — high-probability \(y\) values are both fluent English and reasonable translations of \(x\).

5. Finding the Most Likely Translation

Given a French sentence \(x\), we want to find the English sentence \(y\) that maximizes:

$$\arg\max_{y^{\langle 1 \rangle}, \dots, y^{\langle T_y \rangle}} P(y^{\langle 1 \rangle}, \dots, y^{\langle T_y \rangle} \mid x)$$

For "Jane visite l'Afrique en septembre," many translations are possible:

  • "Jane is visiting Africa in September." ✔️
  • "Jane is going to be visiting Africa in September." ✔️ (but wordy)
  • "In September, Jane will visit Africa." ✔️ (valid but less natural)
  • "Her African friend welcomed Jane in September." ❌ (wrong meaning)

We want the one with the highest \(P(y \mid x)\).

🔴 Warning — The Search Space Is Enormous

If the vocabulary has 10,000 words and the output is 10 words long, there are \(10{,}000^{10} = 10^{40}\) possible sentences. Enumerating them all is impossible. We need a smart search algorithm — that is exactly what beam search is for.

6. Why Not Greedy Search?

A naive approach: at each step, pick the single most likely word, then move on. This is called greedy search.

🔵 Definition — Greedy Search

At each time step, pick the word with the highest probability given all previous words. Then commit to that choice and never revisit it.

6.1 Why Greedy Search Fails

🟣 Example — Greedy Goes Down the Wrong Path

Consider translating "Jane visite l'Afrique en septembre."

  • Greedy: after "Jane", the model thinks "is" is most likely (60%). Picks "Jane is".
  • Then "going" is most likely after "Jane is" — but "Jane is going to be visiting Africa in September" is wordy.
  • Alternative: "Jane visits" starts with a slightly lower-probability word ("visits" instead of "is"), but leads to a much better overall sentence: "Jane visits Africa in September."

Greedy commits to "Jane is" early and cannot backtrack. The final translation is worse than what a smarter search would find.

🟢 Intuition — Greedy Lacks Foresight

Greedy search is like choosing each step of a hike by always stepping to the next highest ground. That gets you to a local peak quickly, but not to the highest mountain. You need to look ahead, or at least keep multiple options open.

💡 Insight — Greedy Is a Special Case of Beam Search

Greedy search is exactly beam search with beam width \(B = 1\). Increasing \(B\) gives better results because more candidates are kept at each step.

7. Beam Search Algorithm

🔵 Definition — Beam Search

Beam search is a heuristic search algorithm that, at each time step, keeps the \(B\) most promising partial sequences (where \(B\) is the beam width). It is not guaranteed to find the globally optimal sequence, but it is much faster than exhaustive search and works very well in practice.

7.1 Step-by-Step

Let's work through the French sentence: "Jane visite l'Afrique en septembre."

Figure 3. Beam search with beam width \(B = 3\). At each step, the algorithm expands every current candidate by all possible next words, scores each extended sequence, and keeps the top \(B\).

7.2 Detailed Algorithm

  1. Step 1: Run the encoder on \(x\). The decoder's first step produces a probability distribution over all \(|V|\) words. Pick the top \(B\) words as the first word candidates. Store each candidate and its probability.
  2. Step 2: For each of the \(B\) candidates, run the decoder one more step to get a probability distribution for the second word. There are \(B \times |V|\) possible (word1, word2) pairs. Score each pair by the product of its two probabilities, and keep the top \(B\).
  3. Step 3 and beyond: Repeat the same expansion and pruning at each subsequent step.
  4. Stop when <EOS> is reached (or a max length is hit). Among the completed sequences, pick the one with the highest total probability (possibly normalized — see next section).
🟡 Important — What "Probability" Means Here

For a candidate sequence \(y^{\langle 1 \rangle}, \dots, y^{\langle t \rangle}\), its beam-search score is the product of the per-step conditional probabilities:

$$P(y^{\langle 1 \rangle}, \dots, y^{\langle t \rangle} \mid x) = \prod_{k=1}^{t} P\!\left(y^{\langle k \rangle} \mid x, y^{\langle 1 \rangle}, \dots, y^{\langle k-1 \rangle}\right)$$

When we write \(\log P\), it becomes a sum — which is numerically more stable and easier to compare.

8. Refinements to Beam Search

8.1 Length Normalization

Because each step multiplies by a probability ≤ 1, longer sequences automatically get lower total probabilities. This biases beam search toward short sentences — which is usually undesirable.

🟣 Example — Short Sequence Bias

Suppose every step has a very high probability of 0.9. After 5 steps, the product is \(0.9^5 \approx 0.59\). After 20 steps, it is \(0.9^{20} \approx 0.12\). A 20-word perfect translation would score lower than a 5-word imperfect one simply because it has more factors. This is unfair.

Fix: length normalization. Divide the log-probability by the length of the sequence (or by a softened power of it):

$$\text{score}(y) = \frac{1}{T_y^{\alpha}} \sum_{t=1}^{T_y} \log P\!\left(y^{\langle t \rangle} \mid x, y^{\langle 1 \rangle}, \dots, y^{\langle t-1 \rangle}\right)$$

where:

  • \(T_y\) = length of the candidate sequence \(y\).
  • \(\alpha\) = a hyperparameter that controls how aggressively to normalize (typically \(0.6\) or \(0.7\)).
  • \(\alpha = 1\): full length normalization (divide by length).
  • \(\alpha = 0\): no normalization (raw sum of log-probs).
🔵 Remember — Typical Values

In production systems, \(\alpha = 0.7\) is a common choice for machine translation. It was found empirically to give a good balance between short and long sequences.

9. Beam Width Discussion

Beam width \(B\)Effect
\(B = 1\)Greedy search — fastest, worst quality
\(B = 3\)Reasonable small-scale setting
\(B = 10\)Common for production translation
\(B = 100\)Better results, ~10× slower
\(B = 1000\)Diminishing returns, much slower
\(B = 3000\)Rarely worth the cost
🟡 Important — Beam Search Is Not Exact

Unlike BFS (Breadth-First Search) or DFS (Depth-First Search), beam search is a heuristic. It runs faster but is not guaranteed to find the global maximum of \(\arg\max_y P(y \mid x)\). It only finds a good approximation. This is fine for most applications because the exact maximum is not always the best translation anyway (a slightly lower-probability sentence may sound more natural).

💡 Insight — Choosing \(B\)

For a research prototype or small dataset, \(B = 3\) is fine. For a production system, \(B = 10\) or so is common. For very high-quality needs, larger \(B\) may help, but returns diminish quickly and compute grows linearly with \(B\).

10. Error Analysis on Beam Search

When a model produces a bad translation, we want to know why: is it the RNN model's fault, or is it beam search failing to find the best output?

🔵 Definition — Error Analysis for Beam Search

A manual inspection procedure that, for each bad translation, compares the probability the model assigns to the human reference \(y^*\) against the probability it assigns to the algorithm's output \(\hat{y}\). If \(P(y^* \mid x) > P(\hat{y} \mid x)\), beam search is at fault. Otherwise, the RNN model itself is at fault.

10.1 The Two Cases

🟣 Example — Setting Up the Comparison

Source: "Jane visite l'Afrique en septembre."

  • Human reference: \(y^*\) = "Jane visits Africa in September."
  • Algorithm output: \(\hat{y}\) = "Jane visited Africa last September."
CaseConditionConclusion
Case 1 \(P(y^* \mid x) > P(\hat{y} \mid x)\) Beam search is at fault — the model did think \(y^*\) was more likely, but beam search failed to find it.
Case 2 \(P(y^* \mid x) \leq P(\hat{y} \mid x)\) RNN model is at fault — the model genuinely believes \(\hat{y}\) is more probable than \(y^*\). The model's probability estimate is wrong.

10.2 The Error Analysis Table

Collect these comparisons over many examples. The table looks like this:

Jane visits Africa in September.Jane visited Africa last September.\(2 \times 10^{-10}\)\(1 \times 10^{-10}\)B (Beam)

After collecting, look at the fractions:

  • If most errors are "B" (beam): increase beam width \(B\).
  • If most errors are "R" (RNN): you need to improve the model itself — more data, better architecture, regularization, etc.
💡 Insight — Diagnosis Guides Action

This analysis is valuable because it tells you where to invest effort. If beam search is at fault, throwing more data at the model won't help; you just need a wider beam. If the model is at fault, widening the beam is pointless.

11. BLEU Score

BLEU (Bilingual Evaluation Understudy) is a metric for automatically evaluating machine translation (and other text generation tasks). It compares the MT output against one or more human reference translations.

🔵 Definition — BLEU Score

BLEU measures how many n-grams (contiguous chunks of \(n\) words) in the MT output appear in any of the reference translations. It ranges from 0 (no overlap) to 1 (perfect). A high BLEU score means the MT output is close to human-quality translation.

11.1 The Precision Problem

Naive precision would be: what fraction of the MT output's words appear in a reference? This is broken.

🟣 Example — Why Naive Precision Fails

Reference 1: "The cat is on the mat."
Reference 2: "There is a cat on the mat."
MT output: "the the the the the the the"

Every word "the" appears in the references. Naive precision = 1.0. But the output is nonsense!

11.2 Modified Precision

Fix: count each n-gram at most as many times as it appears in the references. This is called modified precision.

$$p_n = \frac{\sum_{\text{n-grams in MT}} \min\!\left(\text{count in MT},\ \max_{\text{ref}} \text{count in ref}\right)}{\sum_{\text{n-grams in MT}} \text{count in MT}}$$

In the example above, "the" appears 7 times in the MT output but at most 2 times in any single reference. So the modified count is 2, giving a modified precision of \(2/7\). Much more reasonable.

11.3 Combining n-gram Scores

BLEU combines precision for \(n = 1, 2, 3, 4\):

$$\text{BLEU} = \text{BP} \cdot \exp\!\left(\frac{1}{4} \sum_{n=1}^{4} p_n\right)$$

where:

  • \(p_n\) = modified precision for n-grams of size \(n\).
  • \(\text{BP}\) = brevity penalty (see below).

11.4 The Brevity Penalty

BLEU should penalize translations that are too short (since short output trivially has high precision). The brevity penalty is:

$$\text{BP} = \begin{cases} 1 & \text{if MT length} > \text{reference length} \\ \exp\!\left(1 - \dfrac{\text{MT length}}{\text{reference length}}\right) & \text{otherwise} \end{cases}$$
🟡 Important — Intuition Behind BP

If the MT output is as long as or longer than the reference, no penalty (\(\text{BP} = 1\)). If it's shorter, the BP shrinks exponentially. This discourages the model from outputting very short, trivially-precise translations like "the the."

💡 Insight — BLEU in Practice

BLEU is fast, deterministic, and correlates reasonably well with human judgment for machine translation. It is the standard metric for MT research. It is not perfect — it ignores meaning, grammar, and synonyms — but it's still widely used.

12. Attention Model Intuition

Plain seq2seq models have a serious limitation: they force the encoder to compress the entire input into a single fixed-size vector. For long inputs (30+ words), the model forgets the beginning by the time it reaches the end.

Figure 4. BLEU score vs sentence length. Without attention (blue curve), translation quality rises until ~20 words, then degrades sharply as the encoder cannot remember the whole sequence. With attention (green curve), quality stays high even for very long sentences.

🟢 Intuition — A Human Translator's Gaze

When a human translates a long sentence, they don't memorize the whole thing first and then write. They glance back at the specific part of the source that corresponds to what they are about to write. Attention gives the RNN the same ability — at each step of generation, the decoder can look back at any part of the input.

🔵 Definition — Attention Mechanism

At each decoder step \(t\), the attention mechanism computes a weighted sum of all encoder hidden states \(a^{\langle t' \rangle}\), where the weights \(\alpha^{\langle t, t' \rangle}\) represent how much attention the decoder should pay to input position \(t'\). The weighted sum is the context vector \(c^{\langle t \rangle}\), which is fed to the decoder.

13. Attention Model

The attention model (Bahdanau, Cho, Bengio 2014) adds a small neural network that, for each decoder step \(t\), computes weights for every encoder step \(t'\).

Figure 5. The attention model. The bidirectional encoder produces a hidden state \(a^{\langle t' \rangle}\) for every input position \(t'\). The attention layer computes weights \(\alpha^{\langle t, t' \rangle}\), which are used to form a context vector \(c^{\langle t \rangle}\) — a weighted sum of all encoder states. The decoder uses this context at each step.

14. Computing Attention α

The attention weight \(\alpha^{\langle t, t' \rangle}\) says: how much should the decoder at output step \(t\) pay attention to encoder step \(t'\)?

14.1 The Computation

  1. Use the decoder's previous hidden state \(s^{\langle t-1 \rangle}\) and the encoder's hidden state \(a^{\langle t' \rangle}\) to compute an unnormalized score \(e^{\langle t, t' \rangle}\):
    $$e^{\langle t, t' \rangle} = \text{smallNN}\!\left(s^{\langle t-1 \rangle},\ a^{\langle t' \rangle}\right)$$
    The small NN is usually just a single hidden layer.
  2. Normalize the scores across all \(t'\) using a softmax:
    $$\alpha^{\langle t, t' \rangle} = \frac{\exp\!\left(e^{\langle t, t' \rangle}\right)}{\sum_{t'=1}^{T_x} \exp\!\left(e^{\langle t, t' \rangle}\right)}$$
    This ensures \(\sum_{t'} \alpha^{\langle t, t' \rangle} = 1\).
  3. Compute the context vector as a weighted sum:
    $$c^{\langle t \rangle} = \sum_{t'=1}^{T_x} \alpha^{\langle t, t' \rangle}\, a^{\langle t' \rangle}$$
SymbolShapeMeaning
\(a^{\langle t' \rangle}\)\(n_a \times 1\)Encoder hidden state at input position \(t'\)
\(s^{\langle t-1 \rangle}\)\(n_s \times 1\)Decoder hidden state at output position \(t-1\)
\(e^{\langle t, t' \rangle}\)scalarUnnormalized attention score
\(\alpha^{\langle t, t' \rangle}\)scalarNormalized attention weight
\(c^{\langle t \rangle}\)\(n_a \times 1\)Context vector for decoder step \(t\)
\(T_x\)scalarLength of input sequence

14.2 The Decoder Update

The decoder's hidden state is updated using both the previous hidden state and the context vector:

$$s^{\langle t \rangle} = g\!\left( W_s \begin{bmatrix} s^{\langle t-1 \rangle} \\ c^{\langle t \rangle} \end{bmatrix} + b_s \right)$$

Then the output word is predicted from \(s^{\langle t \rangle}\) as usual.

💡 Insight — Computational Cost

If the input has \(T_x\) words and the output has \(T_y\) words, attention computes \(T_x \times T_y\) scores. For translation tasks where \(T_x, T_y \sim 50\), that's 2,500 scores — cheap. Attention adds a tiny overhead but dramatically improves quality for long sequences.

15. Attention Visualizations

Attention weights \(\alpha^{\langle t, t' \rangle}\) can be visualized as a heatmap. This is useful both for debugging and for building trust in the model.

Figure 6. Attention heatmap for "Jane visite l'Afrique en septembre" → "Jane visits Africa in September." Bright cells indicate high attention. The map shows a rough diagonal alignment: "Jane" attends to "Jane", "visits" to "visite", "Africa" to "l'Afrique", "in" to "en", "September" to "septembre." This is what we hope to see — the model has learned a soft alignment between languages.

🟡 Important — Other Attention Examples

The lecture also shows date normalization examples:

  • "July 20th 1969" → "1969-07-20" — attention reveals which input words map to each output character.
  • "23 April, 1564" → "1564-04-23" — same idea, with the year moving to the front of the output.

These demonstrate that attention works for arbitrary sequence-to-sequence alignment, not just translation.

16. Speech Recognition

Speech recognition is the task of converting an audio waveform into text.

Figure 7. Speech recognition. The input \(x\) is an audio clip (raw waveform) or its spectrogram representation. The output \(y\) is the transcript (a sequence of words). Some systems use an intermediate representation of phonemes before producing words. Modern datasets range from 300 hours (small) to 100,000 hours (large).

🟣 Example — Input and Output

Input: an audio clip of someone saying "the quick brown fox."

Output: the string "the quick brown fox."

Challenges: the audio may be 1000 time steps (samples), while the transcript is only 4 words. Aligning them is not obvious — which is why we need the CTC loss.

17. CTC Cost Function

Speech recognition has a tricky alignment problem: an audio clip might be 1000 time steps long, but the transcript might be only a few words. We cannot simply say "the first 250 samples correspond to 'the'." The lengths are wildly different, and the alignment is unknown.

🔵 Definition — CTC (Connectionist Temporal Classification)

CTC is a loss function for sequence-to-sequence tasks where the input and output lengths differ and the alignment is unknown. It introduces a special "blank" token and collapses repeated characters that are not separated by a blank. This allows the RNN to output a character at every input time step, and the loss automatically figures out the right alignment.

17.1 The Blank Token and Collapse Rule

The RNN outputs a character (or blank) at every input time step. Then we apply the collapse rule:

Collapse repeated characters not separated by a blank. Remove all blanks.
🟣 Example — CTC Collapse

Suppose the RNN outputs a sequence of 19 characters:

t t t _ h _ e e e _ _ _ _ _ q q q _ _

where _ is the blank token. Applying the collapse rule:

  • t t t → t (consecutive t's collapse)
  • _ → remove
  • h → h
  • _ → remove
  • e e e → e
  • _ _ _ _ _ → remove
  • q q q → q
  • _ _ → remove

Result: t h e q ... — which spells "the q..." starting the phrase "the quick brown fox."

💡 Insight — Why Blanks Matter

Without a blank, "thee" would collapse to "the" — we couldn't distinguish "the" from "thee". The blank token lets us separate repeated characters. For example, h _ e _ e collapses to hee, while h e e collapses to he. This gives the model the expressive power to represent repeated letters.

17.2 The CTC Loss

The CTC loss marginalizes over all alignments that collapse to the correct output. It computes the probability that the RNN's per-time-step outputs collapse to the target sequence, summed over all possible valid alignments.

🔴 Warning — The Full CTC Loss is Complex

The full mathematical derivation of the CTC loss is beyond the scope of this course. What matters for our purposes is:

  • The RNN outputs a distribution over (characters + blank) at every time step.
  • CTC defines a loss that sums over all alignments consistent with the target.
  • This allows training without ever specifying the exact alignment.

18. Trigger Word Detection

Trigger word detection is the task of detecting a specific wake word in an audio stream — like "Hey Siri," "Okay Google," or "Alexa."

🔵 Definition — Trigger Word Detection

Given a continuous audio stream, detect when a specific trigger phrase (e.g., "Hey Siri") has been spoken. When detected, the system activates a downstream action (e.g., start listening for a command).

🟣 Example — Real Products
  • Amazon Echo → "Alexa"
  • Baidu DuerOS → "Xiaodunihao"
  • Apple Siri → "Hey Siri"
  • Google Home → "Okay Google"

18.1 The Algorithm

The system processes an audio stream with an RNN. At each time step, the RNN outputs:

  • \(y = 0\): no trigger word has just been said
  • \(y = 1\): the trigger word was said just before this time step

Figure 8. Trigger word detection. The RNN processes the audio stream one time step at a time. At each step, it outputs 0 (no trigger) or 1 (trigger just occurred). The model is trained to output 1 for a short window after the trigger phrase ends. This is a many-to-many RNN with a simple binary label at each step.

🟡 Important — Training Labels

For a positive audio clip containing "Hey Siri", we set \(y^{\langle t \rangle} = 0\) for all time steps before the trigger, then \(y^{\langle t \rangle} = 1\) for a short window after the trigger ends, then back to 0. This gives the model a positive training signal for the trigger window.

💡 Insight — Why Not Just Classify the Whole Audio?

Because we need streaming detection: the model must be able to fire whenever the trigger occurs, not just at the end of the clip. Per-time-step classification (with a many-to-many RNN) handles this naturally.

19. Weekly Summary

This week covered the major sequence-to-sequence architectures and techniques that power modern NLP:

  • Seq2seq models use an encoder RNN to read an input sequence and a decoder RNN to generate an output sequence. They handle input and output sequences of different lengths.
  • Image captioning is a seq2seq task where the encoder is a CNN instead of an RNN.
  • Machine translation is a conditional language model: it estimates \(P(y \mid x)\) rather than \(P(y)\).
  • We want to find \(\arg\max_y P(y \mid x)\). Brute force is infeasible because the search space is exponential in sequence length.
  • Greedy search picks the single most probable word at each step; it is fast but myopic and often suboptimal.
  • Beam search keeps the top \(B\) partial sequences at each step. Beam width \(B\) controls the quality/speed trade-off.
  • Length normalization (dividing log-prob by \(T_y^\alpha\)) counteracts the bias toward short sequences.
  • Error analysis on beam search compares \(P(y^* \mid x)\) vs. \(P(\hat{y} \mid x)\) to identify whether the model or the search is at fault.
  • BLEU score evaluates machine translation by n-gram overlap with reference translations, with a brevity penalty for short outputs.
  • Attention lets the decoder look back at every encoder state at every output step, dramatically improving long-sequence performance.
  • Speech recognition uses an RNN to map an audio spectrogram to a character sequence.
  • CTC loss handles the alignment problem in speech recognition using a blank token and a collapse rule.
  • Trigger word detection uses a per-time-step RNN to fire a 1 when the wake word is heard.

21. Important Equations (Reference)

🔵 1. Conditional Language Model
$$P(y^{\langle 1 \rangle}, \dots, y^{\langle T_y \rangle} \mid x^{\langle 1 \rangle}, \dots, x^{\langle T_x \rangle})$$

The probability of an output sequence given an input sequence.

🔵 2. Most Likely Translation
$$\arg\max_{y^{\langle 1 \rangle}, \dots, y^{\langle T_y \rangle}} P(y^{\langle 1 \rangle}, \dots, y^{\langle T_y \rangle} \mid x)$$

The output we want beam search to find.

🔵 3. Beam Search Score
$$\text{score}(y) = \prod_{t=1}^{T_y} P\!\left(y^{\langle t \rangle} \mid x, y^{\langle 1 \rangle}, \dots, y^{\langle t-1 \rangle}\right)$$

Product of per-step probabilities. In practice, we use the log of this (a sum) for numerical stability.

🔵 4. Length-Normalized Score
$$\text{score}(y) = \frac{1}{T_y^{\alpha}} \sum_{t=1}^{T_y} \log P\!\left(y^{\langle t \rangle} \mid x, y^{\langle 1 \rangle}, \dots, y^{\langle t-1 \rangle}\right)$$

\(\alpha \in [0, 1]\) controls how aggressively to penalize long sequences. Typical \(\alpha \approx 0.7\).

🔵 5. BLEU Score
$$\text{BLEU} = \text{BP} \cdot \exp\!\left(\frac{1}{4} \sum_{n=1}^{4} p_n\right)$$

\(p_n\) = modified n-gram precision, BP = brevity penalty.

🔵 6. Brevity Penalty
$$\text{BP} = \begin{cases} 1 & \text{if MT length} > \text{ref length} \\ \exp\!\left(1 - \frac{\text{MT length}}{\text{ref length}}\right) & \text{otherwise} \end{cases}$$
🔵 7. Attention Weights
$$\alpha^{\langle t, t' \rangle} = \frac{\exp\!\left(e^{\langle t, t' \rangle}\right)}{\sum_{t'=1}^{T_x} \exp\!\left(e^{\langle t, t' \rangle}\right)}$$

Softmax-normalized attention scores, summing to 1 over input positions.

🔵 8. Context Vector
$$c^{\langle t \rangle} = \sum_{t'=1}^{T_x} \alpha^{\langle t, t' \rangle}\, a^{\langle t' \rangle}$$

Weighted sum of encoder hidden states; fed to the decoder at step \(t\).

🔵 9. Attention Scoring Function
$$e^{\langle t, t' \rangle} = \text{smallNN}\!\left(s^{\langle t-1 \rangle},\ a^{\langle t' \rangle}\right)$$

A small neural network that scores how relevant encoder position \(t'\) is to decoder position \(t\).

22. Common Confusions

23. Quick Review (Q&A)

Click each question to reveal its answer.

Q1. What is a sequence-to-sequence (seq2seq) model?

A neural network that takes an input sequence and produces an output sequence. It consists of an encoder (reads the input) and a decoder (generates the output). The two sequences can have different lengths.

Q2. In image captioning, what plays the role of the encoder?

A CNN (typically a pretrained network like VGG or ResNet). It produces a fixed-size feature vector that summarizes the image, which is then fed to the RNN decoder.

Q3. What does a conditional language model estimate?

\(P(y^{\langle 1 \rangle}, \dots, y^{\langle T_y \rangle} \mid x^{\langle 1 \rangle}, \dots, x^{\langle T_x \rangle})\) — the probability of an output sequence given an input sequence.

Q4. Why is the search space for translation so large?

If the output vocabulary is 10,000 words and the target sentence is 10 words long, there are \(10{,}000^{10} = 10^{40}\) possible sentences. Enumerating them all is impossible.

Q5. What is greedy search, and why is it suboptimal?

Greedy search picks the single most probable word at each step. It is suboptimal because an early high-probability choice may lead to a worse overall sequence than a slightly lower-probability alternative.

Q6. How does beam search work?

At each step, it expands every current candidate sequence with every possible next word, scores each extended sequence, and keeps the top \(B\) (beam width). It is a heuristic — fast but not guaranteed to find the global maximum.

Q7. What is beam width, and what trade-off does it control?

\(B\) is the number of candidate sequences kept at each step. Larger \(B\) → better quality but slower. Smaller \(B\) → faster but worse. \(B = 1\) is exactly greedy search.

Q8. Why do we need length normalization in beam search?

Because each step multiplies by a probability ≤ 1, longer sequences automatically get lower total probabilities. Length normalization divides the log-prob by \(T_y^\alpha\) (typically \(\alpha = 0.7\)) to counteract this bias.

Q9. What is the difference between Case 1 and Case 2 in beam search error analysis?
  • Case 1: \(P(y^* \mid x) > P(\hat{y} \mid x)\) — beam search is at fault (the model knew the right answer but search missed it).
  • Case 2: \(P(y^* \mid x) \leq P(\hat{y} \mid x)\) — the RNN model is at fault (the model genuinely believed the wrong answer was more likely).
Q10. What is BLEU score, and what does it measure?

BLEU (Bilingual Evaluation Understudy) measures how many n-grams of the machine translation output appear in the reference translations. It uses modified precision (capping counts at reference occurrences) and a brevity penalty for short outputs.

Q11. What is the brevity penalty in BLEU?

It penalizes translations shorter than the reference. If the MT output is longer than the reference, \(\text{BP} = 1\). Otherwise, \(\text{BP} = \exp(1 - \text{MT length}/\text{ref length})\).

Q12. Why is attention useful for long sequences?

Without attention, the encoder must compress the entire input into a single fixed-size vector, which is hard for long inputs. Attention lets the decoder look at all encoder hidden states at every output step, so it can selectively focus on the relevant part of the input without needing to remember everything in a single vector.

Q13. What is the context vector \(c^{\langle t \rangle}\)?

The attention-weighted sum of all encoder hidden states: \(c^{\langle t \rangle} = \sum_{t'} \alpha^{\langle t, t' \rangle} a^{\langle t' \rangle}\). It is fed to the decoder at step \(t\) alongside the previous hidden state.

Q14. How are attention weights \(\alpha^{\langle t, t' \rangle}\) computed?

First, an unnormalized score \(e^{\langle t, t' \rangle}\) is computed by a small neural network taking the decoder's previous hidden state \(s^{\langle t-1 \rangle}\) and the encoder's hidden state \(a^{\langle t' \rangle}\). Then a softmax over all \(t'\) normalizes the scores so they sum to 1.

Q15. What does the attention heatmap tell us?

It shows which input positions the model attends to when generating each output word. A bright cell at \((t, t')\) means high attention. For translation, the heatmap often shows a rough diagonal alignment (each English word attends to the corresponding French word).

Q16. Why is speech recognition hard from an alignment perspective?

Because the input (audio samples) is much longer than the output (words or characters), and we don't know which input samples correspond to which output characters. The CTC loss solves this by introducing a blank token and a collapse rule.

Q17. What is the CTC collapse rule?

Collapse repeated characters not separated by a blank, then remove all blanks. For example, t t t _ h _ e e e _ _ _ _ _ q q q _ _ collapses to t h e q.

Q18. How does trigger word detection work?

An RNN processes the audio stream one time step at a time. At each step, it outputs 0 (no trigger) or 1 (trigger just occurred). It is trained as a many-to-many RNN with binary labels per time step.

Q19. Why not just classify the whole audio clip for trigger word detection?

Because we need streaming detection — the model must fire as soon as the trigger word is spoken, not at the end of the clip. Per-time-step classification handles this.

Q20. What are the two main components of a seq2seq model?

The encoder (reads the input sequence and produces a representation) and the decoder (generates the output sequence). For image captioning, the encoder is a CNN; for translation, it is an RNN.

24. Self-Test

Conceptual questions from easy → hard. Click to reveal.

Easy

ST1. Give two real-world applications of seq2seq models.

Machine translation (French → English) and image captioning (image → English description). Also text summarization, question answering, and chatbot response generation.

ST2. What is the difference between \(P(y)\) and \(P(y \mid x)\)?

\(P(y)\) is the probability of an output sequence on its own (a plain language model). \(P(y \mid x)\) is the probability of the output given the input \(x\) (a conditional language model). The latter is used for translation.

ST3. What is the beam width \(B\), and what is \(B = 1\) equivalent to?

\(B\) is the number of candidate sequences kept at each step of beam search. \(B = 1\) is exactly greedy search — pick the single best word at each step and never look back.

Medium

ST4. Why is length normalization important in beam search? Give a numerical intuition.

Because multiplying by probabilities ≤ 1 shrinks the total score as the sequence lengthens. For example, a perfectly good 20-word translation with per-step probability 0.9 has total probability \(0.9^{20} \approx 0.12\), while a mediocre 5-word translation with per-step probability 0.9 has \(0.9^{5} \approx 0.59\). Length normalization divides by \(T_y^\alpha\), giving longer sentences a fairer chance.

ST5. You observe that a translation system often produces wrong translations, and you suspect it may be beam search's fault. Describe the error analysis you would perform.

For each bad translation:

  1. Record the human reference \(y^*\) and the algorithm output \(\hat{y}\).
  2. Compute \(P(y^* \mid x)\) and \(P(\hat{y} \mid x)\).
  3. If \(P(y^* \mid x) > P(\hat{y} \mid x)\), beam search is at fault (case 1).
  4. If \(P(y^* \mid x) \leq P(\hat{y} \mid x)\), the model is at fault (case 2).

After analyzing many examples, count the fraction of case-1 vs case-2 errors. If beam search dominates, increase \(B\). If the model dominates, invest in better training data or architecture.

ST6. Why does BLEU use modified precision rather than raw precision?

Because raw precision would reward outputs like "the the the the the the the" — every word appears in the reference, so raw precision = 1.0 even though the output is nonsense. Modified precision caps each n-gram count at its maximum occurrence in any reference, so "the" counted 7 times but appearing at most 2 times in any reference gets a modified count of 2. This gives a much lower (and more honest) precision.

ST7. Why is attention especially useful when input sequences are long?

Without attention, the encoder must compress the entire input into a single fixed-size vector, which loses information for long inputs. With attention, the decoder can look at any encoder hidden state at each decoding step. This lets it selectively focus on the relevant part of the input, no matter how long the input is.

Hard

ST8. Derive the intuition for why the softmax normalization in attention is important.

Without normalization, the "attention weights" would be arbitrary real numbers, and the context vector's magnitude would depend on how many input positions there are. The softmax ensures:

  • All weights are in \((0, 1)\).
  • The weights sum to 1.
  • The context vector is a genuine weighted average of the encoder states, so its magnitude is comparable across different input lengths.

Additionally, the softmax makes the attention distribution differentiable, so we can train it with backpropagation.

ST9. In the CTC collapse rule, why is the blank token necessary? What would happen without it?

Without the blank, repeated characters would always collapse, so we could never distinguish "he" from "hee" or "the" from "thee." The blank separates adjacent identical characters: h e e collapses to "he", while h e _ e collapses to "hee". The blank gives the model the ability to represent repeated letters.

ST10. Suppose you have a seq2seq model that translates reasonably but struggles with long sentences. You want to improve it. Describe two options: one that keeps the current architecture and one that changes it.

Option 1 (keep architecture): Improve the data — collect more long-sentence training examples. Optionally, increase the beam width at inference time to search more candidates.

Option 2 (change architecture): Add an attention mechanism. Instead of forcing the encoder to compress the entire input into a fixed-size vector, attention lets the decoder query any part of the encoder state at any output step. This dramatically improves performance on long sequences without needing an enormous amount of extra data.

ST11. In a speech recognition system using CTC, the RNN outputs a character distribution at each of 1000 input time steps. The output transcript is "cat." Explain how CTC can handle this without needing to know which time steps correspond to which characters.

CTC marginalizes over all possible alignments. Suppose the RNN outputs something like c c _ a a a _ t t _ _ _ .... Collapsing gives "cat." Other alignments like _ c _ a _ t _ also collapse to "cat." The CTC loss sums the probability of all alignments that collapse to the target, so the model learns to assign high probability to some valid alignment without us specifying which one. This is why CTC can train without alignment labels.

ST12. Why is beam search not guaranteed to find the global maximum of \(\arg\max_y P(y \mid x)\)? Is that a problem in practice?

Beam search prunes candidates at each step — it only keeps the top \(B\). A sequence that starts with a low-probability word but has very high probability for subsequent words might be pruned early and never recovered. So beam search is not guaranteed to find the exact global maximum.

In practice this is usually fine: (1) with reasonable \(B\), beam search finds sequences very close to the global maximum; (2) the true global maximum is not always the best translation anyway — a slightly lower-probability sentence may sound more natural.
