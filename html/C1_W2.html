1. Binary Classification

🔵 Definition — Binary Classification

Binary classification is a supervised-learning problem in which the output $y$ can take only two values — conventionally $0$ or $1$. The model's job is to decide which class a given input belongs to.

Examples from the lectures:

  • Email / account security: has this account been hacked? (1 = hacked, 0 = not hacked)
  • Medical diagnosis: is a tumor malignant (1) or benign (0)?
  • The running example of this course: is this image a cat (1) or not a cat (0)?

1.1 How a computer stores an image

To make this concrete, take a $64 \times 64$ pixel color image of a cat. A computer stores it as three separate matrices of numbers — one per color channel:

  • Red channel — a $64 \times 64$ matrix
  • Green channel — a $64 \times 64$ matrix
  • Blue channel — a $64 \times 64$ matrix

Each cell contains a pixel intensity — a number from 0 to 255 describing how much of that color is present at that pixel. So an image of size $64 \times 64$ contains $64 \times 64 \times 3 = 12{,}288$ numbers.

🔵 Definition — Feature Vector

A feature vector is a column vector containing all the input numbers describing one example. For our cat image, the feature vector $x$ has $n_x = 12{,}288$ entries.

$$n = n_x = 64 \times 64 \times 3 = 12{,}288$$
The dimension of the input feature vector for a 64×64 RGB image.
🟢 Intuition

Think of the model as a “black box” that receives a long list of numbers (the pixel intensities) and outputs either 0 or 1. All the learning happens by adjusting internal parameters so that the box outputs the right answer on the training examples.

⭐ Key Idea — Notation Convention

From here on, $x$ denotes the input feature vector and $y \in \{0,1\}$ denotes the binary label. The training set consists of $m$ labeled pairs $(x^{(i)}, y^{(i)})$ for $i = 1, \ldots, m$.

2. Notation for Deep Learning

Andrew Ng is very deliberate about notation because it stays consistent throughout the entire specialization. Internalize it now; it will save you confusion later.

2.1 Superscripts — example vs layer

🔵 Definition — Superscript conventions
  • $(i)$ in parentheses — refers to the $i$-th training example. E.g., $x^{(3)}$ is the third training example's input.
  • $[l]$ in brackets — refers to the $l$-th layer of the neural network. E.g., $W^{[2]}$ is the weight matrix of the second layer.
🔴 Warning

Do not mix these up! $(i)$ is parentheses and refers to examples; $[l]$ is brackets and refers to layers. This distinction is critical once we start writing equations with both.

2.2 Sizes

SymbolMeaning
$m$Number of training examples in the dataset
$n_x$Input size (dimension of the feature vector $x$)
$n_y$Output size (number of classes or output units)
$n_h^{[l]}$Number of hidden units in layer $l$
$L$Total number of layers in the network

For convenience, one can also define $n_x = n_h^{[0]}$ and $n_y = n_h^{[L+1]}$, treating the input and output as “layer 0” and “layer $L+1$”.

2.3 Objects (matrices and vectors)

⭐ Key Idea — Why $X$ is $n_x \times m$, not $m \times n_x$

In many machine learning libraries (scikit-learn, pandas) each row is one example. But in this specialization, following standard deep-learning convention, each column is one example. This makes the matrix arithmetic work out cleanly when we vectorize, as you'll see in Section 11.

2.4 Common forward-propagation equations

For a general layer $l$ with activation function $g^{[l]}$:

$$a_j^{[l]} = g^{[l]}\!\left(\sum_k w_{jk}^{[l]} a_k^{[l-1]} + b_j^{[l]}\right) = g^{[l]}\!\left(z_j^{[l]}\right)$$
The general activation formula: each unit computes a weighted sum of the previous layer's activations, adds its bias, then applies the activation function.

Variables:

  • $a_j^{[l]}$ — activation (output) of unit $j$ in layer $l$.
  • $w_{jk}^{[l]}$ — weight connecting unit $k$ in layer $l-1$ to unit $j$ in layer $l$.
  • $a_k^{[l-1]}$ — activation of unit $k$ in the previous layer.
  • $b_j^{[l]}$ — bias of unit $j$ in layer $l$.
  • $g^{[l]}$ — activation function of layer $l$ (e.g., sigmoid, ReLU).
  • $z_j^{[l]}$ — the weighted sum before applying $g^{[l]}$.

And the predicted output is the final layer's activation:

$$\hat{y} = a^{[L]}$$

2.5 Cost function notation

The cost (or loss) is written $J(w, b)$ or $J(\hat{y}, y)$ and measures how far the predictions are from the true labels. Two common examples:

$$J_{CE}(\hat{y}, y) = -\sum_{i=1}^{m} y^{(i)} \log \hat{y}^{(i)}$$
Cross-entropy cost — used for classification tasks.
$$J_{1}(\hat{y}, y) = \sum_{i=1}^{m} \left| y^{(i)} - \hat{y}^{(i)} \right|$$
L1 cost — sum of absolute errors.

3. Logistic Regression

🔵 Definition — Logistic Regression

Logistic regression is a supervised-learning algorithm for binary classification. Given an input feature vector $x$, it outputs the probability that the label is 1: $\hat{y} = P(y=1 \mid x)$, with $0 \le \hat{y} \le 1$.

Although logistic regression is not itself a “deep” network, it is the fundamental building block of this course. A single-layer neural network for binary classification is logistic regression. Understanding it deeply makes everything that follows easier.

3.1 Parameters

SymbolSpaceMeaning
$x$$\mathbb{R}^{n_x}$Input feature vector (e.g., the flattened 12,288-dim cat image)
$y$$\{0,1\}$Binary label
$w$$\mathbb{R}^{n_x}$Weight vector — one weight per input feature
$b$$\mathbb{R}$Bias (a single scalar threshold)
$\hat{y}$$[0,1]$Predicted probability that $y = 1$

3.2 The model

The logistic regression model computes a linear combination $z = w^T x + b$ and then applies the sigmoid function:

$$\hat{y} = \sigma\!\left(w^T x + b\right) = \sigma(z)$$
Logistic regression output: a probability between 0 and 1.

where the sigmoid function is:

$$\sigma(z) = \frac{1}{1 + e^{-z}}$$
The sigmoid (or logistic) function.
🟢 Intuition — why sigmoid?

The linear part $w^T x + b$ can be any real number — from $-\infty$ to $+\infty$. But we need a probability in $[0,1]$. The sigmoid function “squashes” any real number into the interval $(0,1)$: very negative numbers map close to 0, very positive numbers map close to 1, and 0 maps to exactly 0.5.

3.3 Properties of the sigmoid

  • If $z$ is a large positive number, $\sigma(z) \approx 1$.
  • If $z$ is a large negative number, $\sigma(z) \approx 0$.
  • If $z = 0$, then $\sigma(z) = 0.5$.
🔴 Warning — a common notation confusion

In some textbooks you'll see an extra “intercept” input $x_0 = 1$ with a corresponding weight, absorbing the bias into the weight vector. Andrew's course keeps $b$ separate. Stick with the course's convention: $z = w^T x + b$.

4. Logistic Regression Cost Function

To train $w$ and $b$, we need to define how “wrong” the model is on each example, and then how wrong it is on the whole training set. That's the role of the loss and cost functions.

🔵 Definition — Loss function

The loss function (also called error function) $L(\hat{y}, y)$ measures the discrepancy between one prediction $\hat{y}$ and one true label $y$. It is defined per example.

🔵 Definition — Cost function

The cost function $J(w, b)$ is the average loss over all $m$ training examples. Training means finding the $w$ and $b$ that minimize $J$.

4.1 Why not squared error?

You might think: “Just use the squared error $L(\hat{y}, y) = \tfrac{1}{2}(\hat{y} - y)^2$.” That's what linear regression does. For logistic regression, however, this produces a non-convex cost surface with many local minima, which makes gradient descent unreliable. Instead, we use the cross-entropy loss:

$$L(\hat{y}, y) = -\left[ y \log(\hat{y}) + (1 - y) \log(1 - \hat{y}) \right]$$
Binary cross-entropy loss — the standard loss for logistic regression.

4.2 Understanding the loss, case by case

🟣 Case 1 — When the true label is $y = 1$

The second term $(1-y)\log(1-\hat{y})$ becomes 0, leaving:

$$L(\hat{y}, y) = -\log(\hat{y})$$
  • If $\hat{y} \to 1$, then $-\log(\hat{y}) \to 0$ — small loss. Good.
  • If $\hat{y} \to 0$, then $-\log(\hat{y}) \to +\infty$ — huge loss. Bad.

So the loss pushes the prediction toward 1, which is what we want when $y = 1$.

🟣 Case 2 — When the true label is $y = 0$

The first term $y\log(\hat{y})$ becomes 0, leaving:

$$L(\hat{y}, y) = -\log(1-\hat{y})$$
  • If $\hat{y} \to 0$, then $-\log(1-\hat{y}) \to 0$ — small loss. Good.
  • If $\hat{y} \to 1$, then $-\log(1-\hat{y}) \to +\infty$ — huge loss. Bad.

So the loss pushes the prediction toward 0, which is what we want when $y = 0$.

🟢 Intuition — the loss is a “surprise meter”

Cross-entropy measures how surprised the model would be to see the true label. If the model is confident and correct, the loss is tiny. If the model is confident and wrong, the loss is enormous. This shape is what makes gradient descent well-behaved here.

⚙️ Implementation — numerically safe cross-entropy

In practice, $\log(0)$ is undefined and $\log$ of a number near 0 can underflow. Deep-learning frameworks compute cross-entropy from the raw logits $z$ rather than the sigmoid output $\hat{y}$, using the numerically stable log-sum-exp trick. In NumPy, you should clip probabilities away from exactly 0 or 1:

# Safe cross-entropy in NumPy
epsilon = 1e-15
y_hat = np.clip(y_hat, epsilon, 1 - epsilon)
loss = -(y * np.log(y_hat) + (1 - y) * np.log(1 - y_hat))

4.3 The cost function over all examples

The cost $J(w,b)$ is the average loss across all $m$ training examples:

$$J(w, b) = \frac{1}{m} \sum_{i=1}^{m} L\!\left(\hat{y}^{(i)}, y^{(i)}\right) = -\frac{1}{m} \sum_{i=1}^{m} \left[ y^{(i)} \log \hat{y}^{(i)} + (1 - y^{(i)}) \log\!\left(1 - \hat{y}^{(i)}\right) \right]$$
The cost function for logistic regression — the average cross-entropy loss over the training set.

Here:

  • $m$ — the number of training examples.
  • $\hat{y}^{(i)} = \sigma(w^T x^{(i)} + b)$ — the model's prediction for example $i$.
  • $y^{(i)}$ — the true label of example $i$ (0 or 1).
💡 Insight — why average, not sum?

Taking the average makes the cost independent of dataset size. This matters for choosing a fixed learning rate: if the cost grew with $m$, the learning rate would need to shrink as the dataset grew. Averaging keeps the gradient scale roughly constant.

5. Gradient Descent

We now have a cost function $J(w, b)$. Training means finding values of $w$ and $b$ that make $J$ as small as possible. Gradient descent is the algorithm that does this.

🔵 Definition — Gradient Descent

Gradient descent is an iterative optimization algorithm that repeatedly nudges the parameters in the direction that reduces the cost the most, until the cost stops improving.

5.1 The update rules

Gradient descent repeatedly performs these two updates:

$$w := w - \alpha \frac{\partial J(w,b)}{\partial w}$$ $$b := b - \alpha \frac{\partial J(w,b)}{\partial b}$$
The gradient descent update rules. The partial derivatives $\partial J/\partial w$ and $\partial J/\partial b$ tell us the slope of the cost surface, and $\alpha$ controls step size.

Where:

  • $:=$ means assign (update the variable) — not equality.
  • $\alpha$ (alpha) — the learning rate, a positive hyperparameter controlling how big each step is.
  • $\partial J/\partial w$ — the gradient of the cost with respect to $w$: a vector pointing uphill.
  • $\partial J/\partial b$ — the gradient of the cost with respect to $b$: a scalar pointing uphill.
🟢 Intuition — why subtract the gradient?

The gradient points in the direction of steepest increase of $J$. To go downhill, we move in the opposite direction: we subtract the gradient. Geometrically, we roll the ball down the slope.

⭐ Key Idea — the meaning of the learning rate
  • Too small: training is slow (many tiny steps).
  • Too large: the algorithm may overshoot and diverge — the cost may even grow.
  • Just right: the cost decreases smoothly and reaches a minimum in reasonable time.

Choosing $\alpha$ is one of the most important practical skills in deep learning. It's usually tuned by trial and error on a logarithmic scale ($0.1, 0.03, 0.01, \ldots$).

6. Derivatives — Intuition

Gradient descent needs derivatives. Before diving into the algebra, let's build intuition for what a derivative is.

🔵 Definition — Derivative

The derivative of a function at a point is the slope of the tangent line to its graph at that point. Informally, it tells you: if I nudge the input slightly, how much does the output change?

6.1 A simple example — $f(a) = 3a$

Take the function $f(a) = 3a$. Its graph is a straight line.

  • At $a = 2$, $f(a) = 6$.
  • Nudge $a$ by $0.001$: $a = 2.001$, $f(a) = 6.003$.
  • Change in output: $0.003$; change in input: $0.001$.
  • Ratio: $0.003 / 0.001 = 3$.

So the slope — the derivative — is 3 at $a = 2$. And at $a = 5$, the same calculation gives $0.003 / 0.001 = 3$ again. Indeed, for a straight line the slope is constant everywhere.

$$f(a) = 3a \quad \Longrightarrow \quad \frac{d f(a)}{d a} = 3$$

6.2 A curved example — $f(a) = a^2$

At $a = 2$, $f(a) = 4$. Nudge: at $a = 2.001$, $f(a) \approx 4.004$. Ratio: $0.004 / 0.001 \approx 4$.

At $a = 5$, $f(a) = 25$. Nudge: at $a = 5.001$, $f(a) \approx 25.010$. Ratio: $0.010 / 0.001 = 10$.

The slope changes depending on where we are. Differentiating analytically:

$$f(a) = a^2 \quad \Longrightarrow \quad \frac{d f(a)}{d a} = 2a$$

Indeed, $2a = 4$ when $a = 2$, and $2a = 10$ when $a = 5$. ✓

🟢 Intuition — the formal definition

Formally, the derivative is defined as the limit of the ratio of a tiny output change to a tiny input change:

$$\frac{d f(a)}{d a} = \lim_{\varepsilon \to 0} \frac{f(a + \varepsilon) - f(a)}{\varepsilon}$$

For a straight line, this ratio is the same everywhere; for a curve, it varies — giving us a “slope function” rather than a single number.

⭐ Key Idea — why derivatives matter

In neural networks we want to know: if I slightly change a weight $w$, how much does the cost $J$ change? That quantity is $\partial J / \partial w$ — a derivative. Gradient descent uses it directly to update $w$.

7. Computation Graph

For neural networks, we could compute derivatives by hand — but it's tedious and error-prone. A computation graph gives us a clean, systematic way to do it.

🔵 Definition — Computation Graph

A computation graph is a directed graph in which each node represents a value or an operation. Information flows forward through the graph to compute a final output; derivatives flow backward through the graph (using the chain rule) to compute gradients.

7.1 A small worked example

Consider the function $J(a, b, c) = 3(a + bc)$. Let's compute it for $a = 5$, $b = 3$, $c = 2$.

Break the computation into steps:

  1. $u = b \cdot c = 3 \cdot 2 = 6$
  2. $v = a + u = 5 + 6 = 11$
  3. $J = 3 \cdot v = 3 \cdot 11 = 33$
🟢 Intuition

Think of the graph as a recipe with clearly separated steps. Each step is a simple operation (multiply, add, …). Because we know how to differentiate each simple step, we can chain them together to get derivatives of the whole function. This decomposition is what makes backpropagation possible.

💡 Insight — why this matters for neural networks

A neural network is a computation graph: nodes represent activations, edges represent weights and biases. The forward pass fills in activation values; the backward pass fills in gradients. Every framework (PyTorch, TensorFlow, JAX) builds on exactly this idea.

8. Derivatives with a Computation Graph

Now the key step: how do we compute $\frac{dJ}{da}$, $\frac{dJ}{db}$, $\frac{dJ}{dc}$ efficiently using the graph?

🔵 Definition — Chain Rule

The chain rule says: if $J$ depends on $v$, and $v$ depends on $a$, then the rate of change of $J$ with respect to $a$ is the product of the two rates:

$$\frac{dJ}{da} = \frac{dJ}{dv} \cdot \frac{dv}{da}$$

8.1 Backward pass on our graph

Recall the graph: $u = bc$, $v = a + u$, $J = 3v$ with values $a=5, b=3, c=2, u=6, v=11, J=33$.

Step 1 — derivative of $J$ with respect to itself. By convention, $\frac{dJ}{dJ} = 1$. This seeds the backward pass.

Step 2 — $\frac{dJ}{dv}$. Since $J = 3v$, the derivative is 3:

$$\frac{dJ}{dv} = 3$$

Step 3 — $\frac{dJ}{da}$. Using the chain rule through $v$:

$$\frac{dJ}{da} = \frac{dJ}{dv} \cdot \frac{dv}{da} = 3 \cdot 1 = 3$$

(Because $v = a + u$, $\frac{dv}{da} = 1$.)

Step 4 — $\frac{dJ}{du}$. Also through $v$:

$$\frac{dJ}{du} = \frac{dJ}{dv} \cdot \frac{dv}{du} = 3 \cdot 1 = 3$$

Step 5 — $\frac{dJ}{db}$ and $\frac{dJ}{dc}$. Since $u = b \cdot c$, we have $\frac{du}{db} = c = 2$ and $\frac{du}{dc} = b = 3$:

$$\frac{dJ}{db} = \frac{dJ}{du} \cdot \frac{du}{db} = 3 \cdot 2 = 6$$
$$\frac{dJ}{dc} = \frac{dJ}{du} \cdot \frac{du}{dc} = 3 \cdot 3 = 9$$
💡 Insight — the naming convention

Andrew uses dvar to denote $\frac{d(\text{final output})}{d(\text{var})}$. So da means $\frac{dJ}{da}$, db means $\frac{dJ}{db}$, etc. This naming is used in the coding assignments and in the logistic-regression derivation that follows.

🟢 Intuition — the backward flow

Think of the backward pass as a “responsibility” flow. The final cost $J$ is the output we care about. When we move backward, each node asks: “How much did I contribute to the change in $J$?” The chain rule multiplies these contributions along every path.

9. Logistic Regression Gradient Descent

Now we apply the computation-graph method to logistic regression. The graph for one example is:

$$z = w^T x + b, \quad a = \sigma(z), \quad L(a, y) = -\left[ y \log(a) + (1 - y)\log(1-a) \right]$$

9.1 Building the backward pass

We want $\frac{\partial L}{\partial w_1}$, $\frac{\partial L}{\partial w_2}$, and $\frac{\partial L}{\partial b}$ for a two-feature example ($n_x = 2$). Using the chain rule backwards through the graph:

Step 1 — $\frac{dL}{da}$. Differentiate the loss with respect to $a$:

$$\frac{dL}{da} = -\frac{y}{a} + \frac{1-y}{1-a}$$

Step 2 — $\frac{da}{dz}$. The derivative of the sigmoid is a beautiful expression:

$$\frac{da}{dz} = a(1-a)$$
🟣 Where does $\sigma'(z) = \sigma(z)(1-\sigma(z))$ come from?

Start with $\sigma(z) = (1 + e^{-z})^{-1}$. Using the chain rule:

$$\frac{d\sigma}{dz} = -(1 + e^{-z})^{-2} \cdot (-e^{-z}) = \frac{e^{-z}}{(1 + e^{-z})^2}$$

Now note that $\sigma(z) = \frac{1}{1+e^{-z}}$ and $1 - \sigma(z) = \frac{e^{-z}}{1+e^{-z}}$. Multiplying:

$$\sigma(z)(1-\sigma(z)) = \frac{1}{1+e^{-z}} \cdot \frac{e^{-z}}{1+e^{-z}} = \frac{e^{-z}}{(1+e^{-z})^2} = \frac{d\sigma}{dz}$$

Therefore $\sigma'(z) = \sigma(z)(1 - \sigma(z)) = a(1 - a)$. This is one of the most important identities in deep learning.

Step 3 — $\frac{dL}{dz}$. Chain the two:

$$\frac{dL}{dz} = \frac{dL}{da} \cdot \frac{da}{dz} = \left( -\frac{y}{a} + \frac{1-y}{1-a} \right) \cdot a(1-a)$$

Let's simplify this carefully. Expand:

$$= -\frac{y}{a} \cdot a(1-a) + \frac{1-y}{1-a} \cdot a(1-a) = -y(1-a) + a(1-y)$$
$$= -y + ay + a - ay = a - y$$
⭐ Key Idea — the famous simplification
$$\boxed{\frac{dL}{dz} = a - y}$$

This is one of the most elegant results in deep learning: the gradient of the loss with respect to $z$ is simply the prediction minus the true label. This “clean” form is one reason cross-entropy plus sigmoid is the standard pairing.

Step 4 — $\frac{\partial L}{\partial w_j}$ and $\frac{\partial L}{\partial b}$. Since $z = w^T x + b = \sum_j w_j x_j + b$, we have $\frac{\partial z}{\partial w_j} = x_j$ and $\frac{\partial z}{\partial b} = 1$. So:

$$\frac{\partial L}{\partial w_j} = x_j \cdot (a - y), \quad \frac{\partial L}{\partial b} = a - y$$

9.2 The update rules

With the gradients in hand, the parameter updates are:

$$w_j := w_j - \alpha \cdot x_j \cdot (a - y)$$ $$b := b - \alpha \cdot (a - y)$$
🟢 Intuition — what the update is telling us

The quantity $a - y$ is the “error.” If the prediction matches the label exactly, $a - y = 0$ and no update occurs. If the prediction is too high ($a > y$), we nudge each weight $w_j$ in the opposite direction of $x_j$; if too low, in the direction of $x_j$. The magnitude of the update scales with the feature value $x_j$ and the learning rate $\alpha$.

10. Gradient Descent on m Examples

So far we derived gradients for one example. Real training uses the whole dataset. The cost over all examples is:

$$J(w, b) = \frac{1}{m} \sum_{i=1}^{m} L\!\left(a^{(i)}, y^{(i)}\right)$$

Because the derivative of a sum is the sum of derivatives, the gradient of $J$ is the average of the per-example gradients:

$$\frac{\partial J}{\partial w_j} = \frac{1}{m} \sum_{i=1}^{m} x_j^{(i)} \cdot (a^{(i)} - y^{(i)})$$ $$\frac{\partial J}{\partial b} = \frac{1}{m} \sum_{i=1}^{m} (a^{(i)} - y^{(i)})$$

10.1 The naive (loop-based) algorithm

Here is the straightforward way to implement one gradient-descent step:

# Pseudocode for one gradient descent step (non-vectorized)
J = 0;  dw1 = 0;  dw2 = 0;  db = 0

for i = 1 to m:
    z[i]  = w1 * x1[i] + w2 * x2[i] + b
    a[i]  = sigmoid(z[i])
    J    += -[ y[i]*log(a[i]) + (1-y[i])*log(1-a[i]) ]
    dz[i] = a[i] - y[i]
    dw1  += x1[i] * dz[i]
    dw2  += x2[i] * dz[i]
    db   += dz[i]

J   /= m
dw1 /= m
dw2 /= m
db  /= m

w1 := w1 - alpha * dw1
w2 := w2 - alpha * dw2
b  := b  - alpha * db
🔴 Warning — this is slow

If $n_x = 12{,}288$ (our cat image) and $m = 1{,}000{,}000$ (a large dataset), the code above executes billions of operations per gradient-descent iteration. In Python, this is prohibitively slow. The fix is vectorization — the subject of Section 11.

💡 Insight

Andrew's pedagogical strategy here is deliberate: first show the loop version so you understand the math, then show the vectorized version so you understand the engineering. Both compute the same thing; the difference is speed. You should always write the vectorized version in practice.

11. Vectorization

🔵 Definition — Vectorization

Vectorization is the practice of replacing explicit Python for loops with array operations (using NumPy, for example), so that the heavy lifting is done by highly optimized, parallelized low-level code (BLAS, SIMD, GPU kernels).

🟢 Intuition — why vectorization is faster

Modern CPUs and GPUs can perform the same arithmetic operation on many numbers simultaneously — this is called SIMD (Single Instruction, Multiple Data). A vectorized operation like np.dot(w, x) exploits SIMD; a Python for loop does not, because each iteration carries Python interpreter overhead. The speed difference can be two orders of magnitude or more.

11.1 A small numeric example

Compute $z = w^T x + b$ where $w, x \in \mathbb{R}^n$, say $n = 1{,}000{,}000$.

Non-vectorized:

z = 0
for i in range(n):
    z += w[i] * x[i]
z += b

Vectorized:

import numpy as np
z = np.dot(w, x) + b

Both compute the same number. On a typical CPU, the vectorized version is roughly 300× faster.

⚙️ Implementation — SIMD in one line

The single instruction z = np.dot(w, x) gets translated into machine-level vector operations that process multiple elements per clock cycle. On GPUs, thousands of threads each work on a different element simultaneously.

11.2 Guidelines and common NumPy functions

⭐ Neural-network programming guideline

Whenever possible, avoid explicit for-loops. Almost every quantity you compute in a neural network — dot products, element-wise functions, sums, maxima — has a vectorized NumPy equivalent that is both cleaner and dramatically faster.

🔴 Warning — still need some loops

The “no for-loops” rule refers to iterating over training examples or features. You will still use a loop over the gradient-descent iterations (typically a few thousand). That's fine — the loop is over iterations, not over examples.

12. Vectorizing Logistic Regression

Here is where the notation from Section 2 pays off. Recall we stacked the training examples as columns of a matrix $X \in \mathbb{R}^{n_x \times m}$.

12.1 The forward pass

For all $m$ examples simultaneously:

$$Z = w^T X + b$$

What shape is $Z$? Since $w^T$ is $1 \times n_x$ and $X$ is $n_x \times m$, their product is $1 \times m$. Adding $b$ (a scalar) broadcasts, giving a $1 \times m$ row vector:

$$Z = \begin{bmatrix} z^{(1)} & z^{(2)} & \cdots & z^{(m)} \end{bmatrix}$$

Then, applying the sigmoid element-wise:

$$A = \sigma(Z) = \begin{bmatrix} a^{(1)} & a^{(2)} & \cdots & a^{(m)} \end{bmatrix}$$
⚙️ Implementation — the forward pass in two lines
Z = np.dot(w.T, X) + b     # b is a scalar, broadcasts to (1, m)
A = sigmoid(Z)             # element-wise; A has shape (1, m)

No Python loop over examples. Compare with the loop version — this is the reason deep learning can scale to massive datasets.

💡 Insight

Note the elegant role of broadcasting: the single scalar $b$ is automatically replicated to shape $(1, m)$ when added to $w^T X$. This is why we keep $b$ as a separate scalar instead of fusing it into $w$ via an extra “$x_0 = 1$” feature. Both work; the course convention is cleaner for vectorization.

13. Vectorizing the Gradient Computation

The gradient computation also vectorizes beautifully.

13.1 The key quantity: $dZ$

Recall that for one example, $dz^{(i)} = a^{(i)} - y^{(i)}$. Stacking all examples as columns:

$$dZ = A - Y = \begin{bmatrix} a^{(1)} - y^{(1)} & a^{(2)} - y^{(2)} & \cdots & a^{(m)} - y^{(m)} \end{bmatrix}$$

This is a $1 \times m$ row vector — one gradient contribution per example.

13.2 The gradient with respect to $w$

Recall the non-vectorized formula:

$$dw_j = \frac{1}{m} \sum_{i=1}^{m} x_j^{(i)} \cdot dz^{(i)}$$

Vectorized, this becomes a matrix-vector product:

$$dw = \frac{1}{m} X \, dZ^T$$

Let's verify the shapes:

  • $X$ is $n_x \times m$.
  • $dZ^T$ is $m \times 1$.
  • Their product is $n_x \times 1$ — exactly the shape of $dw$. ✓

13.3 The gradient with respect to $b$

For the bias, we sum all $dz^{(i)}$ and divide by $m$:

$$db = \frac{1}{m} \sum_{i=1}^{m} dz^{(i)} = \frac{1}{m} \texttt{np.sum}(dZ)$$
⚙️ Implementation — the full vectorized iteration
for iter in range(num_iterations):
    # Forward pass
    Z = np.dot(w.T, X) + b
    A = sigmoid(Z)

    # Backward pass
    dZ = A - Y                              # shape (1, m)
    dw = (1 / m) * np.dot(X, dZ.T)          # shape (n_x, 1)
    db = (1 / m) * np.sum(dZ)              # scalar

    # Update
    w = w - alpha * dw
    b = b - alpha * db

That's the entire logistic-regression training loop — no loop over examples, no loop over features. Each iteration handles all $m$ examples and all $n_x$ features at once.

🔴 Common Mistake — dimension checks

Shape bugs are the #1 source of frustration in deep-learning code. Always check X.shape, Z.shape, dZ.shape when debugging. For logistic regression with one output: X.shape = (n_x, m), w.shape = (n_x, 1), Z.shape = (1, m), A.shape = (1, m), dZ.shape = (1, m), dw.shape = (n_x, 1).

14. Broadcasting in Python

🔵 Definition — Broadcasting

Broadcasting is NumPy's rule for performing arithmetic between arrays of different shapes. When the shapes are compatible, NumPy “stretches” the smaller array to match the larger one without copying data explicitly.

14.1 The general rule

When you perform an operation between two arrays, NumPy compares their shapes from the trailing dimension. Two dimensions are compatible if:

  • They are equal, or
  • One of them is 1.

The smaller dimension is then stretched to match the larger one.

OperationShapesResult
Matrix + vector$(m, n) + (1, n)$$(m, n)$ — vector is duplicated across rows
Matrix + column$(m, n) + (m, 1)$$(m, n)$ — column is duplicated across columns
Matrix + scalar$(m, n) + \mathbb{R}$$(m, n)$ — scalar is added to every entry
Row + column$(1, n) + (m, 1)$$(m, n)$ — both are stretched

14.2 A worked example — calorie percentages

Suppose we have a table $A$ of grams of carbohydrate, protein, and fat per 100g of four foods (Apples, Beef, Eggs, Potatoes). Shape: $3 \times 4$.

We want to compute, for each food, what percentage of total calories comes from each macronutrient.

A = np.array([
    [56.0,  0.0,   4.4,  68.0],  # carbs
    [ 1.2, 104.0, 52.0,  8.0],  # protein
    [ 1.8, 135.0, 99.0,  0.9],  # fat
])   # shape (3, 4)

cal = A.sum(axis=0)          # shape (4,)   → [59.0, 239.0, 155.4, 76.9]
percentage = 100 * A / cal      # (3,4) / (4,) → broadcasts the (4,) row across rows

NumPy broadcasts the shape-$(4,)$ vector cal into a shape-$(1, 4)$ row and divides every row of $A$ by it. The result is a $(3, 4)$ matrix of percentages.

14.3 Another worked example — adding a row

Consider adding the row vector $[100, 200, 300]$ (shape $(1,3)$) to the matrix:

$$\begin{bmatrix} 1 & 2 & 3 \\ 4 & 5 & 6 \end{bmatrix} + \begin{bmatrix} 100 & 200 & 300 \end{bmatrix} = \begin{bmatrix} 101 & 202 & 303 \\ 104 & 205 & 306 \end{bmatrix}$$

The row vector is stretched vertically (replicated once per row) to match the matrix shape. This is exactly what happens when we compute $w^T X + b$: the scalar $b$ is broadcast to every column.

14.4 A final example — adding a scalar

$$\begin{bmatrix} 1 \\ 2 \\ 3 \\ 4 \end{bmatrix} + 100 = \begin{bmatrix} 101 \\ 102 \\ 103 \\ 104 \end{bmatrix}$$
🔴 Warning — silent broadcasting bugs

If you accidentally use a shape like $(m,)$ instead of $(m, 1)$ for a column vector, NumPy may still broadcast it — but in the wrong direction, producing silently wrong results. Always use explicit reshape(-1, 1) or keepdims=True when a specific rank is intended. This is one of the most common mistakes in deep-learning code.

⚙️ Implementation — checking shapes
# Use assertions to catch shape bugs early
assert w.shape == (n_x, 1)
assert b.shape == () or b.shape == (1,)

# Force a column vector explicitly
v = v.reshape(-1, 1)

# Force a row vector explicitly
v = v.reshape(1, -1)

15. Why the Cost Function Looks Like That (Maximum Likelihood)

This section explains where the cross-entropy loss comes from. It is labeled optional in the course, but it's worth understanding once — it demystifies the formula.

15.1 Logistic regression as a probabilistic model

Logistic regression outputs a probability: $\hat{y} = P(y = 1 \mid x)$. From this, we can write down the probability of either outcome:

  • If $y = 1$: $P(y \mid x) = \hat{y}$
  • If $y = 0$: $P(y \mid x) = 1 - \hat{y}$

These two cases can be combined into a single formula:

$$P(y \mid x) = \hat{y}^{\,y} \, (1 - \hat{y})^{\,1 - y}$$
A compact expression that gives $\hat{y}$ when $y=1$ and $1-\hat{y}$ when $y=0$.
🟣 Verify the formula
  • If $y=1$: $\hat{y}^{1}(1-\hat{y})^{0} = \hat{y} \cdot 1 = \hat{y}$. ✓
  • If $y=0$: $\hat{y}^{0}(1-\hat{y})^{1} = 1 \cdot (1-\hat{y}) = 1-\hat{y}$. ✓

15.2 Maximum likelihood estimation

Since the training examples are assumed independent, the probability of observing the entire training set's labels is the product:

$$P(\text{all labels}) = \prod_{i=1}^{m} P\!\left(y^{(i)} \mid x^{(i)}\right)$$

Maximum likelihood estimation (MLE) says: choose the parameters $w, b$ that make the observed data as likely as possible. Maximizing a product is awkward, so we take the logarithm (monotonic, so it doesn't change the argmax) — turning products into sums:

$$\log P(\text{all labels}) = \sum_{i=1}^{m} \log P\!\left(y^{(i)} \mid x^{(i)}\right)$$

Substituting $P(y^{(i)}|x^{(i)}) = \hat{y}^{(i)\,y^{(i)}}(1-\hat{y}^{(i)})^{1-y^{(i)}}$:

$$\log P = \sum_{i=1}^{m} \left[ y^{(i)} \log \hat{y}^{(i)} + (1 - y^{(i)}) \log(1 - \hat{y}^{(i)}) \right]$$

Maximizing the log-likelihood is equivalent to minimizing its negative, divided by $m$ for convenience:

$$J(w, b) = -\frac{1}{m} \sum_{i=1}^{m} \left[ y^{(i)} \log \hat{y}^{(i)} + (1 - y^{(i)}) \log(1 - \hat{y}^{(i)}) \right]$$
💡 Insight — so the cost function is a likelihood

The cross-entropy cost we've been using all along is simply the negative log-likelihood of the training data. Minimizing it means finding parameters that make the observed labels most probable. This connection shows the loss isn't arbitrary — it falls out naturally from the probabilistic interpretation of logistic regression.

⭐ Key Idea — convexity

Thanks to the log-likelihood form, $J(w, b)$ is a convex function of $w$ and $b$. That means gradient descent will find the global minimum without getting stuck. (Deep networks lose this guarantee, but the intuition still guides us.)

16. Common Mistakes & Clarifications

🔴 Mistake 1 — Confusing $(i)$ with $[l]$

$(i)$ in parentheses = the $i$-th example; $[l]$ in brackets = the $l$-th layer. Mixing these up is a classic beginner error.

🔴 Mistake 2 — Writing $X$ as $m \times n_x$ instead of $n_x \times m$

In this specialization, columns are examples. Writing $X$ with $m$ rows causes every subsequent matrix multiplication to have the wrong shape.

🔴 Mistake 3 — Using squared error for logistic regression

Squared error produces a non-convex cost for logistic regression. Always use cross-entropy (binary cross-entropy for $y \in \{0,1\}$).

🔴 Mistake 4 — Forgetting that $dz = a - y$

This simplification is what makes logistic regression so clean. If you derive the gradient by hand and get a messy expression, you've probably missed the sigmoid-derivative identity $\sigma'(z) = a(1-a)$ that collapses everything.

🔴 Mistake 5 — Getting the sign of the gradient wrong

Gradient descent subtracts the gradient: $w := w - \alpha \cdot dw$. If you accidentally add, the cost will grow instead of shrinking.

🔴 Mistake 6 — Blindly trusting broadcasting

NumPy will happily broadcast shapes that don't mean what you intended. Use explicit reshape and assert statements to catch bugs early.

🔴 Mistake 7 — Thinking vectorization changes the math

Vectorization does not change what is computed, only how fast. The loop version and vectorized version produce identical numbers (up to floating-point rounding).

🔴 Mistake 8 — Using “$y$” and “$\hat{y}$” interchangeably

$y$ is the ground-truth label; $\hat{y}$ is the model's prediction. The loss compares the two. Mixing them up makes every equation meaningless.

17. Weekly Summary & Review

📌 Weekly Summary

1. Binary classification. Problems where $y \in \{0,1\}$. Images are stored as pixel intensities across RGB channels and unrolled into a feature vector $x \in \mathbb{R}^{n_x}$.

2. Notation. $(i)$ = $i$-th example; $[l]$ = $l$-th layer. $X \in \mathbb{R}^{n_x \times m}$ has examples as columns. $W^{[l]}$, $b^{[l]}$ are the parameters of layer $l$. $\hat{y} = a^{[L]}$.

3. Logistic regression. $\hat{y} = \sigma(w^T x + b)$ with $\sigma(z) = 1/(1+e^{-z})$. Sigmoid squashes any real number into $(0, 1)$, giving a probability.

4. Cost function. Loss per example: $L(\hat{y}, y) = -[y\log\hat{y} + (1-y)\log(1-\hat{y})]$. Cost over all examples: $J(w,b) = \frac{1}{m}\sum L(\hat{y}^{(i)}, y^{(i)})$.

5. Gradient descent. Repeatedly update $w := w - \alpha\,\partial J/\partial w$ and $b := b - \alpha\,\partial J/\partial b$. The learning rate $\alpha$ controls step size.

6. Derivatives. Slope of a function at a point. Key identities: $\frac{d}{da}(a^2) = 2a$, $\frac{d}{da}\ln(a) = 1/a$, and for sigmoid $\sigma'(z) = \sigma(z)(1-\sigma(z))$.

7. Computation graph. A directed graph that breaks a complex computation into simple steps. The forward pass computes values; the backward pass uses the chain rule to compute gradients.

8. Backprop for logistic regression. $da = -y/a + (1-y)/(1-a)$, $dz = a - y$, $dw_j = x_j \cdot dz$, $db = dz$.

9. Vectorization. Replace explicit loops with array operations. Forward pass: $Z = w^T X + b$, $A = \sigma(Z)$. Backward pass: $dZ = A - Y$, $dw = \frac{1}{m}X dZ^T$, $db = \frac{1}{m}\texttt{sum}(dZ)$.

10. Broadcasting. NumPy stretches smaller arrays along size-1 dimensions. Know the rules; use explicit shapes to avoid bugs.

11. Origin of the cost. Cross-entropy is the negative log-likelihood of the training data. Minimizing it = maximum likelihood estimation.

📝 Quick Review (Click to Reveal Answers)

Why is the feature vector for a 64×64 RGB image of length 12,288?
Because the image has 64 × 64 = 4,096 pixels, and each pixel has 3 color channels (R, G, B), so 4,096 × 3 = 12,288 numbers are unrolled into the feature vector $x$.
What is the difference between $(i)$ and $[l]$ in the notation?
$(i)$ refers to the $i$-th training example. $[l]$ refers to the $l$-th layer of the neural network.
What shape is the input matrix $X$, and why?
$X \in \mathbb{R}^{n_x \times m}$ — each column is a training example. This makes vectorized computations across all $m$ examples work cleanly via matrix multiplication.
What does the sigmoid function do, and why is it used in logistic regression?
The sigmoid maps any real number to the interval $(0, 1)$. It is used because logistic regression predicts a probability, which must lie between 0 and 1, while $w^T x + b$ can be any real number.
Write the binary cross-entropy loss for one example.
$L(\hat{y}, y) = -[y \log \hat{y} + (1-y) \log(1-\hat{y})]$.
Why use cross-entropy instead of squared error for logistic regression?
Squared error makes the cost function non-convex with respect to the parameters, leading to multiple local minima and unreliable gradient descent. Cross-entropy produces a convex cost surface for logistic regression.
What is the cost function $J(w, b)$?
The average of the loss over all $m$ training examples: $J(w,b) = \frac{1}{m}\sum_{i=1}^{m} L(\hat{y}^{(i)}, y^{(i)})$.
Write the gradient descent update rules for $w$ and $b$.
$w := w - \alpha \frac{\partial J}{\partial w}$, and $b := b - \alpha \frac{\partial J}{\partial b}$.
What happens if the learning rate α is too large? Too small?
Too large: gradient descent may overshoot and diverge — cost may grow. Too small: training is very slow, requiring many iterations.
What does the derivative of a function tell you, intuitively?
It tells you the slope of the function at a point — how much the output changes for a small change in the input.
State the chain rule.
If $J$ depends on $v$ and $v$ depends on $a$, then $\frac{dJ}{da} = \frac{dJ}{dv} \cdot \frac{dv}{da}$.
In the computation graph for $J = 3(a + bc)$, what is $\frac{dJ}{db}$ at $a=5, b=3, c=2$?
$\frac{dJ}{db} = \frac{dJ}{du} \cdot \frac{du}{db} = 3 \cdot c = 3 \cdot 2 = 6$. Alternatively, $J = 3(a + bc) = 3a + 3bc$, so $\partial J/\partial b = 3c = 6$. ✓
What is $\sigma'(z)$ in terms of the sigmoid output $a = \sigma(z)$?
$\sigma'(z) = a(1-a)$.
Derive $dz = a - y$ for logistic regression.
$\frac{dL}{da} = -\frac{y}{a} + \frac{1-y}{1-a}$ and $\frac{da}{dz} = a(1-a)$. Multiply: $\frac{dL}{dz} = (-\frac{y}{a} + \frac{1-y}{1-a}) \cdot a(1-a) = -y(1-a) + a(1-y) = -y + ay + a - ay = a - y$.
What is the per-example gradient of the loss with respect to weight $w_j$?
$\frac{\partial L}{\partial w_j} = x_j \cdot (a - y)$.
Why is vectorization so important in deep learning?
It replaces slow Python loops with SIMD-optimized array operations that run 100–300× faster on CPUs and even faster on GPUs, making it feasible to train on large datasets.
Write the vectorized formulas for the forward pass of logistic regression.
$Z = w^T X + b$ (shape $(1, m)$), then $A = \sigma(Z)$ (element-wise, also shape $(1, m)$).
Write the vectorized formulas for the gradient computation.
$dZ = A - Y$, $dw = \frac{1}{m} X\, dZ^T$, and $db = \frac{1}{m} \texttt{np.sum}(dZ)$.
What does NumPy broadcasting do when adding a $(m, n)$ matrix and a $(1, n)$ row vector?
It stretches the row vector vertically to shape $(m, n)$ by replicating it $m$ times, then adds element-wise.
What does NumPy broadcasting do when adding a $(m, n)$ matrix and a scalar?
It adds the scalar to every entry of the matrix, effectively broadcasting it to shape $(m, n)$.
What is the probabilistic interpretation of the logistic regression cost?
The cross-entropy cost is the negative log-likelihood of the training data. Minimizing it is equivalent to maximum likelihood estimation — finding the parameters that make the observed labels most likely.
Why is the logistic-regression cost convex?
Because it corresponds to the negative log-likelihood of a probabilistic model with a linear parameterization inside a sigmoid — a structure that is convex in $w$ and $b$.

🧠 Self-Test (Conceptual)

You notice that during training, the cost is decreasing but very slowly. What would you check first?
The learning rate α. If it's too small, training will be slow. Try increasing α by a factor of 3 or 10 and observe. Also check that gradients are computed correctly — a bug that causes small gradients will produce the same symptom.
Your cost is oscillating wildly instead of decreasing smoothly. What's likely wrong?
The learning rate is probably too large, causing the updates to overshoot the minimum. Try reducing α by a factor of 3 or 10.
Someone says “I'll just use squared error for logistic regression — it's simpler.” Why is that a bad idea?
Because squared error yields a non-convex cost surface for logistic regression, so gradient descent is unreliable. Cross-entropy gives a convex cost with a single global minimum, and it also has cleaner gradients ($dz = a - y$).
Suppose you vectorize your code but forget to divide $dw$ by $m$. What will happen to training?
The gradient will be $m$ times too large. This effectively multiplies the learning rate by $m$, likely causing divergence (cost explodes) or chaotic updates. Always average over examples.
You have a shape error where $X$ is $(m, n_x)$ instead of $(n_x, m)$. What goes wrong?
The matrix multiplication $w^T X$ will either fail (incompatible shapes) or produce a wrong-shaped output, and the per-example gradient averaging will be over the wrong axis. This is why checking shapes is essential.
Explain in plain language why the backward pass in a computation graph computes the same derivatives as doing calculus by hand.
Because the chain rule guarantees that the product of local derivatives along a path equals the derivative of the composite function. The backward pass simply organizes the chain rule systematically, node by node, so that many derivatives can be computed efficiently in one pass.
If your sigmoid outputs exactly 0 or 1, what problem might you encounter in the loss computation?
$\log(0)$ is $-\infty$ (or NaN in floating point), so the loss becomes undefined or infinite. In practice, frameworks clip probabilities away from 0 and 1, or compute cross-entropy directly from logits using a numerically stable log-sum-exp formula.
Why does the course keep b separate from w instead of folding it into an “extra input $x_0 = 1$”?
Both are mathematically equivalent, but keeping $b$ separate is cleaner for vectorization: $Z = w^T X + b$ broadcasts a scalar. Folding $b$ into $w$ would require adding a row of 1s to $X$ at every iteration, which is less efficient and more error-prone.
