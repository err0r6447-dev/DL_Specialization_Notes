1. Why This Week Matters

Up to now you have learned how to build a neural network and how to train it with backpropagation. That is the mechanics. This week is about the craft: how do you actually get a deep network to perform well on real data?

💡 Insight Training a deep network is not a single step — it is a highly iterative process. You repeatedly form an idea (a hypothesis about what might improve the model), write code, run an experiment, look at the results, and adjust. The practical techniques in this week are what let you make those adjustments efficiently instead of blindly guessing.
🔵 Definition Hyperparameter — a setting you choose before training that controls how the model learns. Examples: number of layers, number of hidden units per layer, learning rate, choice of activation function, regularization strength. Unlike weights, these are not learned from data; you tune them by running experiments.

2. Train / Dev / Test Sets

2.1 The problem

You train a model on some data. How do you know if it will work on data it has never seen? If you only measure performance on the data you trained on, the model might simply memorize the training examples and fail on new ones. We need a way to estimate how well the model will do in the real world.

2.2 The three-way split

The standard solution is to divide your dataset into three parts:

SetPurposeWho uses it
Training set The model learns its weights from this data (via gradient descent). The learning algorithm
Dev set (development set / hold-out cross-validation set) Used to tune hyperparameters, choose between model variants, and diagnose bias/variance. You, the developer
Test set Used once at the very end to give an unbiased estimate of final performance. Final evaluation only
🟣 Example — choosing split sizes

Suppose you have 1,000,000 images. A reasonable split:

  • Training: 980,000 (98%)
  • Dev: 10,000 (1%)
  • Test: 10,000 (1%)

With 10,000 images instead, a 60/20/20 split gives dev = 2,000 and test = 2,000, which is appropriate because you need a large enough dev set to distinguish small differences in performance.

🟡 Important The dev set and test set must come from the same distribution. If they don't, you are effectively measuring two different things, and the dev set stops being a reliable proxy for test performance. We will discuss this in the next section.
🔴 Warning — common mistake A frequent beginner error is to make the dev set so small that it cannot distinguish between two models whose accuracies differ by less than 1%. If your dev set has only 100 examples, a 1% difference is just one example — pure noise. Choose dev/test sizes large enough to give statistically meaningful results.

3. Mismatched Train/Test Distribution

In many real projects, the data you have for training and the data your model will actually see in production come from different sources. This is called mismatched distribution.

🟣 Example — the cat classifier

You are building a cat classifier. Your training set consists of high-quality cat photos scraped from webpages. But your app's users will upload photos taken with their phones — blurry, poorly lit, at odd angles. These two groups of images have different distributions: different resolution, lighting, composition, etc.

3.1 The rule

🟡 Important — Andrew Ng's guideline Make sure the dev and test sets come from the same distribution. The training set can come from a different (usually larger, more varied) source, but dev and test must match each other.

Why? Because the dev set is your target. You tune hyperparameters to do well on the dev set, and you use the test set to confirm that performance. If dev and test are drawn from different distributions, you optimize for one thing and are evaluated on another.

3.2 What if you don't have enough data for a test set?

If you have very little data, it may be acceptable to have only a dev set and no test set. In that case, the dev set serves both as the tuning set and the final evaluation set. This is a pragmatic compromise; it slightly biases your final estimate, but it is better than having no evaluation at all.

4. Bias and Variance

Bias and variance are the two fundamental ways a model can fail. Understanding them is the key to diagnosing what is wrong with your network and choosing the right fix.

4.1 Intuition with a picture

🔵 Definition — Bias Bias is the error introduced by approximating a complex real-world problem with a simplified model. A high-bias model is too simple to capture the underlying structure. It performs poorly on the training set (it "underfits").
🔵 Definition — Variance Variance is the error introduced by the model's sensitivity to small fluctuations in the training data. A high-variance model is too complex, fitting noise and idiosyncrasies of the training set. It performs well on the training set but poorly on new data (it "overfits").

4.2 Diagnosing bias and variance from errors

In the era of modern deep learning, we usually diagnose bias and variance by comparing training set error and dev set error, and comparing both against human-level error (also called "optimal" or "Bayes" error).

🔵 Definition — Base / Human-level / Bayes error Base error is the lowest achievable error on the task. It is often approximated by human-level performance. If a human can classify cat pictures with 1% error, then 1% is the base error — even a perfect model cannot do better than that because the remaining 1% is genuinely ambiguous.
ScenarioTrain errorDev errorBase errorDiagnosis
A1%11%0%High variance
B15%16%0%High bias
C15%30%0%High bias and high variance
D0.5%1%0%Low bias, low variance
E15%16%15%Low bias, low variance (base error is 15%)
F15%30%15%High variance only
🟡 Important — how to read the table
  • Bias is measured by how far training error is above base error.
  • Variance is measured by how far dev error is above training error.
  • Base error matters: 15% training error sounds terrible, but if human error is also 15%, your model is actually doing as well as possible.

4.3 High bias and high variance simultaneously

In the pre-deep-learning era, people assumed bias and variance traded off against each other — reducing one increased the other. In deep learning, this is no longer always true. A very deep network can be complex enough to fit most of the training data (low bias) while still being sensitive to noise in certain regions (high variance). Scenario C above shows this: 15% training error (high bias) and 30% dev error (high variance) at the same time.

5. Basic Recipe for Machine Learning

Once you have diagnosed bias and variance, there is a standard procedure — a "recipe" — for improving the model.

💡 Insight Notice that the recipe is a loop, not a straight line. Modern deep learning lets us reduce bias without necessarily increasing variance (bigger networks, better architectures), and reduce variance without necessarily increasing bias (regularization, more data). The old "bias-variance tradeoff" is much weaker than it used to be.
⚙️ Implementation — practical order of operations
  1. Train the model and measure training error.
  2. If training error is high compared to base error → high bias. Try a bigger network (more layers / more units), train longer, or use a better architecture (e.g. different activation functions).
  3. If training error is acceptable but dev error is much higher → high variance. Try more training data, regularization (L2, dropout), or a better architecture.
  4. If both are acceptable → you're done. Optionally try to squeeze more performance, but be careful not to overfit the dev set.

6. Regularization — L2 and L1

6.1 What is regularization?

🔵 Definition Regularization is any technique that constrains the model's capacity in order to reduce overfitting (variance) without sacrificing the ability to fit the training data. It typically works by adding a penalty term to the cost function that discourages large parameter values.
🟢 Intuition Imagine fitting a curve through data points. If you allow the curve to be arbitrarily wiggly, it can pass through every point exactly — but it will look nothing like the true underlying trend. Regularization is like telling the curve: "You may fit the data, but I will charge you for every wiggle." The model then prefers simpler solutions that still explain the data.

6.2 Logistic regression with L2 regularization

Recall the standard logistic regression cost function:

\[ J(w,b) = \frac{1}{m}\sum_{i=1}^{m} \mathcal{L}\!\left(y^{(i)}, \hat{y}^{(i)}\right) \]

where \(m\) is the number of training examples, \(y^{(i)}\) is the true label of example \(i\), and \(\hat{y}^{(i)}\) is the predicted probability.

With L2 regularization, we add a penalty on the squared magnitude of the weights:

\[ J(w,b) = \frac{1}{m}\sum_{i=1}^{m} \mathcal{L}\!\left(y^{(i)}, \hat{y}^{(i)}\right) \;+\; \frac{\lambda}{2m}\sum_{j=1}^{n_x} w_j^2 \]

Symbol-by-symbol:

  • \(\lambda\) — the regularization parameter (a hyperparameter you choose; larger \(\lambda\) means stronger regularization).
  • \(m\) — number of training examples.
  • \(n_x\) — number of features (dimension of the input vector \(x\)).
  • \(w_j\) — the \(j\)-th component of the weight vector \(w\).
  • \(\sum_j w_j^2\) — the squared L2 norm of the weight vector, also written \(\|w\|_2^2 = w^T w\).
🟡 Important — why divide by \(2m\)? The \(2m\) factor is a mathematical convenience. When we differentiate the penalty \(\frac{\lambda}{2m}\|w\|^2\), the \(2\) cancels with the derivative of the square, and the \(m\) matches the scaling of the data term. This makes the update equations clean.

6.3 L1 regularization

Instead of squaring the weights, L1 regularization penalizes their absolute values:

\[ J(w,b) = \frac{1}{m}\sum_{i=1}^{m} \mathcal{L}\!\left(y^{(i)}, \hat{y}^{(i)}\right) \;+\; \frac{\lambda}{2m}\sum_{j=1}^{n_x} |w_j| \]

Equivalently, with \(\|w\|_1 = \sum_j |w_j|\):

\[ J(w,b) = \frac{1}{m}\sum_{i=1}^{m} \mathcal{L}(y^{(i)}, \hat{y}^{(i)}) + \frac{\lambda}{2m}\|w\|_1 \]
🟡 Important — L1 makes weights sparse L1 regularization tends to drive many weights exactly to zero. This makes the model sparse — useful if you suspect only a few features matter and you want an implicit form of feature selection. L2 regularization shrinks weights smoothly but rarely sets them exactly to zero.

6.4 The bias term is usually not regularized

Notice that neither penalty includes \(b\). In practice, regularizing the bias has negligible effect because there is only one bias parameter per neuron, whereas there are many weights. Most implementations leave \(b\) unregularized.

6.5 Regularization in a neural network

For a deep network, the L2 penalty is applied to the weight matrices of every layer. The cost function becomes:

\[ J(W^{[1]}, b^{[1]}, \dots, W^{[L]}, b^{[L]}) = \frac{1}{m}\sum_{i=1}^{m} \mathcal{L}\!\left(y^{(i)}, \hat{y}^{(i)}\right) \;+\; \frac{\lambda}{2m}\sum_{l=1}^{L}\left\|W^{[l]}\right\|_F^2 \]

where:

  • \(W^{[l]}\) — the weight matrix of layer \(l\).
  • \(\|W^{[l]}\|_F^2 = \sum_{i}\sum_{j} (W^{[l]}_{ij})^2\) — the squared Frobenius norm of the matrix, which is just the sum of squares of all entries.
  • The sum over \(l = 1 \dots L\) accumulates the penalty across all layers.
🔵 Definition — Frobenius norm The Frobenius norm of a matrix is the square root of the sum of the squares of all its elements. It is the matrix analogue of the Euclidean norm for vectors. Squaring it (as above) gives a simple differentiable penalty.

6.6 How the penalty enters the update rule

With L2 regularization, the gradient of the cost with respect to a weight becomes:

\[ \frac{\partial J}{\partial W^{[l]}} = \frac{\partial J_{\text{data}}}{\partial W^{[l]}} \;+\; \frac{\lambda}{m} W^{[l]} \]

So the weight update (gradient descent) is:

\[ W^{[l]} \;\leftarrow\; W^{[l]} - \alpha\left(\frac{\partial J_{\text{data}}}{\partial W^{[l]}} + \frac{\lambda}{m} W^{[l]}\right) \]

Rearranging:

\[ W^{[l]} \;\leftarrow\; \left(1 - \frac{\alpha\lambda}{m}\right) W^{[l]} \;-\; \alpha \frac{\partial J_{\text{data}}}{\partial W^{[l]}} \]
💡 Insight — "weight decay" The factor \(\left(1 - \frac{\alpha\lambda}{m}\right)\) is slightly less than 1, so every update shrinks the weights a little before applying the data gradient. This is why L2 regularization is also called weight decay.

7. Why Regularization Reduces Overfitting

We have seen the mathematics; now let's build intuition for why penalizing large weights helps.

7.1 The tanh intuition

Consider a network using the \(\tanh\) activation function. The \(\tanh\) function is roughly linear for small inputs, but saturates (flattens out) for large positive or negative inputs.

If we penalize large weights, the network is pushed toward small weights. Small weights mean small \(z = Wa + b\), which means every layer operates in the near-linear region of \(\tanh\). A network of stacked linear layers is itself essentially linear — and a linear model cannot overfit in the wiggly, high-variance way we saw in Figure 4.

🟢 Intuition — in one sentence Regularization makes the network "simpler" by keeping activations in their linear regime, which limits the complexity of the functions the network can represent.

7.2 The cost-vs-iterations picture

🟣 Example — choosing λ

If \(\lambda\) is too large, the weights are forced to be tiny, the network becomes too linear, and you get high bias (underfitting). If \(\lambda\) is too small, regularization has little effect and you still have high variance. \(\lambda\) is a hyperparameter you tune on the dev set — try a range of values (e.g. \(0.001, 0.01, 0.1, 1\)) and pick the one with the best dev error.

8. Dropout Regularization

8.1 The idea

🔵 Definition — Dropout Dropout is a regularization technique in which, during each training iteration, each neuron in the network is temporarily "dropped" (set to zero) with some probability \(1 - \text{keep\_prob}\). This forces the network to learn redundant representations and prevents it from relying too heavily on any single neuron.
🟡 Important — terminology keep_prob is the probability that a given neuron is kept (not dropped). If keep_prob = 0.8, each neuron is dropped with probability 0.2. Dropout rate is \(1 - \text{keep\_prob}\).

9. Implementing Dropout — Inverted Dropout

There are two ways to implement dropout. The modern, standard approach is inverted dropout, which we describe here.

9.1 The algorithm (for one layer)

Suppose we are implementing dropout for layer \(l = 3\), with \(\text{keep\_prob} = 0.8\). Let \(a^{[3]}\) be the activation matrix of layer 3 (shape: number of units × number of examples).

# Step 1: create a random mask, same shape as a3
d3 = np.random.rand(a3.shape[0], a3.shape[1]) < keep_prob

# Step 2: apply the mask
a3 = np.multiply(a3, d3)   # or: a3 = a3 * d3

# Step 3: scale to preserve expected value
a3 /= keep_prob

9.2 What each line does

  • Line 1: generates a random matrix \(d^{[3]}\) with the same shape as \(a^{[3]}\). Each entry is \(1\) with probability \(0.8\) (kept) and \(0\) with probability \(0.2\) (dropped).
  • Line 2: element-wise multiplication zeroes out the dropped neurons.
  • Line 3: divides the surviving activations by \(\text{keep\_prob}\). This is the "inverted" part.

9.3 Why the scaling is needed

🟢 Intuition — the inverted dropout trick Suppose 50 units are active in layer 3 and keep_prob = 0.8. On average, 40 units survive and 10 are shut off. Without scaling, the expected sum feeding into the next layer would be 80% of what it would be without dropout — the next layer would see systematically smaller inputs during training. By dividing the surviving activations by 0.8, we restore the expected value so that \(\mathbb{E}[a^{[3]}_{\text{after dropout}}] = a^{[3]}_{\text{no dropout}}\). This ensures that at test time — when we don't use dropout — no adjustment is needed.
🟣 Example — the arithmetic

Say a neuron's activation is \(a = 10\) and keep_prob \(= 0.8\).

  • With probability 0.8 it survives, and we divide by 0.8: \(10 / 0.8 = 12.5\).
  • With probability 0.2 it is dropped: value becomes 0.
  • Expected value: \(0.8 \times 12.5 + 0.2 \times 0 = 10\). ✔

So the expected activation is unchanged. At test time we use \(a = 10\) directly.

10. Making Predictions at Test Time

At test time, we do not use dropout. We use the full network with all neurons active.

🟡 Important Because we used inverted dropout during training (scaling by \(1/\text{keep\_prob}\)), the expected activation at test time matches what the next layer saw during training. Therefore, no additional scaling is needed at test time. This is the main advantage of inverted dropout over the older "non-inverted" variant.

In pseudocode, a forward pass at test time looks like the standard forward pass — no random masks, no division:

# Test time (no dropout)
z4 = W4 @ a3 + b4
a4 = g4(z4)

11. Understanding Dropout — Why Does It Work?

11.1 The "don't rely on any one feature" intuition

🟢 Intuition — Andrew Ng's explanation Because each neuron can be dropped at any time, the network cannot afford to rely too heavily on any single input feature or any single hidden unit. It is forced to spread out the weights — to learn redundant, robust representations.

11.2 Dropout as an ensemble

Another way to think about dropout: each training iteration uses a different random sub-network. Training with dropout is like training a huge number of small networks that share weights. At test time, using the full network is approximately like averaging the predictions of all these sub-networks — and averaging many models usually reduces variance.

11.3 Practical notes on using dropout

⚙️ Implementation — where and how much
  • Dropout is most commonly used in computer vision, where inputs are high-dimensional and overfitting is a serious concern.
  • It is used less often in other domains, though it can still help.
  • For layers where overfitting is a concern, use a smaller keep_prob (e.g. 0.5). For layers where overfitting is less of a concern, use a larger keep_prob (e.g. 0.9) or no dropout at all.
  • Do not use dropout at test time.
  • Dropout makes the cost function \(J\) harder to define because it is stochastic. A common debugging trick: turn off dropout (keep_prob = 1.0) first, verify that the cost decreases monotonically, then turn dropout back on.
🔴 Warning — gradient checking with dropout Gradient checking does not work with dropout, because the cost function is not deterministic — each iteration uses a different random sub-network. To use gradient checking, set keep_prob = 1.0 (disable dropout) first.

12. Other Regularization Methods

12.1 Data augmentation

If you don't have enough data, you can create more by applying transformations that preserve the label.

12.2 Early stopping

As training progresses, training error keeps falling but dev error eventually starts to rise (overfitting). Early stopping means: stop training at the point where dev error is lowest, even though training error could still go lower.

🔴 Warning — downside of early stopping Early stopping couples two concerns: optimizing the cost function (minimizing training error) and not overfitting (generalization). By stopping early, you may not fully minimize the training cost. An alternative is to use L2 regularization and train as long as you like — but then you have another hyperparameter (λ) to tune. Early stopping is a pragmatic choice when you don't want to spend time tuning λ.

13. Normalizing Inputs

13.1 The idea

When your features have very different scales — say \(x_1\) ranges from 0 to 1 and \(x_2\) ranges from 1 to 1000 — gradient descent can be slow and unstable. Normalizing inputs to have zero mean and unit variance makes optimization much more efficient.

13.2 The formulas

For each feature \(j\):

\[ \mu_j = \frac{1}{m}\sum_{i=1}^{m} x_j^{(i)}, \qquad \sigma_j^2 = \frac{1}{m}\sum_{i=1}^{m} \left(x_j^{(i)} - \mu_j\right)^2 \] \[ x_j := \frac{x_j - \mu_j}{\sigma_j} \]

Symbols:

  • \(x_j^{(i)}\) — the \(j\)-th feature of the \(i\)-th training example.
  • \(\mu_j\) — the mean of feature \(j\) across the training set.
  • \(\sigma_j^2\) — the variance of feature \(j\).
  • \(m\) — number of training examples.
🟡 Important — use training statistics for dev/test Compute \(\mu\) and \(\sigma^2\) on the training set only, then apply the same values to normalize the dev and test sets. Never re-compute the mean and variance on the test set — that would leak information and give an optimistic estimate.

14. Vanishing / Exploding Gradients

14.1 The problem

When training very deep networks (say 150 layers), gradients can become extremely small (vanishing) or extremely large (exploding) as they propagate backward. This makes training unstable or impossible.

14.2 A concrete example

Suppose every layer has weight matrices that are just slightly larger than the identity:

\[ W^{[l]} = \begin{bmatrix} 1.5 & 0 \\ 0 & 1.5 \end{bmatrix} \]

Then the output after \(L\) layers scales roughly as \(1.5^L\). For \(L = 150\), \(1.5^{150}\) is astronomically large (exploding). If instead each weight is \(0.5\), the output scales as \(0.5^L\), which vanishes to essentially zero.

🔴 Warning Vanishing gradients make it impossible for early layers to learn — their gradients become so small that the weights barely change. Exploding gradients cause the weights to oscillate wildly or become NaN. Both are consequences of the multiplicative nature of backpropagation.

14.3 The role of activation functions

The choice of activation function interacts with this problem. Sigmoid and tanh have derivatives that are always less than 1 (and much less than 1 in their saturated regions), which contributes to vanishing gradients. ReLU has derivative 1 for positive inputs, which helps mitigate vanishing gradients in deep networks.

15. Weight Initialization for Deep Networks

15.1 The idea

A partial solution to vanishing/exploding gradients is to initialize the weights carefully. If weights start too large, activations explode; if too small, they vanish. We want an initialization that keeps the variance of activations roughly constant across layers.

15.2 Single-neuron analysis

Consider a single neuron with \(n\) inputs:

\[ z = w_1 x_1 + w_2 x_2 + \cdots + w_n x_n \]

If the inputs \(x_i\) have mean 0 and variance 1, and the weights \(w_i\) are drawn independently with mean 0 and variance \(\sigma_w^2\), then the variance of \(z\) is:

\[ \operatorname{Var}(z) = n \cdot \sigma_w^2 \]

To keep \(\operatorname{Var}(z)\) close to 1 (so activations neither explode nor vanish), we want:

\[ \sigma_w^2 = \frac{1}{n} \]

This suggests initializing each weight from a distribution with variance \(1/n\), where \(n\) is the number of inputs to the neuron.

15.3 Xavier / Glorot initialization

🔵 Definition — Xavier initialization Xavier initialization (also called Glorot initialization) sets the weight variance to \(\frac{2}{n^{[l-1]} + n^{[l]}}\), where \(n^{[l-1]}\) is the number of units in the previous layer and \(n^{[l]}\) is the number in the current layer.

In practice, you sample from a normal distribution and scale it:

\[ W^{[l]} = \texttt{np.random.randn(shape)} \times \sqrt{\frac{2}{n^{[l-1]} + n^{[l]}}} \]

For ReLU activations, a common variant is:

\[ W^{[l]} = \texttt{np.random.randn(shape)} \times \sqrt{\frac{2}{n^{[l-1]}}} \]

This is sometimes called He initialization.

⚙️ Implementation — weight init in code 
# Xavier / Glorot initialization (for tanh)
W = np.random.randn(shape) * np.sqrt(2.0 / (n_prev + n_curr))

# He initialization (for ReLU)
W = np.random.randn(shape) * np.sqrt(2.0 / n_prev)

16. Numerical Approximation of Gradients

16.1 Why we need gradient checking

Backpropagation computes gradients analytically, but it is easy to introduce bugs — a sign error, a transposed matrix, a missing term. Gradient checking is a technique for verifying that the analytical gradients match numerical approximations.

16.2 The derivative as a limit

Recall the definition of the derivative:

\[ f'(\theta) = \lim_{\varepsilon \to 0} \frac{f(\theta + \varepsilon) - f(\theta)}{\varepsilon} \]

This is the one-sided difference. Numerically, we can approximate it with a small \(\varepsilon\), but the error is \(O(\varepsilon)\).

A better approximation is the two-sided difference:

\[ f'(\theta) \approx \frac{f(\theta + \varepsilon) - f(\theta - \varepsilon)}{2\varepsilon} \]

The two-sided difference has error \(O(\varepsilon^2)\), which is much more accurate for the same \(\varepsilon\).

16.3 A numerical example

Let \(f(\theta) = \theta^3\), so \(f'(\theta) = 3\theta^2\). At \(\theta = 1\), the true derivative is 3.

🟣 Example

One-sided with \(\varepsilon = 0.01\):

\[ \frac{(1.01)^3 - 1^3}{0.01} = \frac{1.030301 - 1}{0.01} = 3.0301 \]

Error: \(0.0301\).

Two-sided with \(\varepsilon = 0.01\):

\[ \frac{(1.01)^3 - (0.99)^3}{2 \times 0.01} = \frac{1.030301 - 0.970299}{0.02} = 3.0001 \]

Error: \(0.0001\) — about 300× more accurate!

🟡 Important — practical recommendation Use the two-sided difference for gradient checking. A typical choice is \(\varepsilon = 10^{-7}\), which gives errors around \(10^{-14}\) for smooth functions.

17. Gradient Checking

17.1 The setup

To check gradients across an entire network, we:

  1. Reshape all parameters \(W^{[1]}, b^{[1]}, \dots, W^{[L]}, b^{[L]}\) into one giant vector \(\theta\).
  2. Reshape all gradients \(dW^{[1]}, db^{[1]}, \dots, dW^{[L]}, db^{[L]}\) into one giant vector \(d\theta\).
  3. For each component \(i\), compare the analytical gradient \(d\theta_i\) with the numerical approximation: \[ d\theta_{\text{approx}}[i] \approx \frac{J(\theta_1, \dots, \theta_i + \varepsilon, \dots) - J(\theta_1, \dots, \theta_i - \varepsilon, \dots)}{2\varepsilon} \]
  4. Compute the relative error: \[ \frac{\|d\theta_{\text{approx}} - d\theta\|_2}{\|d\theta_{\text{approx}}\|_2 + \|d\theta\|_2} \]
🟡 Important — reading the relative error
  • \(\approx 10^{-7}\) or smaller → gradients are correct.
  • \(\approx 10^{-5}\) → possibly correct, but inspect further.
  • \(\approx 10^{-3}\) or larger → there is a bug in the gradient computation.

17.2 Pseudocode

for i in range(num_parameters):
    theta_plus = theta.copy()
    theta_plus[i] += epsilon
    J_plus = forward_propagation(theta_plus)

    theta_minus = theta.copy()
    theta_minus[i] -= epsilon
    J_minus = forward_propagation(theta_minus)

    grad_approx[i] = (J_plus - J_minus) / (2 * epsilon)

relative_error = norm(grad_approx - grad) / (norm(grad_approx) + norm(grad))
if relative_error < 1e-7:
    print("Gradients are correct")
else:
    print("Check for bugs!")

18. Gradient Checking — Implementation Notes

⚙️ Implementation — Andrew Ng's practical tips
  1. Don't use gradient checking in training — only to debug. It is computationally expensive (you run forward propagation twice per parameter).
  2. If grad check fails, look at components to identify which layer's gradient is wrong. Compare \(dW^{[l]}\) and \(db^{[l]}\) separately to narrow down the bug.
  3. Remember regularization. If you use L2 regularization, the cost function includes the penalty term \(\frac{\lambda}{2m}\sum_l \|W^{[l]}\|_F^2\). Your gradient calculation must include the derivative of this term. A common bug is to forget the regularization term in gradient checking.
  4. Doesn't work with dropout. Dropout makes the cost function stochastic — each run uses a different random sub-network. Set keep_prob = 1.0 (disable dropout) before running gradient checking.
  5. Run at random initialization, and perhaps again after some training. Some bugs only show up after the parameters have moved away from their initial values.
🔴 Warning — a classic bug A very common bug is to use the wrong sign in the gradient update, or to transpose a weight matrix. Gradient checking catches both. If the relative error is around \(10^{-3}\) or larger, suspect:
  • Sign error in a gradient.
  • Transposed matrix in the computation.
  • Missing regularization term.
  • Using the one-sided difference instead of two-sided.

  • Regularization — L2 (weight decay) and L1 penalties; how they shrink weights and reduce overfitting.
  • Dropout — randomly dropping neurons during training; inverted dropout scaling; why it acts like an ensemble.
  • Other methods — data augmentation and early stopping.
  • Normalizing inputs — zero mean, unit variance; why it speeds up gradient descent.
  • Vanishing/exploding gradients — the multiplicative problem in deep networks.
  • Weight initialization — Xavier/He initialization to keep activation variance stable.
  • Gradient checking — two-sided numerical approximation; relative error thresholds; implementation caveats.

Must-Know Concepts

  • Dev and test sets must come from the same distribution.
  • Bias = training error − base error. Variance = dev error − training error.
  • L2 regularization adds \(\frac{\lambda}{2m}\|W\|^2\) to the cost; it shrinks weights ("weight decay").
  • Dropout uses inverted scaling: divide by keep_prob during training; do nothing at test time.
  • Normalize inputs using training-set statistics, then apply the same statistics to dev/test.
  • Xavier/He initialization keeps activation variance roughly constant across layers.
  • Gradient checking uses the two-sided difference and a relative error formula; \(10^{-7}\) is good, \(10^{-3}\) means a bug.

20. Review Questions

Q1. Why must the dev and test sets come from the same distribution?

Because the dev set is what you use to tune hyperparameters and make modeling decisions. If the test set comes from a different distribution, your dev-set performance is not a reliable predictor of test-set performance — you optimize for one thing and are evaluated on another.

Q2. You have 1,000,000 training examples. What split proportions would you use?

Something like 98% / 1% / 1% (training / dev / test). With a million examples, 1% is still 10,000 examples — large enough for reliable evaluation. The training set should be as large as possible.

Q3. A model has 1% training error and 11% dev error, with base error 0%. Diagnose.

High variance (overfitting). The model fits the training data well but generalizes poorly. Remedies: more data, regularization (L2, dropout), or a simpler architecture.

Q4. A model has 15% training error and 16% dev error, with base error 0%. Diagnose.

High bias (underfitting). The model is too simple to fit even the training data. Remedies: bigger network, train longer, better architecture.

Q5. Can a model have high bias and high variance at the same time?

Yes. In deep learning this is common. Example: 15% training error (high bias) and 30% dev error (high variance) with base error 0%. The model is too simple overall but also overfits noise in some regions.

Q6. What does the L2 regularization term look like in the cost function for a neural network? \[ J = \frac{1}{m}\sum \mathcal{L}(y,\hat{y}) + \frac{\lambda}{2m}\sum_{l=1}^{L}\|W^{[l]}\|_F^2 \]

\(\lambda\) controls the strength. \(\|W^{[l]}\|_F^2\) is the sum of squares of all entries in the layer-\(l\) weight matrix.

Q7. Why does L2 regularization sometimes make weights "sparse"?

Actually, L2 makes weights small but rarely exactly zero. It is L1 regularization that tends to produce sparse weights (many exactly zero). This is a common point of confusion — be careful.

Q8. Explain inverted dropout in three steps.
  1. Generate a random mask \(d\) with the same shape as the activations, where each entry is 1 with probability keep_prob and 0 otherwise.
  2. Multiply the activations element-wise by \(d\) (zeroing out dropped units).
  3. Divide the result by keep_prob to preserve the expected value.
Q9. Why don't we scale activations at test time when using dropout?

Because inverted dropout already scales during training. The expected activation during training matches the unscaled activation at test time, so no adjustment is needed.

Q10. How does dropout act like an ensemble?

Each training iteration uses a different random sub-network (a different subset of neurons). Training with dropout is like training many small networks that share weights. At test time, using the full network approximates averaging their predictions, which reduces variance.

Q11. What is early stopping and what is its main drawback?

Early stopping means stopping training when dev error stops improving. Drawback: it couples two concerns — optimizing the cost function and preventing overfitting. You may stop before fully minimizing training cost. An alternative is L2 regularization, but then you must tune \(\lambda\).

Q12. Why does normalizing inputs speed up gradient descent?

Without normalization, features with very different scales produce an elongated cost surface. Gradient descent zig-zags and converges slowly. After normalization (zero mean, unit variance), the cost surface is more spherical, so gradient descent takes a more direct path to the minimum.

Q13. What statistics do you use to normalize the test set?

The mean \(\mu\) and variance \(\sigma^2\) computed on the training set. Never recompute them on the test set — that would leak information.

Q14. What causes vanishing/exploding gradients?

Backpropagation multiplies many terms together (one per layer). If those terms are consistently less than 1, the product shrinks exponentially (vanishing). If consistently greater than 1, it grows exponentially (exploding). This is especially severe in very deep networks.

Q15. What is Xavier initialization and why does it help?

Xavier initialization sets the weight variance to \(\frac{2}{n^{[l-1]} + n^{[l]}}\). It keeps the variance of activations roughly constant across layers, which mitigates vanishing/exploding gradients. For ReLU, the common variant is \(\sqrt{2/n^{[l-1]}}\) (He initialization).

Q16. Why is the two-sided difference preferred over the one-sided difference?

The one-sided difference has error \(O(\varepsilon)\). The two-sided difference has error \(O(\varepsilon^2)\), which is much smaller for the same \(\varepsilon\). For \(\varepsilon = 0.01\) and \(f(\theta) = \theta^3\), the one-sided error was 0.0301 while the two-sided error was 0.0001.

Q17. What relative error indicates a gradient bug?

Around \(10^{-3}\) or larger. Values around \(10^{-7}\) indicate correct gradients. Values around \(10^{-5}\) are borderline — inspect further.

Q18. Why doesn't gradient checking work with dropout?

Dropout makes the cost function stochastic — each forward pass uses a different random sub-network. Numerical gradients would compare different random networks, so the comparison is meaningless. Set keep_prob = 1.0 before running gradient checking.

Q19. What should you check if gradient checking fails?
  • Look at individual components \(dW^{[l]}\) and \(db^{[l]}\) to find which layer is wrong.
  • Check for a missing regularization term in the gradient.
  • Check for transposed matrices.
  • Check for sign errors.
  • Make sure you used the two-sided difference.
Q20. What is the difference between L1 and L2 regularization in terms of the weights they produce?

L2 produces small but generally nonzero weights. L1 tends to produce sparse weights — many weights become exactly zero. L1 can be useful when you suspect only a few features matter; L2 is more common in deep learning.

21. Self-Test

Click each question to reveal the answer. These questions are designed to test conceptual understanding rather than memorization.

Q1. You are building a speech recognition system. Your training data comes from clean studio recordings, but your users will speak in noisy environments. How should you construct your dev and test sets?

Answer. Because the model will be deployed on noisy speech, the target distribution is noisy speech. Therefore, both your dev and test sets should come from the noisy-environment distribution (or a realistic mix that matches deployment). Your training set may include both studio recordings (which are cheap and plentiful) and noisy recordings — the training distribution can be broader. The key rule from the lecture: dev and test must come from the same distribution, and that distribution should resemble what the model will actually see in production. If you had a clean-only dev set, you would tune hyperparameters for clean speech and then be surprised when the model underperforms on noisy user audio.

Q2. Your model achieves 2% training error and 2.5% dev error, but human-level performance on this task is 1%. What is your diagnosis, and what would you try next?

Answer. First compute the two gaps:

  • Bias gap = training error − base error = 2% − 1% = 1% → some bias.
  • Variance gap = dev error − training error = 2.5% − 2% = 0.5% → small variance.

Diagnosis: high bias, low variance. The model is underfitting — even the training error is 1% above what is achievable. Variance is not the problem. What to try next (from the "basic recipe"):

  • Train a bigger network (more layers, more hidden units).
  • Train longer or use a better optimization algorithm.
  • Try a better architecture (e.g. different activation functions, or a different network design suited to the task).

Regularization would not help here — it would likely increase bias further.

Q3. Explain why adding an L2 penalty to the cost function is equivalent to "weight decay" in the gradient descent update.

Answer. Start with the regularized cost:

\[ J = J_{\text{data}} + \frac{\lambda}{2m}\|W\|^2 \]

The gradient of the penalty term with respect to \(W\) is \(\frac{\lambda}{m}W\). So the full gradient is:

\[ \frac{\partial J}{\partial W} = \frac{\partial J_{\text{data}}}{\partial W} + \frac{\lambda}{m}W \]

The gradient descent update is:

\[ W \leftarrow W - \alpha\left(\frac{\partial J_{\text{data}}}{\partial W} + \frac{\lambda}{m}W\right) = \left(1 - \frac{\alpha\lambda}{m}\right)W - \alpha \frac{\partial J_{\text{data}}}{\partial W} \]

The factor \(\left(1 - \frac{\alpha\lambda}{m}\right)\) is a constant slightly less than 1. Every step, the weight is multiplied by this factor before the data gradient is applied. This is a gentle, continuous shrinkage of the weights — hence "weight decay". The larger \(\lambda\) is, the more aggressive the shrinkage.

Q4. Suppose you use dropout with keep_prob = 0.5 in a layer with 100 units. On average, how many units are active during a training iteration? How does inverted dropout ensure the next layer sees the right scale?

Answer. On average, \(0.5 \times 100 = 50\) units are active (kept) and 50 are dropped in each iteration. The exact number fluctuates from iteration to iteration (binomial distribution), but averages 50.

Inverted dropout scaling: after applying the mask, we divide all surviving activations by keep_prob = 0.5, i.e. we multiply by 2. Example: if a surviving activation was \(a = 10\) (already computed without dropout), it becomes \(10 / 0.5 = 20\). Consider the expected value contributed by the neuron to the next layer's pre-activation:

\[ \mathbb{E}[\text{contribution}] = 0.5 \times (10 / 0.5) + 0.5 \times 0 = 10 \]

So the expected signal seen by the next layer is exactly the same as it would be with no dropout. This is crucial: at test time, when all neurons are active and no scaling is applied, the next layer sees the same expected input distribution it saw during training.

Q5. Why is it dangerous to tune hyperparameters on the test set? What is the correct procedure?

Answer. If you tune hyperparameters on the test set, you are effectively using it as a training signal — you will pick the model that happens to do best on those specific examples. The test set stops being a fair, held-out estimate of generalization and becomes an optimistically biased estimate. In the worst case, you are effectively "overfitting to the test set" without realizing it.

Correct procedure:

  1. Split data into train / dev / test up front.
  2. Train on the training set.
  3. Tune all hyperparameters (learning rate, \(\lambda\), network size, keep_prob, etc.) using the dev set.
  4. Once you have settled on a final model, evaluate it exactly once on the test set. That number is your final reported performance.
  5. If you find yourself wanting to go back and change the model after seeing test performance, you have already contaminated the test set — the honest thing is to reset the split.
Q6. You initialize all weights to a very small constant (e.g. 0.001). What problem might this cause, and how does Xavier initialization address it?

Answer. If every weight is 0.001 and inputs have unit variance, then the pre-activation \(z = \sum w_i x_i\) at layer 1 has variance roughly \(n \cdot 0.001^2\) where \(n\) is the number of inputs — very small. As signal propagates forward through many layers, the activations shrink exponentially toward zero (vanishing signal). Similarly, gradients computed during backpropagation shrink exponentially, so early layers barely learn.

Also, all weights being identical means every neuron in a layer computes the same function — a phenomenon called symmetry that gradient descent cannot break (this is the standard argument for random initialization).

Xavier initialization draws weights randomly from a distribution with variance \(\frac{2}{n^{[l-1]} + n^{[l]}}\), chosen so that the variance of the activations stays roughly constant across layers. Concretely: \(W^{[l]} = \text{randn} \times \sqrt{2/(n^{[l-1]} + n^{[l]})}\). The random part breaks symmetry; the variance-matching part prevents signal from vanishing or exploding as it flows through the network.

Q7. Describe the gradient checking procedure in your own words. Why is it not used during training?

Answer. Gradient checking verifies that the analytical gradients computed by backpropagation are correct by comparing them to numerical approximations:

  1. Reshape all parameters \(W^{[l]}, b^{[l]}\) into a single long vector \(\theta\).
  2. Reshape all gradients \(dW^{[l]}, db^{[l]}\) into a matching vector \(d\theta\).
  3. For each component \(i\) of \(\theta\), compute a two-sided numerical approximation: \[ d\theta_{\text{approx}}[i] = \frac{J(\theta + \varepsilon e_i) - J(\theta - \varepsilon e_i)}{2\varepsilon} \] where \(e_i\) is the \(i\)-th standard basis vector.
  4. Compute the relative error: \[ \frac{\|d\theta_{\text{approx}} - d\theta\|_2}{\|d\theta_{\text{approx}}\|_2 + \|d\theta\|_2} \]
    • \(\approx 10^{-7}\) or smaller → gradients are correct.
    • \(\approx 10^{-3}\) or larger → a bug exists.

Why not in training? Each numerical gradient requires two full forward passes (one for \(\theta + \varepsilon\), one for \(\theta - \varepsilon\)). If the network has millions of parameters, that is millions of forward passes — completely impractical per iteration. Gradient checking is a debugging tool, run occasionally on a small problem to validate the backprop implementation.

Q8. A colleague tells you "regularization always reduces training accuracy." Is this statement accurate? Explain.

Answer. Partially true, but needlessly imprecise. Let's unpack:

  • True in spirit: Adding a regularization penalty like L2 makes the optimization harder — the network is now penalized for large weights, so it cannot fit the training data as aggressively. This typically increases training error (or decreases training accuracy). That is the intended trade-off: we accept slightly worse training performance for much better generalization.
  • But "always" is too strong. With dropout, training accuracy is measured on a stochastically thinned network — a fair comparison requires disabling dropout at evaluation time. With dropout off, the full network usually achieves higher training accuracy than the thinned versions averaged.
  • And it misses the point. The purpose of regularization is not to improve training accuracy — it is to improve dev/test accuracy by reducing variance. The correct statement is: regularization increases training error (or leaves it similar) while decreasing dev error when the model is overfitting.

Bottom line: the statement is a rough rule of thumb, but it is not an absolute law. The real objective is better generalization, and there are cases (especially with modern over-parameterized networks) where regularization has a subtler effect on training metrics.

Q9. You have a very deep network (100 layers) and notice that the early layers' weights barely change during training. What might be happening, and what could you try?

Answer. This is the classic symptom of the vanishing gradient problem. Backpropagation computes the gradient of the loss with respect to early-layer weights as a product of many terms from later layers (each term involves a weight matrix and an activation derivative). If those terms are consistently less than 1, the product shrinks exponentially, so the gradients reaching the early layers are essentially zero — and the early weights do not update meaningfully.

What could cause it and what to try:

  • Activation functions: Sigmoid and tanh have derivatives < 1 everywhere, which makes vanishing worse. Switch to ReLU (derivative 1 for positive inputs) or a variant (Leaky ReLU, ELU).
  • Weight initialization: If initial weights are too small, activations shrink layer by layer. Use Xavier / He initialization to keep activation variance roughly constant across layers.
  • Architecture: Very deep plain networks are prone to this. Try architectures with skip / residual connections (ResNets), which give gradients a shortcut path backward and largely eliminate vanishing in practice. (This is beyond this week's slides — added as Additional Context.)
  • Batch normalization: Normalizing activations inside the network stabilizes gradients and is another common remedy (covered later in the course).
  • Learning rate: If gradients are tiny, a very small learning rate makes them effectively zero. Consider a larger learning rate, though this alone will not fix the fundamental issue.

The first two remedies (ReLU + better initialization) are the ones most directly covered this week.

Q10. Why does normalizing inputs change the shape of the cost surface? Draw or describe the contour plots before and after normalization.

Answer. Consider a simple linear model where input feature \(x_1\) has a very different scale than \(x_2\) — say \(x_1\) ranges from 0 to 1 and \(x_2\) ranges from 1 to 1000. The weights \(w_1\) and \(w_2\) then need very different magnitudes to be "in balance", and the cost \(J(w_1, w_2)\) becomes very sensitive to one weight and insensitive to the other. Geometrically, the level sets (contours) of \(J\) form long, thin ellipses stretched along one axis.

  • Before normalization: Contours are highly elongated ellipses. Gradient descent must zig-zag back and forth across the narrow dimension, taking many tiny steps and converging slowly.
  • After normalization: Each feature has zero mean and unit variance. The weights are now comparably scaled, so the cost surface becomes much closer to spherical (circular contours in 2-D). Gradient descent can head more or less directly toward the minimum and converge in far fewer iterations.

You can see this in Figure 14 above: the left plot shows the elongated elliptical contours (unnormalized), the right plot shows circular contours (normalized). The zig-zag path vs direct path is exactly the phenomenon.

Note: input normalization does not change the location of the minimum of \(J\) in terms of the underlying function learned — it just makes the optimization landscape much more favorable.
